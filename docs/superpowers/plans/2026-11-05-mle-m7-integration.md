# MLE public-train integration with configured construction

Status: integration design, not an executed experiment or a frozen final protocol. This design unblocks Task 2 of the evidence-led delivery plan; it does not change the historical pilot or its results.

## Existing execution and boundary

`composed_agent.run_agent` freezes the public-data bundle, profile, domain, provider and task description in `agent_contract.json`, constructs `Framework.from_profile`, and selects a previously admitted candidate. `PublicTrainDomain` trains each candidate once, records immutable predictions, scores different frozen splits from those predictions, and materializes the selected submission only after checking its original prediction hash. The external campaign runner grades that submission separately. Hidden scores must not enter the search.

The current profile uses schema 1, in-process execution, and a provider that expects code-only responses. M7 requires schema 2, a Git artifact executor and a structured response containing `artifact` and `hypothesis`. A configuration-only switch would give contradictory response instructions and does not connect the CNY authority. `GovernedCNYProvider` refuses direct calls: its registered `CNYInvocationBridge` is the sole transport and currency admission path. Preserve the existing agent as a legacy, separately labeled runtime; do not claim its past scores establish M7 behavior.

## Integration contract

- Add an explicit new runtime choice and freeze it in the run contract. Both baseline and full arms must use the same construction, provider, domain, data protocol and stop semantics; preserve the declared search differences and record their exact profiles.
- Replace the code-only instruction for this runtime with a task instruction consistent with the constructor's JSON output contract. The artifact remains the full executable program; the frozen hypothesis must match the constructor input. The sandbox must execute the exact evaluated artifact and reuse its prediction bytes for scoring and submission.
- Register the currency bridge and fresh provider sessions bound to the *existing* campaign identity and journal. Never create a new allowance, duplicate the legacy provider's settlement, or call the transport outside the bridge. Require audit reconciliation between provider receipts, physical ledger and currency journal, including repairs and any controls.
- Register a genuinely separate domain session and candidate root for each control lane if controls are enabled; a shared mutable `_frozen` cache or candidate directory is not an independent session. Bind the same frozen data and sandbox implementation without exposing hidden labels or control scores to main selection.
- On resume, recover the original persisted materialization and evaluation, rebind predictions to original evidence, and refuse replacement calls where their outcome is unknown. A failed attempt remains a distinct outcome; retain any previously eligible candidate only when the framework's original selection evidence supports it.

## Budget gate before any paid request

The current campaign policy declares an input capacity of 1,048,576 tokens and a maximum output allowance of 393,216. With the current 4,096 output setting, the governed provider's hard per-call physical bound is 1,052,672 tokens; this already exceeds the legacy 60,000-token per-run limit before repair or protected controls. The legacy estimate-based admission is not a hard bound. Do not silently raise the limit, downgrade the guarantee, reset the campaign or dispatch a request to see whether it works. First verify the supplier's current model identity, price and capacity contract against official sources, reconcile the live ledger, and establish an explicitly recorded comparable run budget and control policy within the user's cumulative CNY 200 limit. Actual usage can be lower than a reservation, but that does not make a smaller hard reservation safe.

2. Write behavioral tests using the public agent entry point and a loopback provider: both arm profiles, structured artifact construction, one billed call per attempt, cached predictions across splits, isolated controls, interrupted and resumed calls, invalid artifacts, selection and no eligible-candidate outcomes. Include a strict refusal when hard bounds exceed the declared budget. No external requests or real ledger changes.
3. Implement the explicit opt-in integration and its audit; keep the legacy entry and old evidence intact. Verify sandbox privacy and the full provider/currency reconciliation at public entry. Record source, dataset, evaluator, model identity, all budgets and selection rules before the first paid slot.
4. Execute the six preregistered task/arm slots only after no-paid preflight and current official pricing/capacity verification. Record all failures and unknown costs; unknown settlement blocks further paid calls. Extend to three seeds only under the same frozen protocol.

The 3-task report, GEPA/FunSearch reproduction packages and same-search governance comparison remain separate deliverables; controls in this integration are not by themselves an unbiased governance comparison.

## Official service check (2026-11-05, before implementation)

DeepSeek's [model and pricing page](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) identifies `deepseek-flash` as the moving alias for V4.1-Flash-1017 and lists peak cache-miss input at CNY 2/million tokens and output at CNY 8/million; off-peak rates are lower. The existing campaign's 2/8 micro-CNY per token is therefore a conservative peak-price accounting policy at this check, not proof of the billed amount or a future price guarantee. The [model metadata documentation](https://api-docs.deepseek.com/api/list-models/) gives an example context window of 1,048,576 and output maximum of 393,216 tokens; it says the context window counts input and output together. The current implementation deliberately reserves context plus output independently, a more conservative bound; changing that calculation requires a separately tested invariant and verified service behavior, and would still not reduce it below the old 60,000-token budget. The model listing is an example, not evidence of a live account response. Alias updates mean the exact underlying snapshot cannot be inferred from a receipt naming only `deepseek-flash`. Recheck pricing and model before actual dispatch and record any uncertainty.

## Follow-up seam trace

`runtime._commit_cycle` still writes `composed_evidence` with the full proposal and canonical evidence, and `result.best_candidate_id` identifies the selection. V9 also records `materialization_completed` and physical evaluation outcomes. `inspect()["execution"]["main"]["artifacts"]` validates construction references but does not substitute for the original evaluation's private prediction hash. The implementation must cross-check the selected proposal against both its construction record and its evaluation binding before `PublicTrainDomain.materialize`, rather than assuming an inspection reference alone supplies the submission.

A recovery cut exists between a durable `governed_evaluation_completed` and the later `composed_evidence` append. `PublicTrainDomain.restore_evidence` currently restores only from the latter, while the native recovery adapter can restore a domain snapshot only when the domain implements `checkpoint_state` and `restore_state`. Design and test the snapshot/restore binding to the durable terminal and cached bytes before claiming this cut recovers: do not turn an existing candidate directory into an unverified trusted cache, and do not retrain on an unresolved outcome. Also test that a rejected or non-OK terminal cannot become a selected submission. Control factories must use unique roots while retaining frozen dataset and evaluator identity.

## Recovery implementation in isolated checkout

A public Framework test injects a stop after `governed_evaluation_completed`, then resumes without a new provider call or training run and materializes the original prediction. A tampered prediction is rejected without retry, but the observed outer error is `durable continuation diverged at hierarchical_budget`, which masks the original prediction-integrity reason; diagnose this before claiming helpful failure diagnostics.
