## Greedy mechanism and operator set

- [Greedy parent policy](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/solvers/greedy/greedy.py#L197-L240): generate drafts until `num_drafts`, then with `debug_prob` select a random buggy leaf whose debug depth is **at most** `max_debug_depth`; if none selected and there is no good node, draft; otherwise choose the best good node. The [MLE greedy configuration](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/configs/solver/mlebench/greedy.yaml) uses five drafts, debug probability 1.0 and maximum debug depth 20. These are reference values, not automatically the resource settings of a small Mori test.
- [Greedy step](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/solvers/greedy/greedy.py#L407-L432) derives draft/debug/improve from whether the selected parent is absent/buggy/good, runs the task and appends the node. Thus the upstream greedy code does **not** expose a fully independent interchangeable `π_op`; Mori's requested decoupling is an adaptation and needs its own test.
- Operator inputs indicate draft can start without a candidate, debug and improve each use one node, and crossover uses two nodes ([draft](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/operators/draft.py#L20-L33), [debug](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/operators/debug.py#L20-L32), [improve](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/operators/improve.py#L21-L33), [crossover](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/operators/crossover.py#L21-L32)). Each receives step/time context; this does not itself establish a non-extendable execution budget. The [greedy config](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/configs/solver/mlebench/greedy.yaml) does not enable crossover; the [evolutionary config](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/configs/solver/mlebench/evo.yaml) does. Do not call crossover part of the reference greedy run.
- The reference greedy run also has an analyze operator for execution-output analysis; the [experiment configuration](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/configs/_exp/mlebench/aira_greedy_o3.yaml) sets analysis to GPT-4o and draft/debug/improve to o3, for ten seeds. A single DeepSeek model and smaller budgets must be disclosed as an adaptation, not paper-equivalent.

## Memory and final selection

- [Memory implementations](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/operators/memory.py): no memory returns an empty string; simple summarizes eligible journal nodes; sibling summarizes the supplied parent's children; ancestral walks first parents and by default stops before a successful ancestor. Ancestral behavior on multi-parent crossover explicitly follows only `parents[0]`; do not claim it covers every ancestor. Tests should distinguish the parent whose children are retrieved from the currently proposed child.
- The upstream [best-node routine](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/core/solvers/utils/journal.py#L230-L245) picks the maximum ordered validation metric from good nodes by default, and [greedy returns that same best node](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/solvers/greedy/greedy.py#L181-L195). A separately configurable final selector is a Mori design requirement, not an independently configurable upstream greedy component.

## MLE evaluation boundary and remaining work

- [Task step](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/tasks/mlebench/task.py#L120-L154) executes generated code, checks the submission, and computes official test fitness for valid submissions. [Greedy parsing](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/solvers/greedy/greedy.py#L512-L527) normally takes validation fitness or the analysis result; a `use_test_score` option instead uses test score. The [default greedy config](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/configs/solver/greedy.yaml) sets that option false. Mori's frozen final test and no test-feedback rule is an explicit stronger isolation requirement; merely following upstream task execution is insufficient to prove it.
- Upstream's [MLE instructions](https://github.com/facebookresearch/aira-dojo/blob/c795d8649d30b77fa9b8c011b978bba7127507ad/src/dojo/tasks/mlebench/README.md) pin MLE-bench `d0f60ad0d3b2287469ac3c8ac9767330c928c980`; compare that revision with Mori's grader pin before claiming protocol equivalence. Three Mori tasks/seed identities, exact split hashes, alternative operator policy, independent final selector, replay and real results remain to be specified and tested. The MCTS/evolution configurations have not been reviewed here and remain separate future work.
