## 2. 收敛共识（多个独立系统收敛到的强结论）

1. **禁止 LLM 整篇重写记忆**。ACE 教科书级证据：整篇重写下 18,282 token playbook 一步塌缩为 122 token，准确率 66.7→57.1（低于无记忆基线 63.7）。机制：每步过一次有损压缩器，误差复利。**delta 增量写入 + 确定性非 LLM 合并**是解。
2. **表示 = 结构化 schema + embedding 双键 + 类型分级**。IBM TSM（13 字段 tip：category∈{strategy,recovery,optimization}、trigger、priority、provenance）与 MemRL（(intent, experience, Q) 三元组）独立收敛于此。纯语义检索被证明次优，必须组合结构化字段。
3. **读取 = 两阶段：相似度召回 → 效用/质量重排**。MemRL λ=0.5 甜点且有变分最优性证明；IBM TSM 用 LLM-guided 选择再 +7.2pp。τ≈0.6 是相似度阈值甜点。**关键负结果：top-k 过严会跌破基线（IBM：top-3 时 −2.9pp）——检索不足比不检索更糟**。
4. **程序性/方法论记忆是一等公民**。MemP（程序性记忆随规模优雅扩展、可迁移）、CODESKILL（skill 管理策略 RL 化，+4.01 over 最强 memory 基线）、SkillsBench 警告（LLM 自创技能 +0.0pp vs 人工策划 +16.2pp——技能质量门不能省）。
5. **写入宽进、读取严选 + 快照可回滚**。硬证据门（prime-agent）自主性弱且会被污染证据骗过；MemRL 式"写入宽松、Q 值后置惩罚"有理论保证；但必须保留可清除性/回滚（MemRL 自承 reward hacking 可快速扩散，回滚是唯一补救）。

## 3. 分歧点（设计权衡的真实前沿）

| 分歧 | 两方 | 裁决依据 |
|---|---|---|
| 记忆该不该进 context？ | DGM：记忆=基因型代码库，不进 context，零 collapse 风险 | 评测可自动验证时成立；**评测信号稀疏/不可验证的开放研究任务中失败**（教训粒度=整个 agent，同类 bug 跨分支反复犯） |
| 分支私有 vs 全局共享 | MetaSkill 分支局部+meta 检索传播 vs IBM/MemRL 全局库 | 全局迁移增益大（MemRL 跨任务合并几乎无干扰、跨模型 3.5×）但污染面最大；折中=默认任务局部，跨任务走泛化/抽象层（IBM subtask 机制） |
| 摘要周期 | ShinkaEvolve 周期 MetaSummarizer vs MemRL 即时 EMA | 周期摘要引入 staleness（适应度景观快变时持续推荐过时策略）；即时更新需可靠 reward |
| 遗忘=删除 vs 降级 | MemoryOS FIFO vs MemRL Q 值压低不删除 | 研究场景**阴性结果与被反驳假设是高价值记忆**，应降级归档而非删除 |
| 短期最优 vs 长期最优 | Tenure Crossover（2607.21962）：记忆架构排名随使用时长反转 | 评测必须在多个 tenure 点做纵向测量，单点评测结论不可信 |

## 5. M5 记忆评估协议（怎么知道记忆设计是对的）

**核心难题**：AutoResearch 的提升可能来自记忆，也可能来自检索算子/搜索策略/基座能力。基于 PAST-Bench 协议（唯一把 Task score 与 Mechanism score 解耦的 benchmark）改造：

1. **双重差分主指标**：`AblationLift = (eval−baseline)^{memory-on} − (eval−baseline)^{memory-off}`，剥离练习效应。
2. **三类配对控制**：no_persistence（隔离记忆贡献）/ shortcut（当轮直接给答案，防假阳性）/ **wrong_mechanism**（把经验放到错误通道——若它也能拿到同等增益，说明增益来自"有检索"而非"有记忆"，应归因到 M2/M6 侧。这是对 AutoResearch 最关键的一条）。
3. **机制分与任务分双轴**：mechanism = 写入证据（关键词命中、写入计数）× 检索证据（检索时机、先查后写顺序）× 时序证据（first_use_turn、repeat_violation）；任一环节为 0 总分归零（乘性合成）。
4. **触发强度×迁移距离扫描**：T3 显式 save 指令 → T2 无 save 措辞 → T1 被动暴露；near/far 双距离，报 overfit_penalty。
5. **卫生指标常驻**：memory_pollution_rate、stale_leak_events、over_storage_penalty、写路径 token 成本（必须披露 embedding 模型——MemDelta 教训）。
6. **负迁移必须显式报告**而非当噪声丢弃——这是发现例外污染的唯一途径。

可复用资产：PAST-Bench 源码 `metrics/v2_layer{1,2,3}.py`、`v2_trace_parse.py`（三个纯 trace 解析器零改动可用）、`family.yaml` schema。

# 第二部分：M6 Knowledge 设计空间

## 1. 三维分类学

**时机轴**（最重要）：①构想前离线建库（KAPSO、Tree-of-Ideas）→ ②构想中可选工具（Arbor grounded lane、orx-lit）→ ③构想中强制注入（R&D-Agent）→ ④构想后 veto 闸门（AI-Scientist，**反例**）→ ⑤验证后 advisory 审计（Arbor novelty audit）→ ⑥失败后条件化增强（KAPSO ERA）。

**来源轴**：公共文献库 / 通用 web / 代码仓库语料 / 策展知识库 / 内部经验（注意：R&D-Agent 的 "memory context" 全是内部经验——M5/M6 分界在它那里不存在，且其消融显示 memory context 边际贡献（−9%）远小于推理管线（−24%）：**外部知识模块没有好的消费管线则价值有限**）。

**用途轴**：启发 / 锚定起点 / 约束环境 / 修复 / 审计 / 引用溯源。

## 2. 关键设计模式与证据

1. **启发与审计必须隔离**（Arbor 两车道是唯一显式实现）：grounded ideation 与 novelty audit 独立检索、**从不共享抓取文本**——同一页面既启发想法又为其新颖性背书 = 循环论证。落地字段分离（`node.grounding` vs `node.related_work`）。
2. **审计后置、建议不阻断**：Arbor 的 novelty audit 三档 verdict（novel/partial-overlap/prior-art-exists）advisory 从不阻塞；AI-Scientist 的硬闸门+关键词浅检索是反例——第三方评测发现它把 micro-batching、自适应学习率等已知技术全判为 novel（漏报），而 LLM-as-judge 又会误杀 9/10 人类已接收论文（误报）。**工程答案：软审计 + 独立 SearchAgent + 来源必须实际打开过 + 面向更广文献而非只查自己用过的语料**。
3. **注入格式决定原创性**：2605.27905 大规模实证（219,655 个 AI 生成 idea）——AI idea 系统性更集中、更贴近起始文献、位于低影响区。问题不在"接外部知识"而在注入格式：**注入方案→克隆；注入 gap/约束/失败模式→扩大探索**。Tree-of-Ideas（2608.10740）是正面范式：引文演化树 → gap 中心信号卡 → 方向须 ≥2 条独立轨迹证据 + 非显而易见闸门（拒绝教科书式两方法组合）。
4. **多样性作为一等约束**：IDEAgent（2607.22375）把 ideation 建模为 QD 搜索，与祖先/被拒提案显式比较，Yield 指标 3.89×。
5. **预算分级**：构想期深读（~6k token/页，保方法章节）、审计期浅读（~2k，摘要足够）——Arbor 双 token 预算可直接借鉴。

## 3. M5 / M6 / M2 的边界划分（定稿）

- **M5 = 内部经验**（实验 trace 教训、历史方案、失败模式）——约束"别再试什么"；暴露 `recall(signal)`。
- **M6 = 外部世界**——回答"世界已知什么"；暴露两个工具：`query(intent)`（构想期，四 intent：related_work/survey/lookup/explore）与 `audit(idea)`（后置 advisory 三档）。只管"取、压、证、隔离"，不拥有消费逻辑。
- **M2 消费两者产物**；多样性/QD 约束属搜索策略层，M6 只提供去重所需 embedding/来源证据。
- **联合入口**：KAPSO ERA 模式——失败信号同时触发内部教训检索（M5）与外部修复 heuristic 检索（M6）。
- **防污染清单**：两车道零共享文本；benchmark 模式 M6 默认全关（保公平）；引用必须实际打开；审计用新鲜检索；审计结果永不做硬闸门。

# 第三部分：对框架 M5/M6 的定稿建议

## M5 定稿配置（默认值）

```
M5 Memory:
  表示: 结构化条目（category∈{hypothesis|evidence|method|pitfall}, trigger,
        priority, provenance{来源实验/文献ID}, confidence, ttl, scope）
        + embedding 双键                    # IBM TSM + MemRL 收敛配置
  分层: L1 原始记录 / L2 洞见条目 / L3 可执行方法知识（skill）
  写入: 宽进（无硬门）+ delta 增量（禁整篇重写，CLAUDE.md 不变量）
        + 非 LLM 确定性合并                  # ACE 教训
  读取: 两阶段（相似度召回 τ≈0.6 → 效用重排 λ=0.5）
        top-k≥5，严禁过小                    # IBM 负结果
  更新: EMA 效用 + supersession（废止非共存）+ 降级归档（不删除）
  治理: 活跃库有界 + per-entry 贡献分 + 周期退役评审  # Library Drift 新轴
  回滚: 快照可回滚                           # 污染后唯一补救
  卫生: 来源可信度/TTL/作用域元数据；不信任内容隔离；先检索后写入硬遥测
```

## M6 定稿配置

```
M6 Knowledge:
  车道: ground（构想期可选，intent 化，隔离上下文+压缩 digest）
        / audit（后置 advisory 三档，独立检索，零文本共享）  # Arbor 两车道
  注入格式: gap/约束/失败模式信号卡（带 provenance），非方案拼接  # ToI 教训
  预算: 构想深读 6k / 审计浅读 2k
  默认: benchmark 模式全关
  多样性: 新 idea 与祖先/被拒集显式比较（QD 约束在 M2 层执行）
```
