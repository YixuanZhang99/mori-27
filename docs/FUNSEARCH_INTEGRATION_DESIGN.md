# FunSearch integration design: pending implementation

Status: implementation design, not a working reproduction or benchmark. The pinned reference is [`google-deepmind/funsearch` at `cc53f274237d7ab05c19df939edbc1f9616a7c19`](https://github.com/google-deepmind/funsearch/tree/cc53f274237d7ab05c19df939edbc1f9616a7c19). `core.funsearch_population` is a tested standalone population mechanism; it is not yet part of `Framework` or the M7 runtime. `core.funsearch_selection` preserves ordered samples, distinct ancestry and before/after state references and can replay them; the runtime does not yet bind these receipts to its journal. The overall delivery plan is `docs/superpowers/plans/2026-11-04-evidence-delivery.md` Task 4.

## Existing seam and mismatch

`ComposedRuntime._prepare_cycle` calls policy selection and validates at most two **distinct** parent IDs. `OperatorRequest.parents`, evidence, the construction recipe and candidate ancestry all use that distinct sequence. In contrast the reference samples clusters **with replacement**, may place the same candidate in a prompt more than once, orders sampled functions by cluster score, and builds versioned functions plus an unfinished next version. It samples the destination island and returns that island for the next program registration. Treating a sampled list as ordinary `parents` would silently remove duplicates and lose island/epoch provenance; simply replacing the greedy selector is not sufficient.

The reference uses each per-test score for a canonical signature and the **last inserted** test's score as cluster objective. Our population component requires sorted frozen case IDs and interprets the last frozen ID as objective; this is an explicit adaptation and the task configuration must pin that ordering. It uses Python's seeded RNG, not NumPy global RNG. Its reset is explicitly invoked, not triggered by the reference's wall-clock timer. Epoch checks reject results generated for an island before it was reset; upstream leaves that asynchronous case unresolved. History survives resets. These differences must remain visible in each result.

## Required interface and invariants

1. A versioned `ProgramSelection` value contains the chosen island, epoch, ordered sampled candidate IDs including duplicates, and the population-state reference before and after sampling. The runtime persists the value before any physical provider call. It derives **unique ancestry** in first-seen order separately; the sampled list is never rewritten as ancestry. If the configured ancestry limit cannot represent the unique sampled IDs, fail configuration validation before any call; do not truncate silently.
2. A dedicated FunSearch recipe/materializer consumes the selection and projected public candidate artifacts, checks their IDs, hashes and source scores against admitted journal evidence, and emits the pinned template's versioned function sequence and unfinished next version. It must preserve repeated samples and rewrite direct recursive references safely. It must not smuggle private feedback, evaluator state, hidden data or other candidates into the provider prompt. Source, editable function, permitted interface, prompt version and the full selection must be bound to the construction receipt and replay verifier.
3. The domain reports a complete, immutable set of public per-test numerical metrics with the same fixed case IDs, evaluator and task/data identities. Only explicitly public items reach the planner. Private scores and text are not permitted in planning or model inputs. Partial, duplicate, seeded or non-finite instance values fail closed. The selected objective must be stated rather than derived from incidental mapping order.
4. A sample's island and epoch are frozen before generation. Register the evaluated child on that exact island only if its epoch still matches. A stale completed operation is retained as evidence but is not inserted into a newer island. Initial seed insertion is the only all-island operation. Reset decisions occur at declared deterministic operation counts, with a reference adaptation note, and record founders, scores and RNG state. No private control candidate can enter the main population.
5. Checkpoint and recovery bind population state, random state, ordered selections and reset decisions to the original event journal and evaluation receipts. Replaying a completed call must not reissue provider or evaluator work. An unmatched or conflicting journal event stops instead of reconstructing plausible state from a mutable checkpoint. Physical token/currency budget, sandbox and control-lane rules apply unchanged.
6. The public profile freezes all of the above: pinned task and evaluator, case set and order, program skeleton, editable function, model alias and prompt, sampling/reset settings, seed, iteration/budget and recovery policy. Provide a `Framework` offline fixture exercising initialization, repeated samples, generated program evaluation, reset, interruption and recovery, plus a separate real task package with exact artifacts and all outcomes.

## Implementation sequence

- Extend the runtime's selection protocol with optional typed ordered samples while preserving the legacy list return. Validate and journal sample membership and evidence before materialization; keep unique ancestry and sample order distinct. Add tests for repeated candidates, three unique candidates, policy tampering, empty/private evidence and recovery at the selection/call boundary.
- Implement a versioned program prompt construction adapter with strict AST/interface validation and test recursive names, template preservation, invalid code, injection via unrelated top-level definitions, duplicate samples and replay equality. Connect it to the standard construction receipts rather than calling a provider directly.
- Bridge public per-item numeric evidence into the planner session, and bind its journal/checkpoint state to committed evidence. Exercise isolated control lanes and epoch-stale result handling. Keep the existing GEPA-specific bridge semantics unchanged.
- Connect the existing sandbox/evaluator to the pinned public bin-packing workload. Compare fixed reference decisions and probabilities on controlled fixtures, then publish honest real-model outcomes within the authorized remaining campaign budget. These checks establish a scoped adaptation; they do not independently reproduce the paper's full distributed system or results.

A mock provider, an offline fixture or a population-probability comparison cannot close RUBRIC B4 or demonstrate benchmark parity. The separate real MLE pilot and its source-bound acceptance remain the execution priority.
