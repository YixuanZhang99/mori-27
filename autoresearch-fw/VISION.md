# VISION —— 框架存在的理由（最高裁决依据）

> 本文件是仓内层级最高的文档。任何范围争论、设计冲突、PR 取舍，以本文件为最终裁决依据；
> ADR-0（初版范围）、开发纪律、各 UNIFIED 文档均为其下位。修改本文件 = 项目级翻案，需写明新证据。

## 目的

**做一个"可证伪、可追责、可自证"的 AutoResearch 运行时——而不是又一个进化采样器。**

现有框架（OpenEvolve / FunSearch 系 / EoH / agentdescent / RSIHub）回答的都是"怎么生成和筛选候选"。
我们回答的是它们不回答的三个问题：

1. **这次搜索本身值得吗？**（Simple Baselines P=0.49：复杂流水线可与 IID 随机采样打平，而没有任何框架能告诉你这一点）
2. **预算花到哪去了？**（GEPA 85–90% 预算烧在验证表上；"花了多少 token"≠"这笔支出改变了哪个决策"）
3. **搜到的东西能信吗、能复现吗？**（无准入门、无 Receipt、无软证据作废；门卫逻辑散落且无人值守）

**我们框架 = AutoResearch 的治理层**：调度有依据（M1）、预算有因果（M3）、准入有凭据（M9）、
证据有谱系（I-谱系）、系统能持续证明自己没有自欺欺人（自我证成公约）。
M2/M4/M5 等"生成功能"是尽量复用成熟宿主的部分，不是我们的增量。

## 关键设计（最小充分集合，五条）

1. **intent_queue**：M1→M3 的可拒绝意图通道。调度器不直接花钱，只发意图；预算器可拒可减。全部问责能力的根基。
2. **StopActionTable**：停机查表。M1 只消费 M9 Verdict，永不重算统计。"判断质量"与"执行动作"物理分离。
3. **Receipt 谱系**：硬证据永存、软证据可作废。跨 run 合并、知识沉淀、复现回放全部建立在票据链上。
4. **自我证成公约**：退化基线（IID-RS/SCS）常驻，吃 5–10% 独立预算。系统运行时持续产出"我没有自欺欺人"的证据。
5. **默认沉默的复杂度**：八个操作面只有三个每代动作；复杂机制是保险丝不是发动机。框架复杂度 ≠ API 复杂度，目标接口是 `fw.evolve()`。

以上五条没有一条是新算法——它们是机制设计，来自失效案例的反推，不以论文形式存在。

## 开发四原则

1. **调研成果当测试库，不当灵感库。** 每个失效案例 = 一条回归测试；每条公理 = 一条 CI 断言。参考框架抄实现细节，失效证据守架构边界——两条管道不混。
2. **骨架 fork + 增量楔入 + 接缝守备。** 增量严格限于治理层；每条公理在宿主接缝处有测试守备（S-表）；顺手"改进"宿主逻辑 = 架构引力开始吃人的信号，宿主代码每行改动须能回答"对应哪条公理"。
3. **曳光弹优先，机制按保险丝顺序装。** 最朴素形态先跑通一代循环；机制按失效到达顺序加装（H2 监控 → 三态拒绝 → 相位信号 → pressure/inject）；每装一个机制，先验证它平时沉默。
4. **以"复现一个经典系统"为首个外部验收。** 纯靠配置 profile（不改框架代码）复现 FunSearch/GEPA 行为并落入公开区间，一次证明：抽象没漏、默认值没偏、文档能指导使用。

## 五条关键设计 → M0 六概念的映射（无本质丢失验证）

| 关键设计 | 内核承载 |
|---|---|
| intent_queue 可拒绝通道 | **K2**（本体）+ K3（拒绝的落账处） |
| StopActionTable 停机查表 | **K5** |
| Receipt 谱系（硬证据永存） | **K5**（append-only）+ K4（漏斗谱系字段预留） |
| 自我证成公约 | **K6**（常驻基线 + 5% 保留账户） |
| 默认沉默的复杂度 | M0 路线本身：六概念即全部运行时，扩展皆有触发条件 |

## 一句话

> 现有框架让机器自动做研究；我们的框架让"机器自动做研究"这件事本身变得**可审计、可证伪、可复现**。
> 用最朴素的路径（fork + 曳光弹）实现最坚硬的部分（治理层），让调研证据以测试的形式永远活着。
