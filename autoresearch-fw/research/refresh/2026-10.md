# 研究刷新 2026-10（D 流程首轮）

> 检索日期：2026-10-26。范围：RSI 新框架 / 评估器进化 / 供亲与谱系选择 / benchmark 版图。
> 每条按 D2 三问归档：轴映射 / 是否触发翻案 / 是否新扩展。

## 1. RQGM（Red Queen Gödel Machine）——命中 D3 强制复审

- **内容**：评估器与任务代理置于同一可进化工作区；每 epoch 冻结现役评估器；挑战者须经 held-out 锚点验证方可晋升；**作废依赖被替换评估器的分数记录**。
- **轴映射**：M8（评估器生命周期）、M9（准入凭据失效）、I-谱系（软证据作废的进化版）。
- **裁决要求**：**M8M9 过审时必须回答**——我们的"冻结评估内核"是否需要一个受控的评估器进化通道？RQGM 三件套（epoch 冻结 / 锚点验证 / 级联作废）与我方票据失效机制的对应关系。
- **初步判断【推断】**：M0 内核不动（评估器冻结）；作为新扩展登记："EvoEvaluator 扩展，触发条件 = 出现评估器成为瓶颈的实测证据"。
- 来源：https://www.preprints.org/manuscript/202608.0051（RSI 综述中 RQGM 条目）

## 2. HGM（metaproductivity-aware selection）

- **内容**：按谱系长期潜力而非当前最高分分配扩展预算。
- **轴映射**：M1 供亲（G 系轴）——与 greedy 默认形成直接对照证据。
- **翻案检查**：这是"greedy vs 非贪心"分歧（M1 §6-分歧1）的**新证据**，但不满足自动翻案条件（该条件是运行时塌缩报警率）；处理：登记进分歧 1 的证据栏，M1 复审时纳入。
- **扩展登记**：parent_select 的 metaproductivity 档，触发条件 = 长 run 中 greedy 长期收益显著落后。

## 3. DGM-Hyperagents（DGM-H）

- **内容**：元代理自身代码可进化；元层机制（性能追踪、持久记忆）可自发涌现并跨域迁移（paper review / 机器人奖励设计 → 奥赛评分）。
- **轴映射**：M2-O17 自修改四件套、M1 learn_govern。
- **处理**：设计银行登记，支撑"自修改扩展"的触发后设计；不进 M0。

## 4. OpenMLE 栈 / Frontis-MA1（外部印证 + benchmark 来源）

- **内容**：开放全栈 RSI（OpenMLE-Gym/RL/Evo）；四原子算子 **Draft/Improve/Debug/Crossover**（与 M2 四算子集一致）；MLE-Bench Lite Medal Average 与 NatureBench Lite 迁移数字公开。
- **意义**：① 四算子集的独立外部印证；② MLE-Bench Lite 对比基线来源（RUBRIC B2）；③ 其"执行接地 SFT/RL 训练算子"对应 M2-O14 学习档，作为扩展证据存档。
- **处理**：REFERENCES.md 增补；B2 验收时优先取其公开口径做对照。

## 5. MASS（Sakana，2026-10-12，多代理自监督）

- **内容**：同一模型的虚拟子代理团队 + 工作流搜索 + 自评判选择 + 蒸馏回模型；两轮循环后 score/token 达基座 1.2–1.6×。
- **轴映射**：M2 学习档（蒸馏通道）、M8 自评判（C9 同源共谋风险的活例）。
- **处理**：归档；其"同源自监督"正是 C9 监控对象，引用进 C9 证据栏。
- 来源：https://sakana.ai/mass/ ，arXiv:2610.12176，代码 SakanaAI/mass

## 6. Benchmark 版图确认（RUBRIC B 系依据）

可自动验证：MLE-Bench（75 Kaggle）、RE-Bench（7 个 ML 研究工程题、人机同限时对照）、CORE-Bench（论文复现）、PostTrainBench（固定时间预算后训练）、NatureBench Lite（OpenMLE 系）。
开放人评：MLR-Bench 等——不作 v1.0 验收（人评不可机器检查）。
另注：SAEScientist-Bench（表征审计）等新白盒方向与当前负载无关，仅归档。

## 7. 综述入口（后续刷新的种子）

- 《The Path to Recursive Self-Improving Agents》（2026-08，preprints 202608.0051）：统一框架 = 改进范围 × 改进程序；其 L3/L4 分级可作为我方"扩展档位"的外部参照。
- lobehub/awesome-rsi（持续更新）：作为每月检索的固定源之一。

## 8. RRSI（2026-09-21，第二轮补检）——搜索正则化的外部印证

- **内容**：proposer 采用随轮次退火的编辑预算并利用历史失败/成功记录；selector 增加 benchmark 特定逻辑筛查、噪声调整地板、成本约束和结构剪枝。原文明确讨论固定 evolve set 上的自适应过拟合及 OOD 增益收缩。
- **轴映射**：M2 提案历史与泄漏筛查、M8 噪声底、M3 成本证据、M5 阴性记忆。
- **翻案检查**：不触发内核翻案。噪声底计零、append-only 历史、软失效已经在 K3/K5/M5 路径；成本不得偷换成 M9 聚合分，仍应作为 M3/M4 的独立轴。
- **扩展登记**：`leakage_critic` 与 `annealed_edit_budget`，触发条件分别是 benchmark 特定候选首次出现、单次候选捆绑编辑导致归因失败。
- 来源：[arXiv:2609.24972](https://arxiv.org/abs/2609.24972)，[google-research/rrsi](https://github.com/google-research/rrsi)。

## 9. HarnessPro（2026-10-20）——性能—成本前沿与固定生成测试

- **内容**：从无官方标签的轨迹生成测试并在进化期间冻结；候选按 pass rate 与执行成本做 Pareto 过滤，再选 lite/medium/heavy 代表点，最终冻结后仅在 held-out test 终评。论文报告 GPT-5.5 × Codex 的 heavy 模式相对 RHO 在三个 benchmark 上平均 pass rate +2.0pp、每任务成本 −26.1%。
- **轴映射**：M4 多目标档案、M3 分币种成本、M8 固定测试与 held-out 纪律、M9 性能准入。
- **翻案检查**：不触发 M9 改分。其成本—性能选择可映射为 **M4 Pareto archive 扩展**，而不是把成本混进 per-item flip gate；生成测试属于评估资产，初次注册要质量探针，后续变更走已实现的 anchor meta-gate。
- **扩展登记**：`performance_cost_frontier`，触发条件 = 同分候选出现持续成本分化，且账本成本覆盖率 100%。
- 来源：[arXiv:2610.26770](https://arxiv.org/html/2610.26770)。

## 10. Harness²（2026-10-09）——并行/顺序递归与经验回流

- **内容**：将任务级 harness 改进与 harnessing-level 改进分层；并行递归组合多候选及执行证据，顺序递归把精炼 harness 和积累证据带入下一步。
- **轴映射**：M2 compose/crossover、M5 经验记忆、M1 相位协议。
- **翻案检查**：不触发当前 greedy 或单父 improve 翻案；其收益依赖具体负载与组合协议，先作为 crossover/merge 三件套就位后的对照 profile。
- **扩展登记**：`parallel_sequential_harness_compose`，触发条件同 ADR-0 crossover/merge，且必须有跨任务 held-out 证据。
- 来源：[arXiv:2610.14224](https://arxiv.org/html/2610.14224v1)。

## 11. AIDE²（2026-09-22，v56 翻案复检）

- **内容**：研究代理修改自身代码，在固定评估预算下经隐藏选择集保留改写，并另用未参与选择的 benchmark 检查迁移；论文同时区分选择集增益与二阶 held-out 泛化。
- **轴映射**：M8 选择／测试隔离、M3 固定物理预算、RUBRIC B2/B3 双臂与外部实测。
- **翻案检查**：不触发 M0 或 M9 翻案，也不支持用 archive 最优替代明确部署对象。它加强 v53/v54 的选择契约与回执，以及“必须运行真实外部 campaign 才能声称 parity”的边界。
- **对 v56 的影响**：没有改变安全切片的必要性；seccomp 证据只认证执行隔离，不被解释为研究能力提升。
- 来源：[arXiv:2609.26457](https://arxiv.org/html/2609.26457v1)。

## 12. GEPA／Autoresearch 受控比较（2026-04，v56 翻案复检）

- **内容**：在相同任务、预算和评估基础设施下比较自动 artifact 进化方法，显式区分 training、validation 与 held-out test，并强调评估预算是绑定约束。
- **轴映射**：M3 全成本测量、M8 数据分段、RUBRIC B 同预算对照。
- **翻案检查**：不支持继续堆叠采样器；后续优先级仍是实际 RE-Bench／MLE-Bench Lite 双臂 campaign、完整物理成本与选择证据，而非把本地协议夹具当外部成绩。
- 来源：[arXiv:2604.04347](https://arxiv.org/pdf/2604.04347)。

## 13. v57 安全切片翻案复检

- **复检依据**：沿用本轮 AIDE² 与 GEPA／Autoresearch 受控比较关于固定预算、隐藏选择和真实外部对照的证据要求；没有将执行安全机制误作研究收益证据。
- **裁决**：不触发 M0、M9 或供亲协议翻案。v57 只把既有危险系统调用拒绝清单扩展到 durable `ExternalCommandLLM` worker 的 direct-prctl delivery，优先级仍低于真实 RE-Bench／MLE-Bench Lite 双臂 campaign。
- **边界**：保留 proposal 网络和环境继承是功能要求，不是凭据隔离证明；本地 HTTP 夹具不构成真实外部 API campaign，也不产生 benchmark 分数或 USD 效率结论。
