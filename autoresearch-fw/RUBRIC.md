# RUBRIC —— "趋于完美"的验收定义 v1

> 地位：仅次于 VISION.md。框架开发完成的判据 = **A 架构质量 + B benchmark 表现 + C 治理指标 全部达标**；
> D 研究新鲜度为持续义务（无终点，但有节奏与漏检判据）。
> 每条 rubric 必须可机器检查或有明确人工验收程序；不许出现"看起来不错"式条款。

## A. 架构质量（可抽象复用 / 可维护 / 可扩展）

| # | Rubric | 达标线 | 检查方式 |
|---|---|---|---|
| A1 | 内核概念数 | M0 = K1–K6，不增；公开入口 ≤ 3 个（evolve / inspect / replay） | API 表面扫描 |
| A2 | 纯配置复现 | ≥ 2 个经典系统（gepa_reflective + funsearch_island）纯 profile 复现，**零内核改动** | 复现实验 + diff 为空 |
| A3 | 扩展不改内核 | 每个协议扩展（见 ADR-0 v2 表）装回时只新增插件文件 + 注册行 | 抽 2 个扩展实测：新颖性闸、H2 监控 |
| A4 | 公理即测试 | 内核公理 CI 断言覆盖率 100%，全绿；静态扫描（通道/禁时钟/查表）在 CI 强制 | CI 报告 |
| A5 | 依赖卫生 | M1→M3 仅 intent_queue；模块间无循环依赖；sync 路径无 LLM/网络/时钟 | 静态扫描 |
| A6 | 文档-代码一致 | CONTEXT.md 无表外术语；新人仅照《开发指南》可跑通曳光弹 | 术语扫描 + 冷启动演练 |
| A7 | 深模块检查 | 每模块接口数/内部机制数比 ≤ 1:3；无"透传型"浅模块 | 定期架构评审（mattpocock 式 survey） |

## B. Benchmark 表现（实测验收）

> 原则：**我们是治理层，不以 SOTA 为目标**；达标线 = 同预算下与宿主打平 + 治理指标显著优 + 自证成立。

| # | Rubric | 达标线 | 备注 |
|---|---|---|---|
| B1 | 自证成立（最重要） | 首发 GEPA 负载上，主搜索相对 IID-RS 的增量 **> M8 噪声底**；若打平，框架必须如实报告而非掩盖 | 自我证成公约的直接验收；P=0.49 教训 |
| B2 | MLE-Bench Lite | 经 ZOO TaskAdapter 接入；同预算同模型下与 OpenEvolve 宿主基线差值在噪声底内 | 不追求奖牌率 SOTA |
| B3 | 时间预算对照 | RE-Bench 或 PostTrainBench 择一，跑通并产出可对照分数 | 验证时间/预算治理路径 |
| B4 | 公开区间复现 | ≥ 1 个经典系统的公开报告区间复现（GEPA 样本效率或 FunSearch 不退化） | VISION 开发原则 4 |
| B5 | 预算效率 | admitted_per_usd 不低于宿主的 80%（治理开销 ≤20%） | 治理不能贵到吃掉搜索 |

## C. 治理指标（我们的差异化，必须全 100%）

| # | Rubric | 达标线 |
|---|---|---|
| C1 | 账本覆盖 | 100% 预算支出可映射到七账户 + 对应 intent；对账零缺口 |
| C2 | 凭据覆盖 | 100% 准入有 Receipt，append-only；100% 停机动作可查表复现 |
| C3 | 基线常驻 | 全部正式 run 中 IID-RS 在场，保留账户支出可查 |
| C4 | 回放能力 | 任一 run 可由 snapshot_ref + Receipt 链确定性重放（同种子） |

## D. 研究新鲜度（持续义务）

| # | 规则 | 内容 |
|---|---|---|
| D1 | 刷新节奏 | 每月一次饱和检索（RSI / self-evolving / 评估器进化 / benchmark 四路），产出 `research/refresh/YYYY-MM.md` |
| D2 | 纳入程序 | 每个新工作三问归档：映射到哪个轴/扩展？是否触发某分歧的翻案条件？是否产生新扩展？ |
| D3 | 强制复审名单 | 命中内核机制的新工作（评估器可进化、供亲新证据、基线方法学）必须触发对应分歧复审，不许只归档不裁决 |
| D4 | 漏检判据 | 若外部评审指出一个已发布 >2 个月且命中内核的工作未被登记 = D 流程失效，需复盘检索式 |
