# 开发纪律 v1

> 四件套：① CONTEXT.md 术语表 ② 公理即测试 CI ③ 曳光弹工单 ④ 公理-宿主接缝对照表。
> 原则（mattpocock 口径）：**小步、刻意；反馈循环的速率就是开发速度的上限。**

## ① CONTEXT.md —— 全仓唯一语言

代码中的命名必须且只能来自下表。新增术语先进此表，再进代码。

| 术语（代码命名） | 含义 | 设计锚点 |
|---|---|---|
| `Policy` / `policy_id` | 被调度的一整套搜索策略实例 | M1, PolicyLineage |
| `ParentFormula` | 供亲公式配置（默认 greedy） | M1-H1, §6-分歧1 |
| `AllocationIntent` / `IntentReceipt` | M1→M3 唯一通道的请求/回执 | M1 v1.1, R1/R2 |
| `intent_queue` | 上述通道的物理队列；代码中 M1 与 M3 之间唯一合法连接 | M1-H-通道唯一 |
| `PhaseSignal` | 相位信号（relay_gain 主 + budget_fraction 兜底） | M1-H-信号 |
| `StopActionTable` | (Verdict, scope) → Action 查找表 | M1-H-查表 |
| `BudgetLedger` / `CostAccount` | 三级键账本 / 七账户枚举 | M3-J 系列 |
| `Receipt` | M9 准入裁决凭据（硬证据，永存） | I-谱系 |
| `ground_lane` / `audit_lane` | M6 双车道：事实 / 审计 | M6-D 系列 |
| `inadjudicable` | CI 低于噪声底时的一等输出（非错误） | M1-G17 |
| `degenerate_baseline` | 常驻退化基线（IID-RS/SCS） | 自我证成公约 a 条 |
| `collapse_alarm` | 塌缩报警；greedy 档 2× 对照臂即触发默认复审 | M1 §9-10 |

**规则**：代码评审发现表外术语 → 要么改名，要么先补表。同义词（如 "selector"/"picker" 代指 parent_sample）视为 bug。

## ② 公理即测试 CI

违反任一条 = 构建失败。初版先落静态扫描四条 + 单测两条：

| 编号 | 类型 | 断言 |
|---|---|---|
| T-H1 | 构建期 | 缺 h2_monitoring 或结构多样性载体 → 拒绝启动 |
| T-通道 | 静态扫描 | M1 包内除 `intent_queue.put` 外无 M3 引用 |
| T-禁时钟 | 静态扫描 | sync 路径调用图内无 `time.now`/`datetime`/网络/LLM 客户端 |
| T-查表 | 静态扫描+单测 | M1 收到 Verdict 后只有一次 `StopActionTable` 查找，无统计调用 |
| T-确定性 | 单测 | 同一 snapshot_ref 两次 parent_sample 结果逐位相同 |
| T-回滚 | 监控 | collapse_alarm 率 > 2× 对照臂 → 自动报警（非 CI，运行时） |

每过一个模块的 UNIFIED 过审，把该模块的"公理即测试"清单追加到本节。

## ③ 曳光弹工单（Ticket #1）

```
标题：一代循环最小骨架（GEPA 负载）
范围：
  1. M1: greedy parent_sample + 固定预算 AllocationIntent + StopActionTable 查表
  2. M3: BudgetLedger 最小实现（七账户、reserve→settle、三态 IntentReceipt）
  3. M8/M9: 数值评分 + 文本反馈 + Receipt 签发（单阈值 Verdict 即可）
  4. M2: draft + improve 反射式算子（接 LLM，走异步）
  5. 退化基线 IID-RS 常驻，5% 保留账户
显式不做：pressure_control / inject / learn_govern / idle 槽 / 多 profile / 加权供亲
依赖边：无（第一张工单）
验收：初版范围文档 §成功标准 第 1、2、5 条
```

## ④ 公理-宿主接缝对照表（OpenEvolve 改造专用）

fork 的最大风险是**架构引力**：宿主假设悄悄吃掉公理。每条接缝一个测试守住。

| 编号 | 公理 | 宿主假设 | 接缝处理 | 守缝测试 |
|---|---|---|---|---|
| S-1 | M1-H-通道唯一 | OpenEvolve 直接调 evaluator/db | M1 与 M3 之间插入 intent_queue 适配层 | T-通道（扫描适配层无旁路） |
| S-2 | M1-H-查表 | 宿主在 loop 内做成功/失败判断 | loop 内判断逻辑替换为 M9 Verdict + 查表 | T-查表 |
| S-3 | M2 反射式 improve | 宿主 improve = 代码 diff | 新增 reflective improve 算子，diff 通道降级为可选 | 单测：GEPA 负载下 improve 输入含评估轨迹文本 |
| S-4 | M8 文本反馈 | 宿主评估只回 float | EvaluatorResult 增加 feedback_text 字段，进 ground_lane | 单测：字段缺失 = 评估失败 |
| S-5 | I-谱系（Receipt 永存） | 宿主 DB 可覆盖更新 | Receipt 表 append-only | 单测：update/delete 无对应 API |
| S-6 | 自我证成公约（退化基线常驻） | 宿主无此概念 | 新增 baseline policy 常驻 + 保留账户 | 集成测试：每代预算流水中可见 baseline 支出 |

**规则**：发现第 7 条接缝时，先暂停开发，评估是否触发《初版范围》的骨架翻案条件（冲突点 > 3 处需改宿主核心循环）。
