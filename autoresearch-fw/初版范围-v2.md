## M0 内核：6 个概念（预计 2–3k 行）

| # | 概念 | 来源模块 | 最小形态 |
|---|---|---|---|
| K1 | `op()` 统一算子签名 + 确定性 patcher | M2 | 只实现 **draft + improve（反射式）** 两个算子；LLM 产提案、代码落地 |
| K2 | `intent_queue` 可拒绝意图通道 | M1→M3 | AllocationIntent / IntentReceipt 三态回执 |
| K3 | `BudgetLedger` 七账户账本 | M3 | reserve→settle 预扣结算；流水可查 |
| K4 | `FunnelRecord` 四段计数 | M2 | proposed→applicable→runnable→admitted，每代 4 个数字 |
| K5 | `Receipt` + `StopActionTable` | M9→M1 | 准入留票据（append-only）；停机只查表 |
| K6 | 退化基线 IID-RS 常驻 | 自我证成公约 | 5% 保留账户，与主搜索同跑同记账 |

**交流口径（一句话）**：
> 一个带账本、凭据和常驻对照组的进化循环——调度器发意图、预算器可拒绝、准入留票据、随机基线永远陪跑。

## 显式推迟的协议扩展（设计银行，附装回触发条件）

| 扩展 | 出处 | 装回触发条件 |
|---|---|---|
| 新颖性闸 + 多样性探针 | M2-O8/O9, C1/C3 | 观察到 near_dup_rate 上升或多样性报警（**预期最早触发，预留接口**） |
| H2 有效供亲数监控 | M1-H2 | greedy 塌缩报警首次出现 |
| debug 算子 + 兜底 | M2-O12 | 失败子代率 >20% 且被直接丢弃 |
| crossover / merge | M2 分歧6/7 | 漏斗显示单父改进饱和 + 契约三件套就位 |
| 相位信号 / phase_switch | M1 | 单次 run 预算超阈值、出现明显相位收益 |
| op tax 精细定价 / handoff | M2-O19 | 账本显示算子成本结构失衡 |
| M6 外部知识 | M6 全文 | 任务明确需要检索外部知识 |
| bandit / RL / 学习化算子 | M2-C10 三前置 | 漏斗数据积累 ≥数十代 + 消融超噪声底 |
| 自修改四件套 | M2-O17 | 出现 executor_spec 级候选（T≥ExecutorSpec） |
| 多 profile（除 gepa_reflective） | 各 UNIFIED §8 | 内核稳定后作为验收测试逐个点亮 |

## GEPA × OpenEvolve 缝隙（保留 v1 登记，不变）

- M2 反射式 improve 改写、M8 文本反馈字段，均为 K1/K5 的内核内义务（不是扩展）。
- 翻案条件不变：曳光弹阶段缝隙冲突 >3 处需改宿主核心循环 → 复审骨架决定。

## 初版成功标准（Definition of Done，v2 口径）

1. 一条 GEPA 负载跑通 ≥ 50 代，全程只动用 K1–K6；
2. M1 同步路径无 LLM/网络/时钟调用（CI 静态扫描通过）；
3. 账本七账户流水与 intent 一一对账；
4. 每次准入有 Receipt，停机动作可查表复现；
5. IID-RS 常驻同跑，预算来自 5% 保留账户；
6. **新增**：内核代码中不出现任何"协议扩展"列里的机制名（代码扫描）。
