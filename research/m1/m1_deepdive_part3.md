## G13 分配意图输出形式（M1→M3 唯一通道，刚性）★

> 轴定义回顾：M1→M3 的接口形态——M1 只产出意图，记账、拒绝与配额执行全部归 M3。本轴深挖增量：**intent_queue 的 schema 草案**（字段设计）与"拒绝回流回路"的通道语义。

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| ratio_table | 固定比例表（explore/exploit/重评/移交各占固定份额），无状态响应；等价于把 G6/G7/G9 全部冻结成一张静态配置 | 无正面一手证据——它是全部经典系统的实际默认（OpenEvolve 0.7/0.2 硬编码、GEPA 固定验证预算分配，作者自承须"动态选择验证子集"补救，arXiv:2507.19457）；反面：RelayEvolve Fixed-switch 对照臂全败（arXiv:2608.05651）证明静态表无法响应搜索状态 | 退化对照投影位（S-B15：作为 intent_queue 的永驻对照形态）；或评估环境完全平稳、预算极小的场景【推断】 |
| intent_queue（**默认**） | M1 每个决策块（G6=per_block，h~10 代量级）产出一组带优先级的块级分配意图条目流入队列；M3 按预算记账消费，可整体拒绝/削减/延迟单条意图；被拒绝的意图携带拒绝原因回流 M1 与 X1 | RelayEvolve 块级 Grow–Deepen 11/12 设置均值最高（arXiv:2608.05651）；ShinkaEvolve proposal/eval/db 三池配额为块级意图流的工程先例（arXiv:2509.19349）；AIDE² 外环 ~90% 拒绝率（weco.ai 2026-07，厂商博客级降档）——意图被下游打回的回路必须存在，否则 90% 的拒绝动作无处表达 | **默认值**。与 G6 块粒度绑定——粒度不同则队列条目语义不可定义（逐 call 意图流被 RelayEvolve 一手判死刑） |

### 2. 隐藏结构

- **本轴是"M1 不记账"公理的机械执行装置**。M1 只输出意图、M3 记账拒绝（轴系原则 5 刚性边界）要可执行，前提是所有 M1 的决策成果能被压进一个可被拒绝、可归因、可延迟的数据结构——intent_queue 就是这个压缩格式。ratio_table 的深层缺陷不是"太简单"而是**不可拒绝**（比例表无条目粒度，M3 只能整体接受或整体违约），它使"拒绝回流"回路在类型层不存在，AIDE² 式 90% 拒绝率场景下 M1 会盲目继续生产注定被打回的意图。
- **粒度-机制-输出三位一体（G6×G7×G13 绑定）**：块级粒度（G6）、块级 bandit 分配（G7）、块级意图流（G13）是同一个"块"在三个轴上的投影——任一轴降格到 per_call 都会拉爆另外两个（per_call 意图流的记账成本超过决策本身，RelayEvolve 近视失效是算法层死因、记账成本是工程层死因）。
- **成本可归因标签是 C6 横切约束的唯一落点**：意图条目必须携带 {预估 token/美元成本， 成本归属账户}，否则"探索预算的机会成本记账"（S-B3）无记账载体——探索份额超阈须附近期探索转化率的举证义务，其分子分母都从意图条目的成本标签+下游验收结果里取。
- **拒绝回流是一等谱系事件**：被 M3 拒绝的意图不是"没发生"，而是"发生了并被否决"——回流记录 {intent_id, 拒绝原因， 当时预算余量} 进 X1，与 S-B6"handoff 被否决候选携带否决原因回流"共享同一结构（G18 的策略侧对应物）。

### 3. 反直觉结论

**intent_queue 的最重要的字段不是"分配多少"，而是"这条意图死了找谁"——可拒绝性（rejectability）才是本轴相对 ratio_table 的本质升级。** 直觉上接口设计追求的是表达力（能描述多精细的分配）；证据链显示真正的增量在**回路**：RelayEvolve 的 0.85 占比、POCAII 的相位曲线都能用 ratio_table 静态表达，但 Fixed-switch 全败与 AIDE² 90% 拒绝率共同证明——静态表达的正确性依赖"此刻的状态恰好是设计时预见的状态"，而搜索状态不可预见。意图队列把 M1-M3 关系从"命令-执行"改为"报价-成交"：M1 报价（意图+理由+成本），M3 按预算撮合，未成交部分回流成为 M1 下一轮决策的一等输入。**没有拒绝回流的分配接口，等价于假设 M1 永远不犯错**。

### 4. 模块接口

- **M3（★刚性边界，唯一通道）**：记账、配额执行、拒绝、成本结算全部归 M3；M1→M3 之间不允许存在第二信道（旁路意图=绕过预算治理，构建期拒绝）。
- **X1**：意图条目、拒绝回流、队列状态快照入谱系——G12 退化对照做组件级归因（S-B17）时，"策略增量"的分母就是意图流的历史。
- **G6/G7**：粒度与机制的同块级绑定（上述）；**G14**：策略版本变更后，旧版本在队列中的在途意图须显式处置（失效/重估/继承），否则策略谱系（G15）无法归因"这条意图是哪个版本签发的"【推断】。
- **M8（间接）**：意图条目的 `expected_gain` 字段若被填写，须携带 CI 口径（消费 ReliabilityMeta，见 G17），空填合法——防止伪精度污染 M3 的排序【推断】。

**intent_queue schema 草案**（本轴核心增量，类型层建议物化）：

```python
# core/policy/types.py（建议；与 M4-UNIFIED Layer 1 风格对齐）
class AllocationIntent:            # M1→M3 唯一通道的条目类型
    intent_id: str
    block_id: str                  # 块级粒度标识（×G6，h 代一块）
    kind: Literal["explore", "exploit", "reeval", "handoff", "spawn_island"]
    target: str                    # island_id / trajectory_id / phase
    budget_estimate: float         # 成本可归因标签（C6 落点；单位=token 或美元，归 M3 口径）
    cost_account: str              # 归属账户（explore/exploit/reeval 三账户，S-B3）
    priority: float                # 队列内排序；M3 可按预算重排
    rationale: str                 # 触发信号摘要（如 "relay_gain_saturated", "stagnation_G_t≤0.02"）
    expected_gain: Optional[tuple[float, float]] = None  # (点估计, ci95)；空=不声明
    policy_version: str            # 签发本意图的策略版本（×G14/G15 谱系绑定）
    ttl_blocks: int = 1            # 过期块数——旧意图自动失效，防陈旧意图被执行
    snapshot_ref: str = ""         # 关联的档案快照（×G18：不可逆类意图须挂快照）

class IntentReceipt:               # M3→M1 回流（拒绝回路）
    intent_id: str
    verdict: Literal["accepted", "rejected_budget", "rejected_quota", "deferred"]
    reason: str                    # 拒绝原因（回流 M1 与 X1）
    executed_cost: float = 0.0
```

设计要点三条：
1. **`kind` 封闭枚举 + `ttl_blocks` 默认 1**：意图是易腐品——搜索状态变一块，旧意图的 rationale 即失效；FunSearch 4h 固定重置被生态继承的教训（arXiv:2511.00183）说明"过期的策略决定继续被执行"是真实失效路径。
2. **`expected_gain` 可空但非空时强制 CI 形态**：对齐 M8 公理 B7"无 CI 不报数"（M8M9-UNIFIED §2），把 G17 的统计门槛前移到意图生成处而非事后审计处。
3. **`policy_version` 必填**：策略可学习性（G14）开启后，意图归因是策略谱系评估（G15 的 J 信号）的唯一数据源——没有它，EvoX 式 (S,J,ϕ) 的 J 无法按策略版本切片。

### 5. 证据空缺

- intent_queue 作为显式接口形态**无任何一手系统先例**——RelayEvolve/ShinkaEvolve 的块级配额是内部实现而非跨模块协议，schema 草案是纯设计外推【推断】。
- 拒绝回流回路的效果量化缺失：AIDE² 的 90% 拒绝率是"意图被打回"的存在性证据，但"回流原因被 M1 消费后策略改进了多少"无任何测量。
- `ttl_blocks` 的取值、意图过期率与搜索效率的关系无标定数据。
- budget_split_curve 与 intent_queue 的组合形态（曲线包络+队列修正）无双系统收敛，组合规则是设计外推【推断】。

### 2. 隐藏结构

- **五档梯度不是"越来越先进"，而是"学习对象逐级升维"**：bandit 调的是**统计量**（标量表）、外层爬山改的是**代码**（结构串）、EvoX 进化的是**种群对象**（带谱系的条件化策略）、RL 训练的是**参数**（连续权重）。每升一档，"策略是什么"的本体就换一次——这解释了为什么阴性发现 3（无通用谱系表示）必然存在：四家系统的策略本体不同构，任何"通用格式"都必须先裁决策略的表示层。
- **默认值 frozen 的真正理由不是保守，是可归因性**：DGM 冻结声明与 AVO 判断的深层论据——G12 退化对照（S-B15/S-B17 组件级归因）要求被归因对象在测量窗口内恒定；策略若在运行期自变，对照实验的增量无法归因到"策略 A 还是策略 B"，自我证成闭环断裂。运行期 frozen + 离线 meta_evolvable 的默认值本质是把"变化"放逐到离线层，使在线层永远可审计【推断】。
- **bandit_online 档的证据排序是反直觉的弱**：ShinkaEvolve 内部消融显示 bandit ensemble 增量最小（slightly），而 hal-00519579 给出经典文献的系统性负结果——bandit 档是五档中**证据-声誉倒挂最严重**的一档（叙事上无懈可击、实测增量最小），S-B14"元决策预算按已测增量排序"直接针对此档。
- **EvoX 的涌现相位序列（random→greedy→分层多目标→UCB）是 G8 相位模型的存在性反证与再证**：证明相位结构有信息含量（涌现出来且各相位增益可测），同时证明人工相位表不是唯一来源——但 EvoX 单系统证据不足以把"相位交给进化"升为默认【推断】。
- **AIDE² 降档声明的操作化**：引用 AIDE² 时必须同时引用 (a) 厂商博客出处 (b) 非同行评审标注 (c) 其关键数字（0.739、63%→34%）未见独立复核。其方向性结论（外层爬山可行）被 EvoX/EvolveNet 的机制收敛部分佐证，但幅度数字不可作为设计参数依据。

### 3. 反直觉结论

**"策略可学习"的最强证据（Harness-R1 +9.3、20/20 迁移）恰恰不证明 M1 策略可学习——它证明的是 harness 可学习，两者之间隔着一个未被任何人跨越的鸿沟（阴性发现 1）。** 直觉把五档梯度读成一条通往 RL 训练策略的进化阶梯，越往右越接近"终极形态"；证据显示梯度右端在 M1 域内是空的：梯度训练策略的全部一手证据都在 harness 域，进化循环内部的策略学习全部停在 LLM-进化（EvoX/AIDE²）形态。由此得出的设计结论与直觉相反：**默认值 frozen 不是"暂时的妥协"，而是当前证据下唯一可被 G12 审计的形态**；而 rl_trained 端点的价值不在于启用，在于它标定了框架的**扩展预留位**——策略参数化接口的类型槽应现在就留出（避免 OpenEvolve 式硬编码锁死未来），但槽内默认填 frozen。

### 4. 模块接口

### 5. 证据空缺

## G15 策略谱系与版本治理（★与 G14 共生；阴性发现即设计机会）

> 轴定义回顾：策略版本如何记录、评估、接受/回滚、跨循环层引用。深挖增量：**通用 (S,J,ϕ) 谱系契约抽象**——三家私有表示的最小公共上界。

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 无版本（单策略） | 经典默认：策略即代码，变更即改源码 | OpenEvolve ProgramDatabase 策略硬编码、"换策略需改源码"（newworks_groupE_evol2）——无版本使退化对照在工程上不可执行，S-B15 被架构固化的反例 | **G14=frozen 时的默认值**；此时"谱系"退化为代码版本控制，无需运行期机制 |

### 2. 隐藏结构

- **通用 (S,J,ϕ) 契约抽象（本轴核心增量）**：三家私有表示的最小公共上界可抽象为四元组 `{policy_id, parent_policy_ids[], deploy_context, acceptance_evidence}`——EvoX 的 (S,J,ϕ) 中 S→policy_id+本体引用、J→acceptance_evidence 的统计量、ϕ→deploy_context；AIDE² 的版本链→parent_policy_ids、held-out 分→acceptance_evidence；EvolveNet 的门控→acceptance_evidence 的逐 item 形态、回滚指针→部署状态标注。抽象后的契约显式暴露三家各自的空缺：EvoX 缺回滚原语、AIDE² 缺部署上下文标注（ϕ）、EvolveNet 缺进步率信号（J）——**阴性发现 3"无可移植规范"的正面读法是：每家都只实现了契约的一半，全契约是框架的设计空位**【推断】。
- **J 信号是 G17 的策略层投影**：进步率 J 若按点估计计算，谱系库的排序键就是 winner's curse 排行榜（Grillotti 2023：重测显著低于记录值）——J 必须带 CI 口径（消费 ReliabilityMeta），否则策略谱系治理退化为"给噪声高的策略版本加冕"【推断，与 G17 的耦合是结构性的】。
- **回滚目标="上一共享稳定版"而非"历史最优"是反 winner's curse 设计**：历史最优版的分数含噪声高估（重测回归），上一共享版的分数被后续运行持续重评、估计更准——EvolveNet 这一选择与 M9 Receipt 失效引擎（B11 软证据作废、硬证据永存）同构：回滚锚定的是**证据成熟度最高的版本**而非分数最高的版本【推断】。
- **谱系库与 M4-P16 档案合并的术语对齐**：策略合并/回滚与档案合并协议同构（都是"多来源版本的可验证合并+失败回滚"）——scope 分类、逐 item 门、快照回滚的词汇应从 M4-P16/MergeEvidence 直接复用，避免同一概念两套术语（M4-UNIFIED §3.8 双前置硬门的策略侧投影）。

### 3. 反直觉结论

**策略谱系治理的零号教训是：回滚到"历史最优版本"是一个噪声陷阱，正确回滚目标是"最近共享稳定版"——治理系统里最高分和最安全是同一个排行榜的幻觉两端。** 直觉上版本治理=保留最好的+丢弃差的（better-only 接受给人这个印象）；EvolveNet 的回滚协议揭示另一半：接受端可以 better-only（因为 held-out 判据有 CI 把关），**回滚端必须 stability-first**（因为历史最优分的噪声高估会在危机时刻二次伤害）。由此推出谱系库的双排序键结构：接受用 J（进步率，带 CI），回滚用"共享时长×最近重评存活"（稳定性）——两个键不可合并，合并即把 winner's curse 引入灾难恢复路径【推断】。

### 4. 模块接口

- **X1（★一等输出）**：策略谱系条目（四元组）全部入 X1，与候选谱系同库异类型；版本变更、接受/拒绝、回滚事件为一等谱系事件（对齐 M4-UNIFIED §3.10"合并事件与异源谱系边"的同型待遇）。

## G16 多主体策略分工（与 M4-P16 镜像）

> 轴定义回顾：探索/利用权衡在多个并行进化主体间的配置——从单主体内采样分布升格为多主体间角色编排。与 M4-P16 互为镜像：P16 管存储侧合并，G16 管策略侧角色编排。

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 单主体（**默认**） | 无分工，全部探索/利用权衡在主体内采样分布内表达 | 全部经典系统默认形态 | 单 run 短周期、单部署点 |
| 同质并行分支 | 多分支不加角色干预——**失效取值** | C 组卡片 5：LLM 先验使独立并行分支坍缩到同类编辑（2023 前不存在的新问题）；EvolveNet 角色指派消融为反向证据（去掉角色指派则分支趋同，arXiv:2608.04968） | 永不合法于多主体场景——LLM 先验同质化是结构性而非参数性的，调温度/配比治不了【推断】 |
| 异质角色指派（**多主体默认**） | 按 client index 显式指派互补搜索角色（conservative repair / independent exploration / adversarial audit），角色=意图层分工，探索/利用权衡从分布参数升格为角色配置 | EvolveNet：BIRD held-out **70.7% vs 等总预算集中式 67.3%**（配对 14 胜 9 负）；DS-1000 合并 harness 超最强单 client **+9.0**；无门控链式合并直接崩溃回滚（arXiv:2608.04968）；对抗角色变体：分布式 Red Queen QD 跨节点共享 hall-of-fame（arXiv:2605.27130，workshop 级降档） | 多主体场景默认值；**前置=合并门控在位**（无门控的崩溃证据出自 EvolveNet 自身反面消融——角色分工的收益依赖存储侧合并协议，G16 与 M4-P16 必须同时开启【推断】） |

### 2. 隐藏结构

- **G16 的失效取值（同质并行）是 LLM 时代特有的**：2023 前岛屿模型的并行分支天然异质（随机初始化的差异被变异算子保持）；LLM 先验充当了一个**跨分支的隐式共享记忆**——所有分支从同一 LLM 的相似先验出发，变异供给端收敛（Verbalized Sampling −76%，arXiv:2510.01171 是其供给端上限证据），并行不干预即趋同。角色指派的本质是给每个主体**不同的先验偏置**以抵消共享 LLM 先验的均质化【推断】。
- **角色是意图层的、合并是存储层的，缺一侧另一侧失效**：EvolveNet 证据链拆开看——角色指派（G16）产生异质 delta，合并门控（M4-P16/M9）把异质 delta 变成 +9.0；无门控链式合并则全部清零倒贴。这意味着 G16 的价值兑现路径完全穿过 M4-P16：**策略侧分工的收益在存储侧合并瞬间才实现**（与 M4-P16 深挖"+9.0 合并增益归属=跨 client 机制互补重组"互为因果）。
- **成本档分工与异质角色指派是正交的两维分工**：前者按"经济性"切（谁能便宜探索），后者按"认知方向"切（谁保守谁激进）；RelayEvolve 的 call 级近视教训提示成本档分工的决策粒度同样不得低于块级（×G6）【推断】。
- **跨组织产权/联邦部署判归框架层（刚性边界）**：G16 只到角色意图编排——"给 client i 指派 adversarial_audit 角色"是 M1 意图；数据出域合规、部署拓扑不在 M1 留下任何接口（与 M4-P16 同款裁决）。

### 3. 反直觉结论

**多主体并行的最大风险不是"分支浪费预算"，而是"分支假装多样"——LLM 先验使 N 个独立分支的多样性可能低于一个分支内的采样多样性，角色指派不是优化而是多主体场景的最低合规配置。** 直觉认为并行=免费的多样性（多跑几条线总有一条中）；EvolveNet 的角色消融与 Verbalized Sampling 的 −76% 供给端证据合流说明：不加干预的并行分支在 LLM 时代会退化成"同一策略的 N 次重采样"，而重采样的信息量在供给端先验封顶下趋零。由此，"单主体"与"异质角色指派"之间没有中间档——**同质并行是比单主体更差的取值**（花 N 倍预算买 <1 倍多样性），这是本轴默认值写的"单主体"而非"同质并行"的原因。

### 4. 模块接口

- **M4-P16（★镜像刚性边界）**：合并门控与存储归 M4/M9；G16 只产出角色指派意图（走 G13 intent_queue 通道，kind=explore/exploit 按角色映射）。
- **G7**：角色分工与预算分配联合决策——异质角色的预算份额不应按回报加权（adversarial_audit 角色的"回报"以延迟的合并增益兑现，按即时回报加权必然饿死审计角色，×G18 starvation_floor 的角色级实例【推断】）。
- **M2**：角色意图落到变异方向压力（M1 定方向、M2 定算子，刚性边界不变）。
- **框架层**：跨组织产权、联邦部署拓扑归框架层（同 M4-P16 裁决）。
- **X1**：角色指派事件+角色-预算映射入谱系（合并后的"异源"谱系边须能回溯到角色标签，否则合并增益无法归因到分工【推断】）。

### 5. 证据空缺

- 角色指派的一手证据仅 EvolveNet 单系统；三种角色（repair/exploration/audit）的划分是否充分/最优无消融。
- 角色级预算分配的保底线无标定——audit 角色被饿死的效果未测【推断】。
- Red Queen 对抗角色为 workshop 级；对抗分工与互补分工的相对收益无对照。
- 成本档分工与角色分工叠加的交互（便宜模型是否该承担 audit）无任何文献。

## G17 策略输入统计量与信噪比自适应（★★★本 part 最重轴：CI/噪声底门槛协议）

> 轴定义回顾：M1 核心决策消费的输入是分数点估计还是"边际改进 CI vs 噪声底"统计量——策略强度是信噪比的函数。B 组根因 1 原话："选择（S-1）/切换（S-3）/停止（S-4）/分配（S-5）四类核心决策的默认实现全部消费分数点估计，而其失效的边界条件全部由信噪比决定……SB 的 P=0.49 与 EoH 的 5 倍效率是同一根因的两个极：策略价值 = f（信噪比），f 在低信噪比处为零、在高信噪比处巨大——**不存在无条件的策略优劣，只有条件句**。"本轴是该根因的承载轴，也是 S-B7/S-B11/S-B12 的物化位。

### 1. 取值表

### 2. CI/噪声底门槛协议（本轴核心增量：比较协议的具体化）

四类决策的门槛形式化（消费 M8 ReliabilityMeta；术语对齐 M4-P20 双资格分离与 M9 判定规则库）：

| 决策 | 点估计形态（失效） | ci_gated 形态 | 不可裁决时的默认动作 |
|---|---|---|---|
| 加强选择压力（G1/G3） | plateau 出现→压低温/提 exploit 比 | 仅当 近期边际改进 CI 下界 > noise_floor 且有效亲本数未收缩 才允许加压；**"加强选择"从默认响应降级为待证响应**（S-B11 原文） | 维持现温 + 申请重评头部候选 |
| 相位切换（G9） | 第 N 代切 / 预算比例切 | Relay Gain 边际改进 CI 上界 < noise_floor（饱和判据）才触发 handoff；CI 跨度覆盖噪声底=不可裁决 | 不切 + 继续当前相位 + 预算意图转重评账户 |
| 停止（G10） | K 代无改进即停 | CI 下界 > 噪声底时**禁止以 plateau 为由停止**（S-B7）；软停止要求 plateau 归因报告（S-B8） | 归因失败默认续跑 |
| 分配倾斜（G7） | 按近期回报加权 | arm 间差异 CI 下界 > 噪声底才允许份额倾斜超 pmin 范围；差异不可裁决时份额回归均匀 | 均匀分配 + pmin 保底 |

协议设计要点三条：
1. **比较对象不是"两个分数的 CI 重叠"而是"边际改进的 CI 与噪声底"**：噪声底（noise_floor）是 M8 侧由重评/配对差分测出的最小可裁决效应量（M9 规则 5：效应量<噪声底计零）；CI 是候选间差分的置信区间。二者单位同为分数差，比较 = `ci95_lower(Δscore) vs noise_floor`——这把"统计功效不足"从隐性假设变成显式输出值"不可裁决"。
2. **"不可裁决"是一等输出而非失败态**：SB 的 P=0.49 教训的正确消费方式不是"放弃策略"而是"报告当前配置下策略不可裁决"——该输出触发预算重评（snr_adaptive 档）或评估集扩容请求（向 M8/M3 上报），形成负反馈：信噪比越低，策略越安静，预算越流向信噪比本身。
3. **与 M4-P20 双资格分离的术语对齐**：M4-P20 把候选资格拆为"进档证据位 vs 供亲权重位"——供亲权重的错误按谱系复利。G17 是其策略侧镜像：**M1 消费的分数信号也须分用途**——"报告用分"（可为点估计，进日志）与"决策用分"（必须 CI 形态，进门槛协议），二者在类型层分离，禁止用报告分做决策【推断】。

### 3. 隐藏结构

- **SB 与 EoH 的两极同源是本轴的存在性证明**：P=0.49（低信噪比极）与 5 倍效率（高信噪比极）不是两个独立观察，而是同一函数 f（信噪比） 在定义域两端的取值——**策略价值的条件句结构被两家独立系统各自测了一个端点**。这同时给出 f 的形状先验：低信噪比处 f≈0（且方差>基线，SB 原文"策略层期望产出等于零但方差大于基线"），高信噪比处 f 巨大（5×）。f 的中间段（信噪比中等）无任何系统测过——这是本轴最大的测量空缺，也是默认 ci_gated 而非 snr_adaptive 的原因【推断】。
- **噪声底随相位移动（S-6 隐藏推断的展开）**：探索相位候选差异大、信噪比尚可；利用相位候选趋同、差分信号小、噪声占比上升——**同一策略公式在不同相位的有效性强弱反转**。这意味着：① 门槛协议的比较常数（noise_floor）必须按相位×信噪比分解维护，全局单一噪声底会在利用相位系统性低估噪声；② S-B12"按相位×信噪比分解报告"不是报告格式要求，而是**阈值本身的存储结构**要求【推断】。
- **G17 是 M1 唯一不能自救的轴**：噪声底测量归 M8（跨模块共管，S-4 原文"M1 不能独立自救"）——M1 侧的全部努力只能做到"正确消费统计量"，统计量的生产质量完全依赖 M8 的重评预算。GEPA 85–90% 预算进验证表的案例从反面说明：重评预算不足时，G17 的全部门槛退化为"恒不可裁决"——**该输出本身是正确的**（它如实报告了策略不可证伪），但对工程方是政治上有毒的【推断】。
- **Archive-Sampling 证据的准确归属**：Flageat & Cully 2023"重评优于精细选择"表面上是 M4 档案维护证据，实质是 G17 的预算转移方向证据——它测的是"同预算下，把方差缩减（重评）优先于选择精细化"的净收益，这正是 snr_adaptive 档的动作②【推断】。

### 4. 反直觉结论

**"加强选择压力"是面对 plateau 时最直觉的策略响应，而它在噪声底下恰好是把方差放大器开到最大——G17 的核心纪律是把最直觉的响应降级为最需要举证的响应。** 机制：选择压力作用于观测分数而非真值，压力越大、被选中候选中噪声贡献占比越高（winner's curse 的策略层版本）；噪声主导时 argmax 选择等价于按噪声排序——策略输出的不是最好的候选而是最 lucky 的候选，整个策略层退化为方差放大器（S-6 机制解剖原文）。反直觉点在于失效方向的隐蔽性：噪声过拟合不产生任何异常信号（被选中的 lucky 候选的分数、谱系、后代全部正常），且恰好伪装成"策略有效"（每代 best 微涨）。**因此 ci_gated 的默认不是"谨慎"而是"唯一能区分策略有效与噪声中奖的协议"**——SB 的 P=0.49 与 EoH 的 5 倍效率证明：不做这个区分，你既可能在噪声里为一个零增量策略庆功，也可能在高信噪比域因过早降压而放掉 5 倍效率。

### 5. 模块接口

- **M8（★消费，跨模块共管）**：`ReliabilityMeta{n_trials, ci95, icc, noise_floor}` 是本轴唯一合法输入源；M8M9-UNIFIED §2 已规定"≥300 有效题才报系统比较"（P=0.49 教训的类型层物化）——M1 的决策用分继承同一口径，评估集不足时门槛协议输出恒为"不可裁决"。
- **M9**：`noise_floor_zero` 规则（§3.1 规则 5）是裁决层门槛；G17 是同款门槛的策略层前移——两处阈值定义必须在类型层共享同一 noise_floor 字段，禁止各自维护【推断】。
- **G1/G3/G9/G10**：四轴动作的统计门槛全部经本轴（耦合已在轴系写明）；**G12**：退化对照的"增量超噪声底"判据即本轴协议的对照层应用（同一比较、不同对象）。
- **M4-P20**：决策用分/报告用分的类型层分离与双资格分离同构对齐（上述要点 3）。
- **M3**：snr_adaptive 档的预算转移（选→重评）以 G13 intent_queue 的 cost_account 切换执行——门槛协议的输出最终是预算科目变更意图，记账归 M3。

### 6. 证据空缺

- **f（信噪比） 的中间段完全未测**：SB（极低信噪比）与 EoH（评估精确域）是两个端点，信噪比中等的常态区间无任何系统的功效-信噪比曲线——snr_adaptive 档的自适应函数形状无标定依据。
- "噪声底随相位移动"为结构外推（B 组不确定性说明 (4) 自认）——相位×信噪比分解阈值表无任何实现先例。
- Archive-Sampling 的收益在 LLM 进化域无复现（2302.00463 为 QD 经典域）——预算转移方向的跨域有效性待证【推断】。
- "决策用分/报告用分"类型层分离无系统先例；GEPA 的 85–90% 预算分布是事后统计而非分用途记账的产物。
- 不可裁决输出的负反馈回路（→重评预算→M8 扩容）无任何系统跑通过——全链路是设计外推【推断】。

### 2. 隐藏结构

- **本轴是候选不变量 I-可逆的策略层投影（第四投影）**：M4-UNIFIED §0.0 已列三投影（M9 裁决层 Receipt 失效引擎 / M4 存储层驱逐协议 / M2 算子治理 C11 复活通道）；G18 补上**调度层投影**——相位切换、停止、饿死是"不可逆操作"在策略层的三个形态（切换=状态覆盖、停止=过程终止、饿死=预算归零），I-可逆的核心条款"不可逆性档位与所消费证据的 CI/重评状态在类型层绑定"在策略层的对应物是：**hard 类动作的合法性门槛 = G17 门槛协议输出为"可裁决且支持"**——G18 与 G17 是同一原则的两个轴面（G17 管"证据够不够"，G18 管"证据不够时动作降级成什么形态"）【推断】。
- **快照契约写死对齐 M4-P13**：snapshot_rollback 的快照不新建机制——直接复用 M4-UNIFIED §3.6 双快照（档案快照 `full_db_snapshot` + 策略环境快照），策略侧增量只有两项：①意图条目挂 `snapshot_ref`（G13 schema 已留字段）；②恢复时策略状态（bandit 统计量、相位、温度）随快照一并回滚——**RelayEvolve"初始 Grow 收益受入档顺序污染须剔除统计"的一手细节提示：回滚后 bandit 统计量若不随快照复位，恢复后的分配建立在被污染的历史上**【推断，本轴最易踩的实现陷阱】。
- **饿死的"不可逆"是渐近的而非瞬间的**：乘性权重更新的饿死是正反馈过程（S-5 机制），受害者（零预算岛/实例/谱系）不产生任何日志信号——与 E7 误杀同根，被饿死者无后续数据可平反。starvation_floor 因此不是"公平性"配置而是**可观测性配置**：pmin 保底份额的真正功能是让每个方向持续产生数据，使"它确实不行"成为可证明命题而非默认假设【推断】。
- **软停止的归因报告是 S-B8 与 G12 的汇流点**：归因类（收敛/打转/预算耗尽/噪声底）中"打转"与"收敛"的区分依赖 G17 统计量+"有效亲本数"（S-B2）——归因失败默认续跑的条款把举证责任放在停止方，与 G10 默认值联动。

### 3. 反直觉结论

**在策略层，"不可逆"的真正反义词不是"不执行"，而是"先买单后验货"——全部防塌缩结构（快照、软停止、保底份额）的共同本质是：让便宜的动作延迟到账，让昂贵的证据先行。** 直觉上可逆性是工程冗余（"多存几份快照而已"）；根因 3 揭示的是激励结构：不可逆动作（切换/终止/零预算）每一步都便宜且立即可审计，验证（重评/对照/审计）每一步都昂贵且延迟——无任何结构约束时，系统必然在证据成熟前完成不可逆动作，因为前者便宜后者贵。EvolveNet"回滚恒指向上一共享 harness"提供了更深一层反直觉：**连回滚目标都不能选"历史最优"**（历史最优分含 winner's curse 高估），可逆性设计里连"回到哪"都是统计问题而非排序问题。由此，G18 的"软"不是保守主义，而是**在证据成熟度与动作不可逆性之间做类型层绑定**——这正是 I-可逆候选不变量的定义句，G18 是该不变量被提出以来最完整的模块级展开。

### 4. 模块接口

- **M4-P13（★快照载体，刚性复用）**：双快照机制、快照间隔预算科目、断点续跑回归测试（M4-UNIFIED §3.6"续跑后前 N 候选分布应与原 run 统计不可区分"）全部复用；M1 不建第二套快照。
- **G13**：不可逆类意图（kind ∈ {handoff, spawn_island} 及停止类相位动作）强制挂 `snapshot_ref`——类型层绑定 I-可逆【推断】。
- **G17**：hard 类动作的合法性=门槛协议"可裁决且支持"；不可裁决时动作自动降级为软形态（软停止/快照+延迟/pmin 保底）。
- **G7**：starvation_floor 是分配机制的组成部分（pmin 进 bandit 的份额约束）；回滚时 bandit 统计量随快照复位（上述陷阱）。
- **G9/G10**：切换/停止动作的结构配套（快照先行、归因报告随停止事件）；**X1**：快照事件、回滚事件、饿死审计清单、归因报告全部为一等谱系事件（零预算幸存者清单常驻审计=周期性 X1 输出）。
- **M3**：快照预算、pmin 保底份额的预算占用均为一等科目（保底份额是"防塌缩保险费"，须在预算表可见否则第一个被砍【推断】）。

### 5. 证据空缺

- **pmin 的取值无任何标定**——hal-00519579 明示其为难超参但未给选择协议；饿死审计的报警阈值（连续多少块零预算触发审计）无标定。
- 策略状态随快照回滚（bandit 统计量复位）无任何系统先例——RelayEvolve 的入档污染细节是最接近的警示，但未做回滚场景。
- 软停止归因报告的分类准确性（"打转 vs 收敛"的判别力）无测量——归因类间的混淆矩阵是空白。
- 快照+回滚在相位切换场景的成本-收益（快照预算占比 vs 避免的误切换损失）无一手数字；EvolveNet 回滚是合并场景，相位切换场景的回滚演练无先例【推断】。

## Part 3 收尾：六轴横向结构

1. **G13 是其他五轴的物化底座**：G14 的版本归因靠 `policy_version`、G18 的快照绑定靠 `snapshot_ref`、G17 的 CI 口径前移靠 `expected_gain`——意图条目 schema 是六轴契约的交汇点，先建 schema 后谈机制。

3. **G17/G18 是 B 组两根因的轴面投影**：根因 1（点估计 vs 统计量）→ G17，根因 3（不可逆跑在延迟证据前）→ G18，二者的绑定关系是"证据门槛（G17）决定动作档位（G18）"——I-可逆候选不变量的定义句恰好同时是两轴的接口契约。
