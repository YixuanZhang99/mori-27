## P15 退化自检基线（档案结构复杂性的奥卡姆剃刀）

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| resident（SCS/单链表投影永驻对照） | 档案结构按"单链表 incumbent+challenger"（AIDE² 外环形态）或"SCS：每代随机 3 个前代程序拼 prompt、无 fitness 选择"（Simple Baselines 形态）做退化投影，与主档案**同预算常驻对照**；任何拓扑/前沿/驱逐结构变更（P1/P2/P10 取值变更）须跑赢投影且增量超 M8 噪声底才允许进默认配置。对应 M2-UNIFIED Layer 4 `degenerate_baseline` 调度的档案侧镜像 | Simple Baselines：~100 题验证集下 P(ShinkaEvolve>IID RS)=0.49——复杂档案结构与无档案基线在小验证集下**统计不可区分**（arXiv:2602.16805）；AIDE² 单链无档案仍达 RSI L1（weco.ai 2026-07，博客级降档，方向被 DGM §4.3 消融独立佐证）；反向证据：DGM 去 archive 消融显著退化（arXiv:2505.22954）——档案结构的价值真实存在但**以评估统计可靠性为前提** | **默认值**。它是档案模块唯一不可裁剪的常驻组件（对齐 M2 侧"IID-RS/SCS 永驻、移除=构建失败"）；任何非默认档案结构（岛、网格、Pareto 矩阵）的启用声明都隐含本对照在位 |
| none | 无对照——档案复杂性不可证伪，"结构增量"与"噪声实现"在 fitness 曲线上永远无法分离 | FunSearch/AlphaEvolve/OpenEvolve/ShinkaEvolve/GEPA 全部现状（B 组根因 2 记录：二阶指标全部缺失，退化对照更是无人做）；VRP 纯贪心 3 代塌缩（arXiv:2604.07872）证明无对照下失效路径最短 | 仅当档案退化为纯缓存（无选择压力回馈）时可豁免【推断】 |

### 2. 隐藏结构

- **P15 与 M2-O1 自检是同构不同面的两把剃刀**：M2-O1 的 IID-RS/SCS 对照对象是"算子集表达力"（变异侧），P15 对照对象是"档案结构复杂性"（状态侧）。同一套 Simple Baselines 证据被两侧各消费一次且不可互相替代——算子强而档案无结构（VRP 塌缩）、档案复杂而算子退化（SB 场景），两条失效路径需要各自的对照组才都能被抓到。
- **剃刀的生效强度由 M8 噪声底直接决定**：SB 的 P=0.49 不是"档案无用"的证明，而是"~100 题验证集下档案增量 < 噪声底"的测量——P15 对照的判定规则天然就是 M9 的 `noise_floor_zero`（效应量<噪声底计零，M8M9-UNIFIED §3.1 规则 5）。即 P15 不是独立机制，而是**把 M8 的噪声底测量周期性施加到档案结构这个"宏观候选"上**【推断：档案结构=作用域最大的候选，其评估样本=整个 run】。
- **单链投影是档案的"最差合法形态"参照**：F-B11（最小合法档案是多峰）规定档案不得低于单链；P15 的 resident 档则要求单链作为对照**永驻**——一个做下限禁令、一个做对照基准，合在一起使"档案结构"成为可证伪对象而非信仰声明。
- **实现陷阱**：退化对照与主档案共享评估预算，SCS 投影的成本在噪声大时反而可能"赢"（SB 场景），此时正确响应是**先质疑评估集规模**（M8 侧）而非砍档案结构——剃刀砍错方向的风险是真实存在的【推断】。

### 3. 反直觉结论

**档案结构的最强证据（DGM 消融显著退化）与最弱证据（SB P=0.49）指向同一个结论：档案的价值不在档案里，而在评估可靠性里。** 直觉认为"更精巧的档案=更好的搜索"；证据显示档案复杂性的全部增量可以被评估噪声完全吞没（P=0.49），也可以在评估严格时成为主要增量（DGM 消融、GEPA +6.4%）。因此 P15 的默认不是"相信档案有用"而是"**任何档案结构变更是一张必须用统计功效兑现的支票**"——resident 对照的真正功能不是防档案过度设计，而是**持续测量"当前评估配置还支撑得起多复杂的档案"**。

### 4. 与其他模块接口

- **M8（消费）**：对照的判定输入=噪声底（`ReliabilityMeta.noise_floor`）与配对差分 CI（M8M9-UNIFIED §2）；评估集规模不足时 P15 输出恒为"不可裁决"，该输出本身是一等信号。
- **M1**：对照结论是 P1/P2/P9/P10 结构变更的准入门——M1 的结构切换决策须附最近一次 P15 对照结果。
- **M3**：resident 对照占用评估预算（SCS 投影 ≈ 一个最小 run 的成本），须作为一等预算科目注册，否则对照第一个被砍【推断】。
- **M2**：与 M2-O1 自检共享退化基线实现与调度槽（`degenerate_baseline` idle op），但对照对象与报告通道独立——两模块的退化台账不合并记账。

### 5. 证据空缺

- SB 的 P=0.49 在 ~100 题验证集下测得；评估集放大后档案结构增量何时"浮现"出噪声底，无任何系统的功效-结构敏感性曲线。
- AIDE² 单链达 RSI L1 为厂商博客级证据，无同行评审；其外环评估（固定美元预算+private 分数）与 DGM 的差异未被受控分离——"档案收益依赖评估严格度"目前是双案例对照而非实验结论。
- 无任何系统**实际运行过**档案结构的退化对照（所有"对照"都是论文间事后比较）——resident 档的运行成本、报警误报率均无一手数字。

## P16 档案分布与合并协议（★重点轴：EvolveNet 展开 + 重标定呼应 M8 锚点）

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 单主体集中式 | 档案为单 run 单进程私有状态；全部经典系统默认形态 | 阴性背景：FunSearch/AlphaEvolve/OpenEvolve/ShinkaEvolve 均无跨 run 合并原语，多 run 结果只能"取各 run 最优"作报告（B 组 M4-7 案例 3） | **默认值**。单 run 短周期、评估环境唯一时无需更高档位 |
| 跨 run 事后合并（共享锚点重标定） | 合并前，各 run 候选在**共享锚点集**（F-B14，呼应 M8 系 anchor 机制）上重评，分数映射到公共尺度；合并档案中每候选标 `source_run_id`，跨 run 谱系边标"异源"；锚点记录永久保留、不参与评估器版本作废（M8M9-UNIFIED §3.2 anchor 豁免条款的直接复用） | 无直接一手系统——这是 F-B14 公理推导出的取值；间接证据：M4-7 记录"不同评估版本分数不可直接比较"（跨 run 分数差可能只是评估版本差，与 E6 共谋）；DGM archive 按 (benchmark commit, agent version) 隐式绑定、换版本旧分失效不自动作废【推断】 | 多 run 同任务、评估环境版本有漂移、想免费扩充亲本池时；**前置=P13 谱系四元组完备**（缺谱系的候选合并后无法标注异源） |
| 联邦式 delta+证据门控合并（EvolveNet 形态） | K 个数据本地 client 各自进化，回传 program delta+行为证据（非原始数据）；server 做**scope-typed 合并**：diff → 机制分解 → scope 分类（全局/域条件化）→ 条件化组合 → **逐 item 证据准入门** → 失败整体回滚。合并本身成为元算子（程序不可平均，合并是非算术的） | EvolveNet（arXiv:2608.04968）：BIRD held-out **70.7% vs 等总预算集中式 67.3%**（配对 14 胜 9 负）vs 等串行深度 68.7%；DS-1000 合并 harness 比最强单 client **高 9.0 分**；合并协议消融（Delegation / GLOBAL-only / select-best）各自证明贡献；**无门控的链式合并版本直接崩溃回滚**；五 benchmark 全显著（McNemar/Wilcoxon，Holm 校正后成立）；换整套模型栈（deepseek-v4-flash→MiMo-V2.5）定性行为复现 | 多部署点数据不可出域、且每点有独立进化预算时；**前置=M9 逐 item 门在位**（无门控链式合并崩溃是 EvolveNet 自己的反面消融）；跨组织产权/部署拓扑归框架层（刚性边界），M4 只到合并协议与 scope 语义 |
| 对抗式 champion 交换（Red Queen QD） | 跨节点 gossip 传的不是解而是**对手**（champion 程序），档案内实例化军备竞赛压力；异构 LLM（Codex/Claude/Gemini/Qwen）互为多样性算子 | 分布式 Red Queen QD（arXiv:2605.27130，Core War testbed）：hall-of-fame 跨节点共享、MAP-Elites 内 Red Queen 压力；workshop/扩展摘要级，具体数字【未复核】 | 对抗/红队任务（解的适应度依赖对手分布）；单系统证据，置信降档 |
| test-time 瞬时档案（TTHE） | 档案生命周期短至一次评估：评估内从零构建，gold 对 proposer/judge 隐藏，准入只靠当前无标签 batch 的执行代理信号 | TTHE（arXiv:2607.08124）单点【未复核】；无第二家复现（C 组阴性发现 5） | 测试时搜索/无标签场景；**准入语义归 M9**（裁决同 M2 对 C6 的处置），M4 侧只剩"短生命周期"这一分布形态 |

### 2. 隐藏结构

- **合并是非算术操作，这是整个轴的存在理由**：权重可以平均、程序不能——合并语义必然包含"机制分解→scope 分类→条件化组合"的 LLM-merger 环节（EvolveNet）或"锚点重标定"的校准环节（F-B14），两者共同把"档案合并"从工程运维升级为**有失败模式的算法操作**。无门控链式合并"直接崩溃回滚"证明：合并错误的代价不是次优而是灾难。
- **+9.0 合并增益的归属【推断】**：DS-1000 上合并 harness 超最强单 client 9.0 分，意味着合并收益不是"集成分摊方差"（集中式等预算已控制该效应，70.7 vs 67.3 才是净拓扑收益）而是**跨 client 的机制互补重组**——与 HarnessBank 跨 WHERE×WHY 坐标重组 +13.9%（M2 侧证据）同构：多样性在 client 间积累、价值在合并瞬间兑现。P16 因此与 P9（多样性承载）在分布层面重连通。
- **重标定义务 = M8 锚点不变量在档案侧的实例化**：F-B14 的共享锚点集与 M8M9-UNIFIED 的"不可进化评估锚点"（B9/I-α）是同一枚硬币——锚点集是合并时唯一不可被任何 run 的优化压力触及的公共参照。Receipt 的 `evaluator_version` epoch 边界批量失效条款（§3.2 条件④）在合并场景的对应物是：**跨评估版本的候选分数默认作废、锚点重评分默认保留**。
- **谱系新边型"异源"是 X1 的 schema 扩展**：跨 run 谱系边与 crossover 多父边不同——它跨 run id、跨评估环境版本、可能跨主体。合并档案伪装成单谱系是 M4-7 的失效配置，"异源"标记必须在类型层强制（缺 `source_run_id` 的合并产物拒绝入库）。
- **实现陷阱**：EvolveNet 的逐 item 准入门消费 per-item 二值证据（M8M9 `ItemResult.verdict` 形态），跨 run 合并若只有聚合分（旧 run 的遗留记录），合并门退化为分数比较——旧档案的"分数遗产"必须先补 per-item 重评或整体降级为锚点重标定档【推断】。

### 3. 反直觉结论

**分布式拓扑的净收益（70.7 vs 67.3）小于合并协议的净收益（+9.0），而无协议合并的收益是负无穷（崩溃回滚）——档案分布化的价值几乎全部住在合并环节而非分布本身。** 直觉认为联邦/多 run 的收益来自"并行探索更多区域"；EvolveNet 的三组对照（等总预算集中式 / 等串行深度 / 无门控链式）拆开显示：并行探索只值 +2.0（70.7 vs 68.7 等串行），而合并机制值 +9.0，缺门控则全部清零倒贴。由此推出设计优先级：**先建合并门与重标定，再谈分布拓扑**——这与"先分布、后补协议"的工程直觉恰好相反。同时，**跨 run 合并通用协议/标准格式不存在**（C 组阴性发现 1，EvolveNet 是唯一一手系统且其合并是任务特定 LLM-merger）——阴性发现即设计机会：M4 把"合并协议+异源谱系边"做成一等接口，恰好填补文献空位，但默认值仍须保持保守（集中式），因为协议证据只有单点。

### 4. 与其他模块接口

- **M9（★刚性边界）**：合并时的逐 item 准入门、scope 裁决、无门控禁止合并，判定逻辑全部归 M9（M8M9-UNIFIED `decision_rule` 封闭枚举消费 `ItemResult`）；M4 只执行存储侧后果（入库/回滚/scope 标注）。
- **M8**：合并门的证据输入=per-item EvalResult；锚点重标定消费 M8 anchor 机制与 `noise_floor`（跨 run 分数差<噪声底时合并排序不可裁决）。
- **X1（★一等输出）**：合并事件、来源 run id、"异源"谱系边、合并门版本，全部为一等谱系事件；M4-7 证明谱系是唯一使合并后污染可召回的结构。
- **P13**：合并前快照对齐（合并失败整体回滚依赖可恢复快照）；**P10**：合并前须先过驱逐可证伪性（被硬删除的候选无法参与合并审计）。
- **框架层**：跨组织产权、数据出域合规、联邦部署拓扑判归框架层（M2 对 C4 的同款裁决），M4 不留部署接口。

### 5. 证据空缺

- EvolveNet 是分布合并档的**唯一一手系统**；scope-typed 语义、merge 门阈值、回滚粒度均无第二实现可对照（C 组阴性发现 1 原话）。
- "跨 run 事后合并重标定"档无任何实现先例——共享锚点集的大小、重评预算占比、标定漂移容忍度全部无标定。
- Red Queen 对抗交换为 workshop 级证据；异构 LLM 互为多样性算子的收益未量化分离（LLM 差异 vs 拓扑差异混杂）。
- 合并事件与 P20 资格位的交互（被污染 run 的候选合并进来后如何传染目标档案）无任何文献触及——与 F-B3 召回联动的"跨 run 召回"是纯设计外推【推断】。

## P17 档案移交与估值（档案作为跨相位资产）

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 无移交（单模型单相位） | 档案随 run 生灭，不打包不估值 | 经典默认：FunSearch/AlphaEvolve/OpenEvolve/GEPA 全部如此；阴性发现：进化系"跨代语义抽象普遍缺失"（A 组 §2.5） | **默认值**。单模型单预算场景 |
| 固定切换 | 到点（代际边界/预算耗尽）档案整体移交下一阶段；无估值、无压缩 | 无一手量化；工程惯例（多阶段 pipeline 的 checkpoint 接力）【推断】 | 移交带宽不紧张、相位边界已知时 |
| 子模目标估值+自适应 handoff（RelayEvolve 形态） | 维护在线 relay bank（|S|≤k）：以 **top-r 质量+多样性覆盖的单调子模目标** F 选移交子集（贪心+局部交换，(1−1/e) 近似保证）；**Relay Gain**=bank 的边际改进，同时驱动 bandit 调度、handoff 时机与种子集选择——移交集本身是优化目标 | RelayEvolve（arXiv:2608.05651）：4 benchmark×3 预算中 **11/12 设置均值最高**；一手规律"进展强前置"——便宜模型前 20 代捕获强模型 **0.82–1.01×** 的进展；call 级 bandit 路由被证明近视（"逐 call 路由是错的问题"，LLM 调用状态耦合） | 多模型档位接力（弱模型探索→强模型精化）、移交带宽受限（k 上限=移交预算）时；**前置=移交集可快照（P13）且携带 P18 语义字段**（无 plan/summary 的移交集对接收方不可读【推断】） |

### 2. 隐藏结构

- **估值对象从"个体分数"变为"子集组合价值"**：子模目标 F 的两个成分（质量、覆盖）分别对应档案的 exploit/explore 资产——移交估值是**把 P2 前沿定义做一次组合优化**（top-r 质量≈cell_elite 视角，多样性覆盖≈grid 覆盖视角）【推断】。k 受限使"选谁移交"成为非平凡决策；无 k 约束时子模档退化为整体移交。
- **Relay Gain 的三重消费是档案侧信号反哺调度的先例**：bank 边际改进同时喂 bandit 调度（M1）、handoff 时机（M1 相位决策）、种子集选择（M2 亲本供给）——档案第一次在证据上成为**调度信号的生产者**而不只是被动存储。
- **"进展强前置"（0.82–1.01×）是本轴最具迁移性的一手规律**：它给出 handoff 时机的定量锚——弱模型在 ~20 代内完成强模型 82–101% 的进展，之后继续烧弱模型预算的边际价值骤降。该数字同时是 M2-O19 算子经济学（相位/代为决策单位，非逐 call）在档案侧的对应物。
- **实现陷阱**：relay bank 与主档案的关系未在原文明确【推断：bank 是主档案的在线压缩投影】；若两者各自维护，主档案的驱逐事件（P10）与 bank 成员资格可能不一致——移交集的可证伪性要求 bank 成员也过 P20 证据资格审查。

### 3. 反直觉结论

**"什么时候换强模型"这个看起来是调度问题的决策，其最优信号源是档案而非预算曲线。** 直觉用预算比例（烧完 30% 换档）或 wall-clock 定 handoff；RelayEvolve 证明正确信号是 relay bank 的**边际改进**（档案状态函数）——档案估值曲线比成本曲线更早、更准地宣告相位终结。同时"call 级 bandit 近视"意味着：在档案粒度之下（逐调用）做模型路由是对错问题的最优解——**决策粒度必须抬到移交集级别**，这对所有想加"便宜模型先试、贵了再升级"机制的框架是硬性约束。

### 4. 与其他模块接口

- **M1（★）**：handoff 时机是搜索相位决策，归 M1 消费；M4 只暴露 Relay Gain 时序与移交集构造器。
- **M3**：移交预算（k、压缩率、目标档位成本结构）注册进 M3；移交本身的 token/带宽成本是 C5 横切约束的直接落点。
- **P13**：移交集必须可快照、可恢复（含谱系四元组，F-B13）——移交是跨相位谱系延续，谱系断裂的移交等于重新冷启动。
- **M2-O19**：RelayEvolve 证据在 M2 侧已入算子经济学（决策单位=相位/代）；本轴管档案侧的打包与估值，两侧共享 Relay Gain 信号但分别记账。
- **P20**：移交集成员须持交付资格（证据位），仅分数位者不得进 bank【推断：移交=交付的预备态】。

### 5. 证据空缺

- RelayEvolve 为单系统证据；11/12 设置最优的例外（1/12）未被原文归因；"0.82–1.01×"的跨任务方差未报告。
- 子模目标中质量与覆盖的相对权重、top-r 的 r 选择无消融【推断】。
- 移交集在接收方（强模型）手中的"可读性"（语义字段是否被消费、消费增量多少）无任何测量——移交的内容表示需求（×P18）是设计外推。

### 2. 探针族设计与框架对齐（本轴核心增量）

**与 M2-O9 DiversityProbe 的类型级对齐**（M2-UNIFIED §2 一手）：

```python
# M2 侧既有类型（M2-UNIFIED-v1.md L153-161）
class DiversityProbe:
    generation: int
    metric: Literal["exact_match_template", "behavioral_proxy"]  # 嵌入指标禁用
    value: float
    alarm: bool = False          # 超报警阈值；报警→父代/算子切换记录须入 X1
    prior_ceiling: Optional[float] = None  # C2：LLM 原生采样多样性实测上限

# P19 档案侧探针族的同构扩展（本深挖的建议物化【推断】）
class ArchiveHealthProbe:
    probe_kind: Literal["supply_entropy", "cross_island_distance",
                        "instance_discriminability", "reeval_survival"]
    generation: int
    value: float                 # 或分布摘要（探针③为分布）
    alarm: bool = False          # 报警→治理动作/配置切换记录须入 X1（同 O9 契约）

```

对齐要点四条：

1. **度量保守性继承**：DiversityProbe 禁用嵌入指标（arXiv:2508.13333 证明嵌入混淆 dynamic/static 多样性）——P19 探针②（跨岛距离）继承同一禁令：跨岛距离默认用 exact_match_template / behavioral_proxy 口径，嵌入距离仅作诊断不作报警依据（M4-4"为什么难防"节明示"嵌入式多样性指标混淆逻辑差异"是同根风险）。
2. **消费 M8 ReliabilityMeta**：探针③④的原始输入是 per-instance 分数矩阵与重评记录，其统计合法性依赖 `ReliabilityMeta{n_trials, ci95, icc, noise_floor}`（M8M9-UNIFIED §2 L86-90）——重评存活率的"存活"判定必须用 noise_floor 规则（效应量<噪声底计零），否则探针④本身成为噪声消费者。GEPA 85–90% 预算案例说明探针③的成本必须显式定价注册 M3（对齐 eval tax 范式）。
3. **报警即谱系事件**：O9 契约"报警→父代/算子切换记录须入 X1"原样继承——探针读数跨代时序+报警触发的治理动作全部入 X1，使 P19 成为跨代可审计的治理档案（轴系总览表："探针读数进 X1 谱系"）。
4. **与 M9 gate_quality_probe 的制度同构**：M9 侧"每个否决门强制伴生 gate_quality_probe（定期测 FP/FN）；无探针的门不得行使否决权只许打标签"（M8M9-UNIFIED 分歧 5 硬编码）——P19 探针反馈治理档应继承同款保守纪律：**无校准数据的探针不得自动触发治理动作，只许报警**（治理档的启用前置即仪表盘档的误报率先被测量）【推断】。

### 3. 隐藏结构

- **四个探针看管四种失效，且互不代偿**：供给熵看管 M4-1（输入端浓度）、跨岛距离看管 M4-4（拓扑失效）、实例判别力看管 M4-5（前沿表示失效）、重评存活率看管 M4-8（证据失效）——与 O17 四件套"缺一即有已知攻击路径"同构。任一探针可省的形式化条件不存在；只存在"该探针消费的结构未启用"的豁免（如无岛拓扑时探针②豁免）。
- **探针是治理轴的传感层，治理轴是探针的执行层**：P3（岛数）/P4（迁移）/P8（供给函数）/P10（驱逐）的全部"动态化"取值（动态繁殖、阶段感知迁移、供给函数热替换）都以探针读数为触发器——没有 P19，这些轴的动态档是盲的；没有这些轴，P19 的报警无处可去。这是轴系内最密的一组耦合（×4）。
- **探针自身的成本是档案经济学（C5）的一部分**：探针③④需要重评预算（Archive-Sampling/EME 式周期重评是线性成本，M4-8 原文），探针①②近零成本（日志重放）——成本梯度给出一个自然的启用顺序：①②常驻、③按实例表规模配预算、④按重评预算档位启用【推断】。
- **与 M2-O20 的输入/输出分工**：O20 重复率台账看管变异器**输出端**（近重复率、闸拒绝率——"拒绝率飙升=多样性塌缩先行指标"，M2-UNIFIED §3.3），P19 探针①看管档案**供给端**浓度——同一塌缩过程的两端读数，双读数交叉验证可避免单端误判（如闸阈值过紧造成的假塌缩信号）【推断】。

### 4. 反直觉结论

**档案塌缩从来不是不可观测的，只是从来没人把观测做成一等输出——四大系统（FunSearch/AlphaEvolve/OpenEvolve/ShinkaEvolve）fitness 曲线齐全而二阶读数全零，是仪表缺失而非现象隐蔽。** 直觉把"塌缩隐形"归因于塌缩本身的统计性质（"任何单条候选的 fitness 都看不出问题"）；但 VRP 案例里连 LLM 自己都能在第 3 代自诊断出"selecting exclusively from the top cost stratum"——现象在数据里明明白白，缺的是常驻的仪表盘与报警纪律。由此推出本轴的制度核心：**探针缺失应视同塌缩已发生**（M2-C1"无探针的循环默认视为已塌缩"的档案侧直译）——健康不可观测与已知不健康，在治理上等价。这也解释了为什么探针族中看起来最"奢侈"的重评存活率（要花真预算重评精英）恰恰是优先级最高的一档候选：Justesen 与 Grillotti 的一手测量都指向"档案顶端有相当比例经不起重评"——不量它，档案的可信度本身未知。

### 5. 与其他模块接口

- **M8（消费）**：噪声底、CI、ICC 是探针③④的判定合法性来源；探针的重评请求走 M8 级联调度（注册预算档位，eval tax 范式）。
- **X1（★一等输出）**：探针读数跨代时序、报警事件、触发的治理动作与结果，全部入谱系——P19 是 M4 对 X1 的最大写入方之一。
- **M1**：探针报警是 M1 切换父代公式/相位决策的触发信号（对齐 M2"O9 报警是 M1 切换父代公式的触发信号"的同构条款）。
- **M3**：探针③④的重评预算是显式定价科目；探针成本与档案维护成本共享一条预算曲线。
- **P3/P4/P8/P10**：四轴动态档的触发器（见隐藏结构）；**P15**：退化对照结果是"档案结构级"的第五个探针读数【推断】。
- **M9**：探针触发的治理动作若改变候选存活状态（驱逐冻结、资格降级），须经 M9 裁决通道而非 M4 自执行（双资格分离的边界，见 P20）。

### 6. 证据空缺

- **全部四个探针无一度量实现先例**：供给熵的"有效熵"定义（基因型/表型口径）、跨岛表型距离的度量选择、实例判别力的量化式、重评存活率的周期与样本量——全部无标定证据，阈值是公理推导的占位符（与 M2 边界声明 5"阈值类参数全线无标定"同源）。
- 探针→治理动作的**闭环**无任何一手系统跑通过（ShinkaEvolve 动态岛繁殖是唯一单指标单动作先例）——反馈治理档的稳定性（振荡风险、过度反应）完全未验证【推断】。
- 探针读数与最终性能的预测效度（探针报警后多久 fitness 可见恶化）无任何时序相关性研究——报警的提前量未知，治理窗口大小无法定。
- 嵌入禁令（继承自 O9）使探针②在高维语义任务上的灵敏度存疑：exact_match/behavioral proxy 对"策略趋同但代码字面不同"的岛间趋同可能漏报【推断】。

## P20 双资格分离（★重点轴："进档靠分数、供亲/交付靠证据"与 M9 Verdict/Receipt 的接口）

> B 组根因 1 原话："档案是'幸存者偏差的制度化装置'……M4 的一等公理：**进入档案靠分数，供亲与交付靠证据**——两个资格必须分离。"本轴是 M4-2（hacking 放大）与 M4-8（噪声滞留）的共同对策。

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 合一（分数即一切资格） | 分数同时决定入库、亲本权重、交付选择；高分解锁全部资格 | 失效配置的一手后果：RHB 实测 RL 模型 13.9% hacking 率（arXiv:2605.02964）→"最假的分数坐最重的亲本席位"（亲本权重反比于名次，B 组 M4-2）；Countdown-Code：1% 污染祖源点燃灾难性作弊（Khalifa 2026，转引 arXiv:2605.21384）——小比例污染祖源放大为种群级失效；Justesen 2019 重评后空格——按分数交付的精英经不起重测 | 永不合法作默认（M4-2/M4-8 的直接失效配置） |
| 供亲位分离（默认档） | 候选携带两个布尔位：`archived`（分数门槛过即可留档，保留信息）与 `parent_eligible`（须过污染探针+置信门槛才置位）；被标记者字段在位但供亲位关闭（F-B4："分数与亲本权重解耦——被污染探针标记的候选可留在档案但被剥夺供亲资格"）；谱系四元组不全者"可留档不供亲"（F-B13） | 正面先例：DGM 刻意冻结 archive/父选择机制且父代选择∝分数×(1+子代数)（§C.2）——供亲权本就独立于分数存在过，只是未与污染探针联动；反面计量：RHB 13.9% 为档案侧感染率上限，供亲位分离把感染半径从"整个子种群"压回"单点档案条目" | **默认值（最低档必配）**。任何有变异器消费的档案都须开——供亲是污染扩散的唯一通道（M4-2 机制解剖），关掉它污染的复利化即停止 |
| +交付位分离 | 第三个位 `deliver_eligible`：最终交付/移交候选须满足**保守晋升**（F-B15：CI 下界高于被替代者的点估计）且驱逐/保留决策不得低于联合噪声底裁决（F-B16）；交付位消费完整证据链（Verdict/Receipt） | Justesen 2019 矫正重评后"sometimes leaves cells empty"（GECCO）；Grillotti & Cully 2023（GECCO）：档案精英重测显著低于记录值——**按点估计交付=按高估交付**是 QD 文献的一手结论；UQD（arXiv:2302.00463）：Archive-Sampling 显著优于固定采样（"不重评"是失效配置） | 存在下游部署/移交（P17 移交集=交付预备态）时必开；前置=M8 侧 CI 与噪声底测量在位（ReliabilityMeta 字段非空） |

### 2. 与 M9 Verdict/Receipt 的接口（本轴核心增量）

双资格的**判定逻辑归 M9、存储与执行归 M4**（刚性边界），类型级挂接如下：

```python
# M4 档案条目侧（本轴新增字段，默认值全 False=最保守）
class QualificationBits:
    archived: bool = True                 # 分数门槛（宽门，M9 漏斗"入库宽"档）
    parent_eligible: bool = False         # 供亲位：须持有效 Receipt（见下）
    deliver_eligible: bool = False        # 交付位：保守晋升裁决通过
    disqualify_reason: Optional[str] = None   # 剥夺理由（可证伪，对齐 M9 rationale_ref/B8）
    reliability_snapshot: ReliabilityMeta = ...  # {n_trials, ci95, noise_floor} 一等字段（F-B15）

# 资格位与 M9 Receipt 的绑定关系（M8M9-UNIFIED §2 一手类型）
# parent_eligible := ∃ Receipt(verdict.kind==ACCEPT, scope∈{global,home,cell},
#                              未触发失效条件①-⑤)
# deliver_eligible := Receipt 且 reliability.ci95.lower > incumbent.point_estimate（保守晋升）
```

接口要点四条：

1. **资格位是 Receipt 的物化指针，不是 M4 自判结果**：M9 的 Receipt 三绑（`head_sha/base_sha/gate_graph_version`+`evaluator_version`，§3.2 失效条件①-⑤）直接给资格位提供**自动失效语义**——评估器版本 epoch 边界 Receipt 批量失效 ⇒ 对应候选 `parent_eligible` 位自动复位待重估。M4 不需要实现自己的失效逻辑，只消费 M9 的票据状态机。【设计决定】
2. **置信度一等字段（F-B15）= ReliabilityMeta 的档案侧快照**：`{评估次数, 分数 CI, 最后重评时间}` 直接映射 `ReliabilityMeta{n_trials, ci95, noise_floor}`+重评时间戳；保守晋升规则（CI 下界>被替代者点估计）是 M9 `noise_floor_zero` 规则（效应量<噪声底计零）在交付场景的加强版。
3. **资格剥夺须举证**：`disqualify_reason` 对齐 M9 公理 B8（否决须附结构化可证伪理由，`Verdict.rationale_ref`）——供亲位剥夺不是静音过滤（AIDE `is_buggy` 式自判硬过滤是反例，M4-3 案例 3），剥夺事件本身入 X1 可被事后审计与平反。
4. **噪声底下不裁决（F-B16）的执行形态**：驱逐/保留的分数差 < 联合噪声底时，资格位**冻结不变**并触发重评请求（走 M8 级联），而非按点估计静默翻转——这把 M4-8"驱逐与噪声底互相劫持"的双层随机问题转化为确定性的"不可裁决→延迟"规则。

### 3. 隐藏结构

- **三资格位对应 M9 的严格度三元组**：M9 分歧 5 裁决"漏斗分层：入库宽、谱系相对、合并/部署严"——`archived/parent_eligible/deliver_eligible` 恰是这三个档位的档案侧载体。双资格分离不是发明新结构，而是**把 M9 已有的严格度漏斗钉进 M4 的数据结构**（没有资格位的档案，严格度分层只停留在门侧、进不了亲本池）。
- **供亲位是 P7 亲本池契约的新增布尔位**：P7 四固定字段（island_id/children_count/rarity/per_instance_best）写死对齐 M2-O11；`parent_eligible` 是**第五个字段且为过滤位**——M1 的采样公式永远看不到 `parent_eligible=false` 的候选（类型层过滤，不是权重归零）。权重归零仍可被调参复活，类型层过滤不可【推断：对齐 M2/M9 的"类型层白/黑名单不可配置关闭"先例】。
- **祖源级召回（F-B3）是资格位的批量操作**：污染判定后，受影响谱系的枚举/降级 = 对谱系子树批量复位 `parent_eligible`——依赖 X1 谱系四元组（F-B13）完备。1% 污染点燃灾难性作弊（Countdown-Code）说明召回延迟的代价是复利的：资格位+谱系召回的共同目标是把"单点作弊的成本=1 个假分数"从结构上固定住，不让它变成"1 个被污染的子种群"。
- **交付位与 P17 移交的合流【推断】**：relay bank 成员资格应要求 `deliver_eligible`——移交是交付的预备态；无交付位的移交集会把噪声高分直接快递给下一阶段（移交放大效应）。
- **实现陷阱**：资格位复位后的"平反"路径必须存在（重评通过→位恢复且事件留痕），否则资格分离退化为另一种 is_buggy 式永久误杀；平反率本身应进 P19 仪表盘【推断】。

### 4. 反直觉结论

**把 hacked/噪声高分留在档案里但剥夺供亲权，比把它们删了更安全。** 直觉上污染候选应该清除（删除=干净）；证据与机制都指向相反：删除丢失信息（失败模式的诊断价值、审计的物证、谱系的连续性），且删除本身是不可逆操作（M4-3 驱逐误杀）；而污染的**危害通道不是存在而是供亲**——hacked 候选只有被当亲本才会扩散（M4-2 机制解剖）。资格分离因此是"限制传播半径"（B 组根因 4 模块定位公理）的最小充分手术：不切组织、只断血管。同理，交付位的保守晋升（CI 下界>点估计）看起来"浪费"了统计功效，但 Justesen/Grillotti 的重评证据表明档案顶端的点估计系统性偏高——**保守晋升不是牺牲了真精英，而是拒绝为幸存者偏差付款**。

### 5. 与其他模块接口

- **M9（★刚性边界）**：资格的判定规则（污染探针、保守晋升、噪声底裁决）全部归 M9 的 `decision_rule` 封闭枚举；M4 只存位、执行过滤、上报事件。资格位翻转=Receipt 状态变化的投影，M4 无独立裁决权。
- **M8（消费）**：`ReliabilityMeta`（CI/噪声底）是交付位的输入；重评请求走 M8 调度。
- **P7**：`parent_eligible` 作为亲本池契约第五字段（类型层过滤位）。
- **X1（★）**：资格翻转事件、剥夺理由、祖源级召回的谱系枚举结果全部入谱系；召回操作本身依赖谱系四元组（F-B13）。
- **P10**：驱逐/保留不得低于噪声底裁决（F-B16）——驱逐执行前查资格位快照；**P17**：移交集要求交付位。
- **M1**：采样分布天然不见被剥夺供亲位者（过滤在 M4 完成，M1 无需感知）。

### 6. 证据空缺

- 污染探针的检出率上限（E1：GPT-5.2 只检出 63%）意味着供亲位分离只能按漏检率压缩感染半径，**残余污染的谱系扩散速率无量化模型**——"1% 点燃"的剂量-效应曲线在档案侧无对应测量。
- 保守晋升（CI 下界>点估计）的交付**假阴率**（真精英被拒的代价）无任何一手测量；QD 文献只有"点估计交付=高估"方向证据，无反向代价对照。
- RHB 13.9% 是 RL 模型生成侧 hacking 率，作为档案侧感染率上限是推断【原文明标】——档案侧实测感染率无任何系统报告。
- 资格位与 Receipt 失效条件的绑定（评估器版本变更→供亲位批量复位）的**级联成本**（一次 epoch 边界复位多少亲本池、恢复多慢）无运行数据【推断】。
