## N1 预算币种族与汇率表

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 单币种（token 或 usd 或 eval_count 或 node 或 wallclock） | 全账本一种单位，折算在配置层隐式发生 | FunSearch=墙钟 4h/轮+样本数上限（Nature 2024）；AIDE=节点数上限+调试节点单独上限 10 节点/12h；AIRA-dojo=remaining_time 一等参数；MEMOIR 协议=评估次数 B=16、<$1/run | 原型期、供应商与模型档永不变、无跨 run 对照需求时 |
| usd+token 双账户 | 美元记钱、token 记物理量，两条平行账 | promptolution 惯例 1M token/<$0.15 混用（m2/groupC）——双币种并存已是生态事实，只是未制度化 | 单一供应商但需跨模型档比较时 |
| **多币种账户族 + 显式汇率表（默认）** | `BudgetAccount{unit, ceiling, spent, reserved}`×5 单位；跨币种只在显式汇率层折算，账本内不混记 | 五单位并存的一手枚举（GA 卡片 1）；单系统常同时设两种以上（FunSearch=墙钟+样本；AIDE=节点+墙钟） | 换供应商/换模型档/跨期对照——即一切严肃 run |

### 2. 隐藏结构

- **"预算单位"表面是记账选择，实质是控制环路的被控变量声明**（GB B-B7）：配额以调用数计而实际消耗以 token 计，硬上限就在错误的维度上收紧——aider 重试率 15–28% 意味着"1000 次调用配额"对应 token 量的波动区间是 ±28%。选币种=选控制精度。
- **汇率表是框架内唯一无人拥有的公共品**（GA 前沿空位 3）：eval↔token↔usd 的折算全由手工配置文件承担，无版本化先例。汇率表与 N14 的版本戳合流后才成为"可审计的测量仪器"而非"某次部署的随手常数"。
- 墙钟是唯一不可囤、不可转移的币种——其余币种都可跨科目转账（N8），墙钟到期即蒸发；这使 wallclock 账户天然需要独立的 ttl 语义【推断】。

### 3. 反直觉结论

**更多币种不是记账复杂化，而是防失真的唯一手段——单币种账户的"简洁"是把汇率风险静默转嫁给所有跨期结论**。直觉上 usd 是天然统一货币；但 LLM API 2024–2026 多次数量级调价，"去年 $100 的搜索"与"今年 $100 的搜索"对应完全不同的搜索深度（GB B-4）。正确的问题不是"用哪种钱记"，而是"哪个量不漂"——答案是物理量（token/调用数/墙钟），美元反而只是汇率层的一种折算视图。

### 4. 模块接口

- **←M2-O19 op tax / ←M8M9 eval-tax**：价目表来源；M3 只消费不制定。
- **→N14**：汇率表本身版本化，跨期对照以标准币为锚。
- **→M1**：intent 的 budget_estimate 须声明币种（AllocationIntent 未含 unit 字段——**接口缺口**，见证据空缺）。

### 5. 证据空缺

- AllocationIntent 类型（M1 §2）无 budget unit 字段，多币种 intent 的契约形状未定【接口缺口，须与 M1 对齐补字段】。
- 五币种并存的运行系统实例为零（各系统均 1–2 种），多币种账户族是空位设计，无运行期教训可引。

## N2 记账粒度层级

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| per-call | 每次 LLM 调用一条记录；原子防漏，但聚合意义弱 | 同一编码任务跨 run token 方差 30×（arXiv:2604.22750）；精度相近 agent 间成本方差 50×（arXiv:2511.14136）——per-call 均值无管理意义 | 仅作最底层原子记录，永不作报表粒度 |
| per-node / per-call-group | 算子调用内聚成组；嵌套算子拆成内部调用序列上报 | M2-O20 sub_funnels：不拆则预算失控不可诊断 | 算子归因、M2 漏斗核算的喂数粒度 |
| **三级键 (account, block_id, op_kind×model_tier)（默认）** | call→op→block 三层：call 防漏、op 归因、block 决策 | RelayEvolve：逐 call 路由是错的问题，正确决策单位是 population 整代（GA 卡片 2） | 标准场景默认；向 M1 回流只在 block 层 |

### 2. 隐藏结构

- **三层粒度对应三种不同的消费者**：call 层消费者是台账完整性校验（防漏记）；op 层消费者是 M2（算子产率/漏斗）；block 层消费者是 M1（下一代分配）。混用粒度=给消费者喂错信号——M1 消费 call 级信号等于把 30–50× 方差的噪声喂进乘性权重更新（GB B-7b：S-5 饿死被成本噪声放大）。
- **嵌套算子是粒度体系的应力测试**（GB B-2）：M2-O16 嵌套透明性使"一次算子调用"的内部展开不可计；B-B3 要求沿调用链上卷实际消耗，无上卷能力的调用按成本上界预扣（先扣押金后结算）——这把 N2 与 N5 焊在一起。
- 实现陷阱：三级键中 op_kind×model_tier 的 tier 维度来自 M2 模型档（o3 vs o3-mini vs Flash），tier 定义变更须触发台账口径版本变更（×N14）。

### 3. 反直觉结论

**记账越细越好是错的——细粒度数据若被直接用于决策，反而比粗粒度更有害**。per-call 数据在高方差（30×）环境下的均值是数学上存在但管理上无义的量；RelayEvolve 证明连"正确决策单位"都在代级。记账层必须全粒度保留（防漏、防 B-2 隐形），但暴露给决策层的粒度必须经块级聚合降噪——"记全、看粗"。

### 4. 模块接口

- **→M2-O20**：op 层喂算子漏斗核算；嵌套上卷协议（B-B3）须与 M2-O16 算子签名共同定义。
- **→M1**：block 级回流（×N3），对齐 block_id。
- **→N11**：三级键是 admitted_per_usd 按算子/相位归因的前提。

### 5. 证据空缺

- 嵌套算子的成本上卷无任何系统实现先例（GA/GB 均无），B-B3 的"按上界预扣"只有 agentgateway 的单层类比，嵌套深度>1 时的押金递归规则无证据。
- 30×/50× 方差数字来自单任务研究，跨任务族的方差分布未知。

## N3 决策粒度

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| per-call | 逐调用裁决/回流 | RelayEvolve Fixed-switch 全败于阶段自适应（arXiv:2608.05651）——连相位级都比固定细粒度好 | 永不作回流粒度 |
| **per-block / per-generation（默认）** | 块级裁决、块级回流；块内额度由 intent 的 budget_estimate 一次性承诺 | M1 契约 ttl_blocks=1（intent 即一块）；BAVT 固定轮数上限省 68% 成本且 solve rate 几乎不掉甚至因聚焦而升（arXiv:2510.16786） | 标准场景；h~10 代一块的假设下块与代近似对齐 |

### 2. 隐藏结构

- **决策粒度=信号语义的容器**：M1 的 intent 是前瞻承诺（份额+expected_gain 带 CI），只有块级结算才能把"承诺 vs 兑现"放进同一会计期间——这正是 B-B14 对账闭环的最小可行粒度。粒度小于块则承诺未兑现即被结算（误报），大于块则对账滞后（ttl 已过期）。
- **块级配额是可校准旋钮**（BAVT）：固定轮数上限经良好校准可省 68%——意味着"每块几轮"存在可离线标定的合理区间，与 TALE 合理预算区间（N5）同构【推断：校准协议本身待建】。
- 易腐性耦合：ttl_blocks=1 使块级决策天然带"过期清理"义务（×N9），跨块意图须显式续约。

### 3. 反直觉结论

**给 agent 更细的自主调度权（per-call 灵活路由）反而更差，给死一个块级预算框反而更省甚至更好**。BAVT 的"固定轮数上限不掉 solve rate 甚至提升"与 RelayEvolve 的"固定时刻表全败"看似矛盾，合读得：失效的是"固定**时刻表**"（与相位解耦），有效的是"固定**块内额度**"（与任务结构对齐）——决策粒度要对齐搜索的语义结构（块/代），而非对齐时间或调用计数。

### 4. 模块接口

- **⇄M1**：块级回流节奏对齐 intent 生命周期（ttl_blocks）；回流含 executed_cost（IntentReceipt）。
- **→N13**：intent 兑现率（承诺份额 vs 实际消耗）为健康指标的原料，只能块级计算。

### 5. 证据空缺

- BAVT 的轮数校准在单任务（非进化循环）上做，进化循环中"每块几轮"的校准曲线不存在。
- 块长 h 与决策粒度的联合消融缺（M1 侧 G 轴问题，M3 只消费其结论）。

## N4 上限性质

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 仅监控告警（**反模式**） | 事后观察超支，无拦截 | 2025-11 四个 LangChain agent 死循环 264h 烧 $47k，根因=无 per-agent 硬上限+无法调用前终止（Waxell 2026-04）；Helicone/LangSmith/Braintrust 全为事后监控 | 永不 |
| **硬上限+软上限降级档（默认）** | 软阈（80%）广播"收敛模式"，不可逆操作（驱逐/重置/快照复活）单独审批；硬触顶 terminate-before-call 后入只读结算态 | GB B-B6；执行层必须在下一次 API 调用发出前拦截（Waxell） | 标准场景默认 |
| 纯硬熔断 | 到数即停无缓冲 | 截断偏差：被截断 run 系统性是"探索更激进/任务更难"的 run，混记则污染统计（GB B-3a） | 仅作软档失效后的最后保险 |

### 2. 隐藏结构

- **节流机制本身是选择压力**（GB B-3）：FunSearch 4h 固定岛重置在演化后期恰好截断正在突破的谱系，且该超参被 PDE-SHARP 等生态原样继承（islands=4/reset=3600s，arXiv:2511.00183）——配额周期与搜索相位解耦时，"何时停"等价于"选择谁死"。软阈广播的本质是把"触顶"从一个时刻变成一个**相位**，让各模块有机会有序收敛而非被砍。
- **超额级联是协议缺失而非模块过错**：触顶后档案照常驱逐、谱系照常记代、复活重耗配额（GB B-3b）——每个单步都局部合理；B-B6 的"超限模式广播+级联冻结"是框架级广播协议的预算侧实例（与 M1 G18 可逆性轴互为镜像）。
- 截断 run 的双重身份：既是已消耗成本（钱花了）又是非随机缺失数据（B-B5）——台账必须同时记"消耗"与"截断归因标记（触顶维度/已消耗/进行到相位）"，统计层须声明删失处理方式。

### 3. 反直觉结论

**硬上限越"硬"越需要软前置——纯硬熔断比仅监控多拦住了钱，却制造了更隐蔽的数据污染**。仅监控的失败是显性的（$47k 账单），纯硬截断的失败是隐性的：截断 run 若混记，策略增量/算子产率的统计全部被截断偏差污染，且被截断分支无后续数据可自证（与 E7/S-4 同构）。所以默认档不是"最硬的"，而是"硬熔断外包一层软阈相位"。

### 4. 模块接口

- **→M1/M4/M2**：超限模式广播（80% 软阈）；硬触顶后禁止任何模块执行不可逆操作（级联冻结）。
- **→X1**：截断归因标记入台账（B-B5）。
- **×N6**：软上限触发降级请求（→M1 重发），硬上限触发熔断——两级语义不可混。

### 5. 证据空缺

- "80% 软阈"的取值无任何实证支撑（GB 提议值），最优软阈位置与任务成本分布的关系无研究。
- 超限模式广播在现有框架中零实现，协议形式（广播内容、冻结清单）为空位设计。

## N5 配额执行模式（reserve→settle 预扣结算）★

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 事后结算 | 先执行后记账 | 与 N4 仅监控同构失效（调用发出后拦截已无意义） | 永不作唯一模式 |
| **reserve→settle（默认）** | 验收时按 budget_estimate 预扣→执行→供应商回报实际成本后结算，多退少补，差入台账；支持层级预算 | Solo agentgateway（2026-06，github.com/day0ops/quota-management）：金融级配额控制标准形态——预留/结算/层级/审批四步 | 一切自动 run 默认 |
| 审批制（人授权硬门） | 超限须人工批准 | agentgateway 支持但作为可选层 | 大额例外（如对照科目挪用，×N8） |

### 2. 隐藏结构

- **reserve 的估计质量是执行模式的真实瓶颈**：预扣按 budget_estimate，而估计误差来自重试率（aider 15–28%）、嵌套展开（B-2）、token 弹性（TALE）。TALE 证据（budget 10 → 实际 157 tokens，arXiv:2412.18547）给出方向性警示：**过紧的估计/约束反而推高实际消耗**——reserve 值存在"合理预算区间"，越界双输（过紧=消耗膨胀，过松=预扣锁死额度降低并发）。TALE-EP 的正面数字：平均省 67% token、精度损失 <3%。
- **预扣失败即拒绝的语义链**：reserve 余额不足 → rejected_budget → M1 重发低档意图（×N6/N9）——预扣是 M3"只报价不决策"原则的物理载体：M3 不替 intent 降档，只报告"此价不可执行"。
- settle 差额不是误差而是**信号**：settle/reserve 偏差率（×N13）按（op_kind×model_tier×供应商）切片后是重试风暴/嵌套失控的早期探针【推断：阈值待标定】。

### 3. 反直觉结论

**预算约束写进 prompt 是"建议档"，只有外部预扣是"执行档"——且建议档过紧时反而更费钱**。直觉认为把预算告知 LLM 能让它自我节制；TALE 证明 LLM 不服从紧约束且过紧约束增加 token 消耗（解释：模型为满足形式约束产生冗余输出【推断】）。结论：prompt 级预算提示至多作软引导（×N12 喂算子档），执行语义必须完全由 reserve→settle 的外部拦截承载。

### 4. 模块接口

- **⇄M1**：reserve 失败 → IntentReceipt{verdict=rejected_budget, reason, executed_cost=0}；settle 完成 → executed_cost 回填。
- **→X1**：reserve 与 settle 各记一条，差额独立入账（B-B15 差额显式归宿的原料）。
- **←N1**：多币种分别预扣（token 与 usd 余额任一不足即拒绝）。

### 5. 证据空缺

- agentgateway 证据为单系统工业实践，无学术消融；reserve 估计模型（按什么分布预测 intent 成本）零文献。
- TALE 的"合理预算区间"边界只在单任务测得，进化循环场景未验证。

## N6 降级档位集与决策归属

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 模型降级 | 切换模型档 | o3 ~$0.15–0.60/iter vs o3-mini ~$0.03–0.12 vs Gemini-Flash ~$0.01–0.05（OpenEvolve README）；FrugalGPT 级联最高省 98%（Chen et al. 2024） | 生成质量对模型档不敏感相位 |
| 评估降档 n_trials↓ | 降评估深度 | M8M9 cascade：shallow n_trials=2 → deep n_trials=5+full_trace；ICC 自动调 n_trials | 受 B-B10 噪声底保底约束——评估档有不可压缩下限 |
| 采样降频 | 降门控/采样频率 | M8M9："门控频率与单次评估成本共享一条预算曲线联合优化" | 高频监控类开销 |
| **三者组合+保底档（默认）** | 多杠杆组合，保底档不可再降 | TALE：降级非单调免费，存在合理预算区间，越界双输 | 标准场景 |
| 归属：M3 自动降档（**反模式**） | M3 就地换档执行 | 档位选择=分配语义，M3 自动降档使 M1 的 expected_gain 承诺与实际执行配置脱钩，对账（B-B14）失真 | 永不 |
| 归属：**M3 拒绝+M1 重发低档（默认）** | M3 只报价与拒绝，降档经 rejected_budget 回流，M1 以低档参数重发 intent | A 组核心设计主张；分配语义单一作者原则 | 标准场景 |

### 2. 隐藏结构

- **"降级"在 M3 侧的真实操作是"拒绝+报价"，降档决策本身一次都不在 M3 发生**。这条边界使 M3 的日志语义干净：台账里只有"执行了什么 intent、花了多少"，没有"M3 擅自改了什么"——一切配置变更都经 M1 重发留下 intent 谱系（policy_version 关联），对账闭环可完整重建因果链。
- **保底档的制度必要性**：无保底时降级链本身是静默质量坍塌通道（GA 卡片 3）；保底档的定值不是成本问题而是统计问题——评估保底由 M8 噪声测量定值（B-B10：噪声底须低于最小可裁决改进量），低于保底 M3 应拒绝开跑并报告"预算不足以产生可证结论"，而非静默压缩评估（SB P=0.49 是举证门槛）。
- **供给端降本与需求端筛选正交**（GA 卡片 6）：FrugalGPT 98%/Morph 70–85%/85-10-5 配比省 92%（厂商级，谨慎引用）都是"同等意图下的降本"，M3 是"哪些意图值得执行"——M3 消费其定价表但不复制其机制。

### 3. 反直觉结论

**最能省钱的模块恰恰不该有省钱决策权**。直觉上让 M3 自动降级是"就地优化"；但降级改变的是 intent 的兑现配置，属分配语义——M3 自动降档后，M1 账上的 expected_gain（带 CI 的承诺）对应的是一个从未被承诺的配置，下一代分配的反馈信号自此失真。把降档踢回 M1 看似多一次往返，实际保住的是整个对账闭环的因果完整性。

### 4. 模块接口

- **⇄M1**：rejected_budget → M1 重发低档（唯一降档通道）。
- **←M8M9**：评估降档的下限由噪声底测量定值；×M2 模型档价目。
- **→N13**：保底档被触及次数=健康信号（预算结构性不足的证据）。

### 5. 证据空缺

- "保底档"的具体定值协议（n_trials 下限与噪声底的函数关系）依赖 M8 噪声测量，该测量本身在多数系统缺位。
- 拒绝-重发回路的时延成本（一次往返=一块？）未量化——ttl_blocks=1 下重发意图可能已过期【接口风险】。

## N7 科目体系（决策因果链投影 vs 模块图投影）★

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 模块图投影（**反模式**） | 按模块名划账（生成/评估/档案） | GEPA：85–90% rollout 花在"维护验证表"隐性科目，账上记作"评估"——总 rollout 6,438/678/6,858/2,157 vs 纯训练 737/79/558/269，验证/训练比 8.7–8.9×（arXiv:2507.19457，原文明确无成本控制） | 永不；它是第 0 天零思考默认而非设计 |
| **决策因果链投影（默认）** | 科目={explore, exploit, reeval, control, handoff, repair, overhead}；区分"产生新候选"vs"维护既有候选可信度"两类成因；隐性科目一等化（独立配额+占比报警线） | B-B1/B-B2；M1-H3 `cost_account∈{explore,exploit,reeval}` 已物化三科目；AIDE² 外环 ~90% 拒绝率="被拒候选的生成+评估"是从未入表的沉没科目 | 标准场景默认 |
| 配比：固定 / M1 信号动态 / **固定下限+弹性上部（默认）** | control 5–10% 硬下限+reeval 噪声底保底，其余科目 M1 信号驱动 | 任务设定对照保留 5–10%；C10/G12 对照不可从构建移除 ⇒ 无保留份额则高负载时对照意图必被饿死；B-B11 科目边际回报均衡化（Archive-Sampling>固定采样，arXiv:2302.00463） | 默认 |

### 2. 隐藏结构

- **科目体系的失效不违反任何内部一致性**（GB B-1"为什么难防"）：按模块划账的报表在同一边界内永远自洽，错配只在与成本成因对齐的替代科目表对照时才暴露——而替代科目表不存在。这意味着科目设计无法靠"运行中发现问题"来修正，必须在第 0 天按决策因果链立账。
- **固定开销占比随总预算下降而上升**【GB 推断】：隐性科目多为固定成本（验证表必须维护），总预算收紧时被挤压的永远是主科目——**小预算 run 与大预算 run 的科目结构系统性不同，跨预算尺度的结果不可比有预算层成因**。这直接支撑 N13 有效预算率作为结论可比性声明的必备标注。
- **对照科目 5–10% 硬下限的制度保障链**（重点）：(a) 启动时与主科目同时锁定、按比例而非余额分配（B-B13）——余额模式下对照的存在性依赖当期运气，制度上等于没有；(b) 挪用须走显式例外程序（谁批的/理由/补跑计划，B-B12）；(c) 连续 N 期未补跑触发结论降权（待证声明标注"对照已过期"）；(d) 兑现率入 N13 健康指标常驻报告。四层缺一即被"这期预算紧先保主线"的局部理性击穿（保险悖论：没出事时保费永远显得浪费）。
- 对照科目的产出是框架自我证成的直接证据：Snell et al. 2024 预算对齐评测——compute 拉平后复杂推理策略常不优于简单基线；"省下的预算再投资为搜索深度"（AIDE² 16× 压缩先例）。

### 3. 反直觉结论

**科目划分是预算系统里最"不工程"却最决定成败的决策——它是会计制度而非软件架构**。GEPA 的 85–90% 之所以以"论文附录数字"而非"运行期报警"存在，不是因为没人测量，而是因为没有一个科目让这个数字**该被报警**。反直觉点在于：增加科目（更细的账）不增加任何运行时开销，却能改变全部下游结论的可信度——而最贵的记账错误（按模块划账）恰好是零思考的默认。

### 4. 模块接口

- **←M1**：`cost_account` 字段为类型层锚点（explore/exploit/reeval 已物化）；control/handoff/repair/overhead 的 intent 标记须 M1 侧扩展【接口缺口】。
- **←M8**：reeval 保底额度由噪声底测量定值（B-B10）。
- **→N8**：科目间流动规则；**→N13**：隐性科目占比与对照兑现率的取数处。
- **→M4 报告**：科目结构随 run 配置归档，供跨 run 可比性声明。

### 5. 证据空缺

- **对照保留科目在全生态零实现**（GA 前沿空位 1：FunSearch/AIDE/OpenEvolve 均无自我证成预算线）——5–10% 的具体数值无消融支撑，只有任务设定与 GEPA 反面锚点。
- "产生新候选 vs 维护可信度"的二分对 handoff/spawn_island 类 intent 的归科规则未定义【推断：按其主要消耗成因归科】。
- 跨模块补贴双记（B-B2）的会计实现（双记条目 schema）无先例。

## N8 科目间转账与修复类消耗归属

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 禁转 | 科目间零流动，最可审 | G17 不可裁决时（CI 覆盖噪声底，adjudicable=None）无处转入重评预算，统计事件被迫等人 | 极保守合规场景 |
| **白名单事件触发（默认）** | 仅三类事件：adjudicable=None（→reeval）/ 相位切换 / Verdict；全部入台账 | G17 重评转账先例（M1 §3.5）——既有转账的触发条件是统计事件而非人工 | 标准场景 |

| **修复归属：按决策归因入账+沉没成本隔离（默认）** | debug/重试/回滚/复活消耗归因到引发决策的 intent 并沿链上卷；无归因记"系统损耗"科目常驻报告；复活候选沉没成本既不计入"已投资价值"也不计入成本-产出比分母；回滚链长度设配额上限，超限冻结该自修改 intent | AIDE₈₅ 进化出"bug rate>15% 才挂 debug 组件"——debug 预算启用阈值须被进化出来，反证全量/无 debug 默认皆失效（weco.ai 2026-07）；AIDE² 反作弊层被自修改改坏+修复无科目（E2 案例预算侧投影） | 标准场景 |

- **转账白名单是科目体系（N7）的宪法执行机构**：N7 划定的保留份额只有在 N8=白名单+例外程序时才物理不可掏空；两轴的关系是"立法 vs 司法"。
- **修复类归属的正确解是归因而非会计技巧**：三种朴素归属各有正确场景，一刀切必错——"这笔消耗是谁的决策引起的"需要 intent→算子→失败→debug 的因果链记录，恰是 B-7 对账层的另一症状；故 B-B16 的上卷义务与 B-B14 的对账闭环共享同一份因果链数据。

### 3. 反直觉结论

**debug 预算的最优配置不是"多"或"少"，而是"阈值化"——且该阈值在默认设计空间里不存在，是被进化出来的**。AIDE₈₅ 自主进化出 bug rate>15% 才挂 debug 组件，说明 fix-vs-regenerate 的经济学分界点真实存在且远离两个朴素默认（全量 debug/无 debug）。M3 的职责不是替系统选阈值，而是让 repair 科目的消耗可见可归因——阈值本身留给上层策略在可见数据上学。

### 4. 模块接口

- **←M2-O12 debug 兜底 / ←M4 buggy_leaf 复活通道**：修复消耗的源头模块，须提供归因链（哪个 intent/配置版本引发）。

- **→N13**：系统损耗科目占比、对照挪用例外次数入健康指标。

- fix-vs-regenerate 分界点除 AIDE₈₅ 单一案例外无第二系统证据。
- 三种修复归属对下游激励的影响是机制推演【GB 自标推断】，无对照实验。
- 回滚链配额的具体上限值无任何参照。

## N9 意图处置三态拒绝分流 ★

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 验收：先进先出 | 队列顺序执行 | 无视 priority 与 ttl，高优 intent 被低优堵塞 | 负载永远远低于配额时 |
| 验收：**priority 重排+ttl 过期清理（默认）** | 优先级排序；ttl_blocks=1 到期未执行即作废清理（易腐品）；snapshot_ref 过期同废 | ttl 易腐+快照绑定为 M1 §2 类型层锚点 | 标准场景 |
| 拒绝：**三态分流（默认）** | rejected_budget（余额不足→M1 重发低档）/ rejected_quota（配额触顶→M1 重新分配）/ deferred（暂不可执行但可等待，如依赖快照未就绪） | IntentReceipt 四态枚举（accepted 外三态）为 M1 §2 既定契约；AIDE² 外环 ~90% 拒绝率为拒绝回流一等化的旁证 | 标准场景 |

### 2. 隐藏结构

- **三态拒绝的语义区分是给 M1 的决策提示，不是错误码**：rejected_budget 告诉 M1"降价重发"，rejected_quota 告诉 M1"此路配额结构性地满，改分配"，deferred 告诉 M1"别改，等等"——三态合并为一个 reject 会迫使 M1 盲猜重发策略【推断：三态分流的价值在拒绝率高的系统中放大，AIDE² 90% 拒绝率下盲猜代价最大】。
- **拒绝是一等谱系事件**（GA 前沿空位 2）：无系统将拒绝回流作谱系记录；但拒绝事件携带"哪个方向的 intent 在什么预算下不可执行"的信息，是 M1 下一代分配与 M4 报告的必需输入。
- **ttl 易腐性的暗面**：ttl_blocks=1 意味着 rejected 后 M1 重发的 intent 已是新 intent（新 intent_id），原 intent 的 reserve 痕迹须随作废一并清理，否则台账出现"幽灵预扣"【推断：与 N5 的 reserve 生命周期绑定】。

### 3. 反直觉结论

**高拒绝率不是系统病态，而可能是预算纪律生效的指纹——前提是被拒成本入科目**。直觉上 90% 拒绝率意味着上游在浪费；AIDE² 案例显示严格外环（~90% 拒绝）恰是其超人类版本的组成。病态的不是拒绝率而是"被拒候选的生成+评估"这一沉没科目不入账（GB B-1 案例 2）——拒绝分流的价值=让沉没成本显式化，而非压低拒绝率本身。

### 4. 模块接口

- **⇄M1**：IntentReceipt 回流（verdict, reason, executed_cost）；拒绝事件入 M1 下一代分配输入。
- **→X1**：拒绝/作废事件入谱系（一等事件）。
- **×N4**：rejected_quota 与超限模式广播联动（触顶相位下新 intent 默认 deferred）。

### 5. 证据空缺

- 三态分流 vs 单态拒绝的 A/B 证据为零（IntentReceipt 四态是契约既定，非实证结论）。
- priority 重排的饿死防护（低优 intent 永远排后）无机制设计——M1 侧 S-5 饿死问题在 M3 队列层的镜像未解【推断：需 aging 机制，无先例】。

## N10 台账 schema 与可见性

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| **最小字段集+append-only 入 X1+policy_version 可切片（默认）** | {account, block_id, unit, reserved, settled, op_kind, model_tier, eval_tier, intent_id, policy_version, admission_outcome}；只增不改；成本可按签发策略版本切片 | M2 §3.6"先建日志后调策略"；EvoX (S,J,ϕ) 版本三元组同构——策略演进史与成本史可联合切片 | 标准场景默认 |

### 2. 隐藏结构

- **policy_version 是台账从"账本"升格为"因果数据库"的关键字段**：无它则"哪个策略版本烧钱效率高"不可答；有它则成本信号可按策略版本切片（EvoX J 信号同构），M1 的策略进化获得成本维度的选择压力【推断：这是 M3 对 M1 策略进化（G14/G15）的唯一反馈通道】。
- **append-only 与截断/拒绝事件的兼容**：作废的 reserve 不删除而是追加"reserve_released"条目——账本的物理不可改性保留了全部审计路径（×N5 幽灵预扣的解法）。
- admission_outcome 字段把台账与准入结果绑定，是 N11 cost-of-pass 的 R（成功率）能在台账内直接计算的前提。

### 3. 反直觉结论

**台账最重要的字段不是金额而是版本号**。金额回答"花了多少"，policy_version + 口径版本戳（×N14）回答"这个数字在什么语境下为真"——跨期比较中前者无意义后者才有意义。各框架账本都记金额、都不记版本，等于都在生产"注定过期的数字"（GB B-4：与 M8 Receipt 失效同根）。

### 4. 模块接口

- **→X1**：append-only 存储；台账条目携带谱系引用。
- **→M1**：块级聚合的成本/效率信号（×N3）。
- **→M4**：run 归档时科目结构与效率指标随档。

### 5. 证据空缺

- 最小字段集是从既有卡片归纳的设计断言，未在任何系统上验证过完备性（如缺 snapshot_ref 的显式字段——目前靠 intent_id 间接关联）【推断】。
- 台账体量（每块多少条目、长 run 的存储/查询成本）无估算。

### 2. 隐藏结构

- **admitted_per_usd 与 cost-of-pass 分治"内部效率"与"外部采购"**：前者把 M9 准入作为产出端口（内部闭环），后者把任务成功作为产出端口（外部对标）；两者的比（admitted 但未 pass）恰是 M8/M9 评估质量的镜像指标【推断】。
- **R（成功率）的分母定义是 cost-of-pass 的暗坑**：按 intent 计、按块计还是按 run 计，同一系统可给出差数量级的 v——CPST 的"端到端摊销"口径（含重试/工具/缓存）是唯一与其他系统可比的口径，但依赖 N2 三级键与 N8 修复归属全部到位。
- **效率指标的方向性危险**（GB 根因 3）：压评估、挪对照在当期 admitted_per_usd 上总表现为改善——效率指标必须与健康指标（N13）联读，单读效率指标等于奖励预算侧作弊。这是 N11×N13 分轴的核心理由。

### 3. 反直觉结论

**"更便宜的模型"与"更便宜的系统"可以相差 19×3=57 倍——单价指标不仅无用，而且方向性地奖励高重试率组件**。$/token 低的模型往往 diff 合规率低（aider：Qwen2.5-Coder-32B 71.6% vs o1-preview 84.2%），重试成本使名义节省反转；唯一诚实的采购指标是含重试摊销的期望成功成本。推论：M3 向 M1 报效率信号时必须报 CPST 口径，否则 M1 会学会偏爱"便宜而脆"的配置。

### 4. 模块接口

- **→M1**：效率级信号喂重排优先级（块级，×N3）。
- **→M4**：run 报告附 cost-of-pass（CPST 口径）。
- **×M2-O19**：目标函数对齐（admitted_per_usd 为共同核算单位）。
- **×N13**：异常级指标与健康指标的分工——N11 管"值不值"，N13 管"M3 自身坏没坏"。

### 5. 证据空缺

- cost-of-pass 在进化循环（多代、准入中间端口）中的定义无文献——Erol/Efficient Agents 均为单次任务场景。
- admitted_per_usd 与最终任务性能的相关性从未被验证（它是 M2-O19 的设计断言）。

## N12 预算余量反馈

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| M3 内部状态 | 余量不进任何决策上下文 | BATS：无预算感知时，给更大工具预算不提升性能——agent 触顶早（arXiv:2511.17006） | 永不 |
| **喂 M1（默认，BATS 式）** | 块级余量摘要进分配决策上下文；BATS Budget Tracker 插件按剩余资源在"深挖/转向"间自适应 | BATS 2025-11 | 标准场景 |
| **喂算子（默认，AIRA 式）** | per-call remaining_budget 进算子签名，算子内部自适应（少 prompt 几轮） | AIRA-dojo：remaining_time 为一等运行时参数 | 算子有内部预算自适应能力时 |

### 2. 隐藏结构

- **双喂的口径一致性是隐藏要求**：M1 看到的块级余量与算子看到的 per-call 余量若来自不同账本视图（如 reserve 前后），会出现"M1 以为有余量、算子已自收缩"的错位；两处须同源（×N1 多币种分别报）。
- **预算感知的收益不在"省钱"而在"行为整形"**：BATS 的自适应（深挖 vs 转向）与 BAVT 的聚焦效应（固定上限反而提升 solve rate）共同指向——余量信息改变的是搜索行为的形状，而非单纯截断它【推断】。
- 喂算子档与 N5 的 token 弹性警示相邻：remaining_budget 以 prompt 注入时是"建议档"，算子可按之整形但不可作执行依据（执行归 reserve）。

### 3. 反直觉结论

**告知预算紧张反而可能增加消耗（TALE），隐瞒预算却必然浪费预算（BATS）——正确解不是"说或不说"而是"对谁说什么粒度"**。对 LLM 输出层说紧约束→token 膨胀；对决策层（M1）说块级余量→分配自适应；对算子说 remaining→行为聚焦。预算信息是按消费者粒度分发的，广播同一数字给所有层是双输。

### 4. 模块接口

- **→M1**：块级余量摘要（随 IntentReceipt 或独立心跳）。
- **→M2**：算子签名扩展 remaining_budget（AIRA 先例）。
- **×N13**：余量分布（各科目剩余比例）本身是健康读数。

### 5. 证据空缺

- BATS/AIRA 均为单 agent 场景，进化循环中"余量反馈给分配器"的收益无一手证据。
- 双喂口径一致性是设计断言，无实现先例。

## N13 M3 健康指标体系（盲区成轴）★

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 无健康指标（**反模式**） | M3 只有内部报表，账本平衡即"正常" | GB 根因 3：M3 失效不表现为自身异常，而表现为所有他模块系统性降级——失效放大器无自诊则无报警 | 永不 |
| **四指标常驻报告（默认）** | ①有效预算率=进入搜索的预算/名义预算（B-B4）；②对账差额率=\|intent 层−call 层差\|/总预算（B-B15）；③隐性科目占比=reeval 验证表+repair+overhead 合计占比（B-B1）；④对照配额兑现率=control 实际执行/启动时锁定配额（B-B12/B-B13） | GEPA 85–90% 验证开销以论文附录数字而非运行期报警存在=③缺失的直接证据；B-6"无人记得最后一次有效对照是何时"=④缺失的症状 | 标准场景默认 |
| 健康指标+阈值联动 | 隐性科目占比超阈→归因报告；对照兑现率连续 N 期不足→待证声明标注"对照已过期"；差额率超阈→对账审计 | B-B15/B-B12 末句 | 生产默认 |

### 2. 隐藏结构

- **四指标对应四种"账本平衡但系统已坏"的失效形态**：有效预算率抓 B-2（固定开销吞噬，"名义 100 实际 70"）；差额率抓 B-7（intent↔call 对账失败，差额无主）；隐性科目占比抓 B-1（验证表吞噬主科目）；对照兑现率抓 B-6（自我证成饿死）。四者共同覆盖 GB 八条失效中五条的可观测面——健康指标本质上是把 B 组失效集编译成常驻探针。
- **有效预算率的跨尺度可比性功能**：固定开销占比随总预算下降而上升（B-1c【推断】）⇒ 小预算 run 的低有效预算率必须在结论可比性声明中标注——该指标同时是 M3 自检与他模块（M4 报告/M8 复现）的输入。
- **与 M4-P19 健康探针同构**：档案层有浓度/熵探针，预算层的四指标是同等级别的模块健康观测量；健康读数应向全框架广播（而非内部报表），因为 M3 失效的病症显现在他模块。

### 3. 反直觉结论

**预算控制器最危险的失效恰恰是"账面完全正常"的失效**。直觉认为记账系统的健康=账平；但 GEPA 的账本从来是平的（每笔 rollout 都记了），85–90% 的错配存在于科目结构而非数字中——错配不违反任何内部一致性（B-1）。故 M3 的健康不能由"账平"自证，必须由独立于记账逻辑的结构性比率（四指标）外证。这是"裁判不能给自己计分"的预算层实例。

### 4. 模块接口

- **取数**：×N7（隐性科目定义）、×N8（对照挪用例外）、×N5（settle/reserve 偏差并入差额率）、×N2（块级聚合）。
- **广播**：→M1（分配输入）、→M4（run 报告与归档）、→M8/M9（对照过期标注影响裁决置信）。
- **→X1**：健康读数时间序列入档（跨 run 漂移可追）。

### 5. 证据空缺

- **四指标的阈值全部无标定**（占比多少算超、差额率多少算失控）——无任何系统实现过，无失败分布可参照；首版只能以 GEPA 8.7× 这类极端值定保守上限【推断】。
- "有效预算率标注"的可比性声明格式无先例（与 M8 的可比性声明如何衔接未定）。
- 健康指标自身的监控成本未估算（指标不能成为新的隐性科目——自指风险）。

## N14 计费口径版本化与标准币锚定（盲区成轴）

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 裸数字记账（**反模式**） | 成本记录无口径信息 | FunSearch/AlphaEvolve/OpenEvolve/ShinkaEvolve 公开实现均无版本戳字段【GB 推断，按已知代码库判断】 | 永不 |
| **口径版本戳（默认基线）** | 每条记录附（供应商, 模型版本, tokenizer/计数器版本, 单价表版本, 日期）；无戳历史账目跨 run 比较降权或禁用 | aider 排行榜：同模型 DeepSeek-V3 换供应商 diff 合规率 98.7%→84.0%——供应商变更同时动单位成本与单位有效产出，成本效率归因被混淆（2024-09~2025-01 多期） | 一切 run |
| **版本戳+标准币锚定（默认）** | 跨期"等预算"以不可漂量定义：有效 LLM 调用数×上下文长度，或标准币（固定基准模型的等价 token）；美元/token 保留到标准币的版本化换算函数 | LLM API 2024–2026 多次数量级调价使"去年 $100"与"今年 $100"对应完全不同的搜索深度（GB B-4）；promptolution 同额美元≠同额搜索深度（CAPO 93.7 vs 78.1 token 单价消耗结构不同） | A/B 对照、退化基线重跑（S-B15）的必备前提 |

### 2. 隐藏结构

- **与 M8 Receipt 纪律同构是本轴的定位锚**（GB 根因 2）：M3 的"美元/token"与 M8 的"分数"同为有时效、有版本的测量值而非物理常数；两组失效共享修复语法（版本戳/锚定/保底/比例锁定）——框架公约若只在评估层设防，防线会被从预算侧绕过（B-5 即"不动任何代码就使评估失效"的合法路径）。
- **双漂混淆是版本戳必须成组出现的原因**：供应商切换同时动成本与质量（98.7%→84.0%），只记价格版本不记（供应商×模型版本）则"成本效率变化"无法归因到价格还是行为——版本五元组缺一不可。
- **换算函数本身版本化**（B-B9 末句）：标准币↔美元的换算率随价目表漂移，旧账重写（按新口径折算）在政治上不受欢迎（可能推翻旧效率结论）——版本化换算函数使"不重写旧账、但可重译"成为可能【推断：这是 append-only（N10）与可比性需求的唯一相容解】。

### 3. 反直觉结论

**跨期公平对照的"等预算"恰恰不能用钱定义——唯一诚实的预算等价物是物理搜索深度**。直觉上"同样 $100"最公平；但在价格数量级漂移的生态里，美元是最不稳的度量衡。标准币（固定基准模型等价 token）把一个经济学问题（价格漂移）还原为物理学问题（搜索深度），代价是承认一切历史美元结论都需重译——这正是 M2-O3"换供应商=触发台账重置"纪律从算子层向预算层的推广。

### 4. 模块接口

- **⇄M8**：与 Receipt 版本纪律同构对齐（字段命名/降权规则建议共享）。
- **→X1**：版本五元组入台账 schema（×N10）。
- **×N1**：汇率表版本化；**→M4**：run 归档附口径声明，跨 run 对照的公平性前提显式化。

### 5. 证据空缺

- "标准币"的具体定义（基准模型选谁、基准模型自身退役后如何换锚）无先例——换锚本身是一次口径漂移【推断：需锚传承协议，空白】。
- "现有框架均无版本戳"基于已知公开实现的判断，未逐一代码审计（GB 自标推断成分中等）。
- 主动对账（定期重测单位成本）本身的预算开销未估算。

## 深挖总结：跨轴主题

1. **"只报价不决策"是 M3 全部接口设计的生成元**：N5（reserve）、N6（拒绝+M1 重发）、N9（三态分流）同是一条边界刚性原则的三个切面——M3 越干净地不做分配决策，对账闭环（B-B14）的因果链越完整。
2. **健康指标（N13）与效率指标（N11）的分轴是本轴系对 GB 根因 3 的直接回应**：效率奖励"省"，健康惩罚"省的代价"——单读任一指标都被激励不对称击穿，联读才构成完整仪表盘。
3. **预算层与评估层是同构测量系统**（根因 2）：N14 的版本戳/标准币与 M8 Receipt 纪律共享修复语法；M3 设计评审应与 M8 联合进行。
4. **空位设计清单**（全生态零实现，M3 的差异化所在）：对照保留科目（N7）、拒绝回流一等谱系（N9）、版本化汇率表（N14）、四指标健康报告（N13）。
