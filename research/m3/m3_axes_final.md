# M3 BudgetController 定稿轴系（轴系建立 · 定稿）

> 依据：`groupA_budget_design.md`（记 GA，12 条候选轴 B1–B12 + 6 张系统卡片）、`groupB_budget_failures.md`（记 GB，失效 B-1～B-8 + 候选公理 B-B1～B-B17 + 三个共同根因）。格式对标 `m1/m1_axes_final.md`。M3 轴用 N 前缀（避免与公理 B-B#、M1 的 G、M2 的 O、M4 的 P 混淆）。所有数字均引自两份底稿，不新搜；推断标【推断】。

## 轴系设计原则

1. **轴 = 决策维度，不是组件列表**；每条轴回答"实现 M3 时必须做的、可不同答的选择"。
2. **边界刚性（A 组核心设计主张）**：
   - **分配意图归 M1**：M3 只报价（reserve）、预扣、结算、拒绝，**不做降档决策**；预算不足时以 `rejected_budget` 经 IntentReceipt 回流 M1，由 M1 重发低档意图——档位选择是分配语义，归 M1 单一作者（GA 卡片 3）。
   - **定价归 M2/M8M9**：算子单价消费 M2-O19 op tax，评估单价消费 M8M9 eval-tax（deterministic≈免费 → LLM judge $0.01–0.03 → 多 judge probe $0.05–0.10）；M3 消费价目表，不制定价目表。
   - **准入归 M9**；**台账 append-only 入 X1**（对齐 M2 §3.6"先建日志后调策略"）。
3. **M3 的输入契约锚点（M1-UNIFIED §2）**：`AllocationIntent{intent_id, block_id, kind, target, budget_estimate, cost_account, priority, expected_gain(可空,强制CI), policy_version, ttl_blocks=1, snapshot_ref}`；回流 `IntentReceipt{verdict∈{accepted, rejected_budget, rejected_quota, deferred}, reason, executed_cost}`。**可拒绝性 + ttl 易腐 + 快照绑定**是三条类型层锚点。
4. **取值互斥、轴间可组合；每轴给默认值**：默认值 = "评估噪声中等、预算有限、单主体单 run"标准场景下证据最强档。
5. **每条轴必须被证据锚定**：至少一条 GB 失效（反推）或 GA 一手实证（正推）。

## 第〇部分：合并与裁决

### Group B 盲区 → 新轴裁决（三个共同根因）

- **根因 1（账本按模块结构划分，成本成因按决策链分布）→ 不另立轴，改写 N7/N8 取值骨架**。B-1/B-2/B-7/B-8 共享的根因是"科目=决策因果链投影 vs 代码模块图投影"，这恰是科目体系（N7）与转账/归属规则（N8）的取值维度本身——把它立为独立轴会掏空 N7 的内容。处置：N7 的科目集扩为 `{explore, exploit, reeval, control, handoff, repair(修复类), overhead(固定开销)}`，并在定义中写死"科目按决策成因划分、隐性科目一等化"（B-B1/B-B2）；N8 扩入修复类消耗归因（B-B16/B-B17）。
- **根因 2（预算台账与 M8 分数台账同构漂移）→ 新轴 N14 计费口径版本化与标准币锚定**。B-4（口径漂移）+ B-B8（版本戳）+ B-B9（标准币）构成独立于"币种族"（N1）的维度：N1 回答"记几种钱"，N14 回答"钱的历史记录如何跨期可比"。与 M8 Receipt 版本纪律同构，不建轴则无处安放。
- **根因 3（M3 是失效放大器而非失效点）→ 新轴 N13 M3 健康指标体系**。GB 明确裁决："M3 的健康指标（有效预算率、差额率、隐性科目占比、对照配额兑现率）必须是全框架的一等公民，而非内部报表"。这不是任何既有轴的取值（N11 效率指标回答"花得值不值"，N13 回答"M3 自己是否健康"——效率正常而健康恶化的组合正是 B-1/B-6/B-7 的失效形态），独立成轴，承载 B-B4/B-B12/B-B13/B-B15 的指标侧。

### Group A 轴处置

- B1–B12 全部保留，编号平移为 N1–N12。
- **特别裁决①（B5×token 弹性耦合）**：reserve 的预扣估计须落在 TALE"合理预算区间"（过紧估计反推高消耗，budget 10 → 实际 157 tokens，arXiv:2412.18547），写入 N5 耦合而非立轴。
- **特别裁决②（B7×B8 硬耦合保留）**：control 科目保留份额只有在 N8=白名单转账时才不可被掏空，两轴独立、耦合写死。
- **特别裁决③（N8 扩取值）**：在 B8 的转账触发白名单之外，并入修复类消耗归属规则（B-B16 按决策归因入账；B-B17 复活沉没成本隔离+回滚链配额）——两者同为"跨科目资金流动的规则"，同属一轴。

**最终轴系：14 轴**（N1–N12 对应 A 组 B1–B12；N13、N14 来自 B 组盲区）。

## N1 预算币种族与汇率表（原 B1）

**一句话定义**：M3 账本以哪几种计量单位开账户、币种间如何折算。

| 取值 | 描述 |
|---|---|
| token / usd / eval_count / node / wallclock 单币种 | 单一单位账户（各系统现状） |
| usd+token 双账户 | 美元记账 + token 物理量并行 |
| **多币种账户族 + 显式汇率表** | 五单位并存，跨币种只在显式汇率层折算（token↔USD 供应商价目驱动；eval↔USD 由 eval-tax 档表驱动） |

**证据锚点**：FunSearch=墙钟（4h/轮）；AIDE=节点数；AIRA-dojo=remaining_time 一等参数；MEMOIR 协议=评估次数 B=16、<$1/run；RelayEvolve=整代 handoff 为单位（GA 卡片 1）。单币种在换供应商/换模型档时静默失真。
**默认值**：多币种账户族 + 显式汇率表（汇率表版本化见 N14）。
**耦合**：×N14（汇率表须版本化，B-B9）；×M2 op tax / ×M8M9 eval-tax（价目来源）。

## N2 记账粒度层级（原 B2）

**一句话定义**：台账记录的最小原子与聚合层级。

| 取值 | 描述 |
|---|---|
| per-call | 原子记账（防漏，但高方差无管理意义） |
| per-node / per-call-group | 算子归因粒度（喂 M2-O20 sub_funnels） |
| **三级键 (account, block_id, op_kind×model_tier)** | call→op→block 三层各司其职 |

**证据锚点**：RelayEvolve 证 per-call 路由是错的问题（决策单位是整代）；同一编码任务跨 run token 方差 30×（arXiv:2604.22750）、精度相近 agent 间成本方差 50×（arXiv:2511.14136）；TensorZero/Helicone 工业栈 per-call+per-task 归因为标准能力。
**默认值**：三级键。
**耦合**：×N11（三级键是 admitted_per_usd 按算子/相位归因的前提）；×N13（差额率依赖块级聚合）。

## N3 决策粒度（原 B3）

**一句话定义**：M3 对 M1 回流与内部配额裁决的最小决策单位。

| 取值 | 描述 |
|---|---|
| per-call | 逐调用裁决（噪声、状态耦合下失效） |
| **per-block / per-generation** | 块级/代级，对齐 AllocationIntent.block_id 与 ttl_blocks |

**证据锚点**：RelayEvolve handoff 整代为单位（arXiv:2608.05651）；M1 契约 block_id/ttl_blocks=1（GA 卡片 2）；BAVT 块级轮数配额可省 68% 成本且几乎不掉 solve rate（arXiv:2510.16786）。
**默认值**：per-block（向 M1 回流只在块级发生，防高频噪声）。
**耦合**：×N2（决策粒度=记账粒度第三层）；×M1（回流节奏对齐 intent 生命周期）。

## N4 上限性质（原 B4）

**一句话定义**：预算耗尽的执行语义——监控、软上限降级还是硬熔断。

| 取值 | 描述 |
|---|---|
| 仅监控告警 | 事后观察（**反模式**："alert 是验尸报告不是护栏"） |
| **硬上限 + 软上限降级档** | 软阈（80%）广播收敛模式 + 硬熔断 terminate-before-call |
| 纯硬熔断 | 到数即停，无降级缓冲（截断偏差风险，GB B-3） |

**证据锚点**：2025-11 四个 LangChain agent 死循环 264h 烧 $47k（无 per-agent 硬上限+无法调用前拦截，Waxell 2026-04）；执行层必须在下一次 API 调用发出前拦截。
**默认值**：硬上限+软上限降级档（GB B-B6：80% 软阈广播 + 硬触顶后只读结算态）。
**耦合**：×N6（降级归属）；×N9（截断 run 须带截断归因标记入台账，B-B5）；×M4/M1（超限模式广播冻结不可逆操作）。

## N5 配额执行模式（原 B5）

**一句话定义**：预算从承诺到结算的物理流程。

| 取值 | 描述 |
|---|---|
| 事后结算 | 先跑后记账（无法拦截，同 N4 反模式） |
| **reserve→settle 预扣-结算** | 出闸前按 budget_estimate 预扣，供应商回报实际后多退少补，差入台账 |
| 审批制 | 人授权硬门（不适于自动研究循环） |

**证据锚点**：Solo agentgateway 金融级四步配额（2026-06，层级预算/预测/审批）；prompt 注入预算约束只是建议档（TALE token 弹性，硬执行必须外部拦截）。
**默认值**：reserve→settle；预扣估计须落在 TALE 合理预算区间（过紧反推高消耗：budget 10 → 实际 157 tokens）。
**耦合**：×N1（reserve 按多币种分别预扣）；×N13（settle/reserve 偏差率=健康指标）；×N6（rejected_budget 触发 M1 重发而非 M3 自动降档）。

## N6 降级档位集与决策归属（原 B6）

**一句话定义**：预算压力下可降什么档、谁来决定降档。

| 取值 | 描述 |
|---|---|
| 模型降级 / 评估降档 n_trials↓ / 采样降频 | 单杠杆 |
| **三者组合 + 保底档不可再降** | 保底档防降级链成为静默质量坍塌通道 |
| 决策归属：M3 自动降档 | **（反模式）** 档位=分配语义，M3 自动降档=越权 |
| 决策归属：**M3 拒绝 + M1 重发低档** | 分配语义单一作者（边界刚性原则 2） |

**证据锚点**：M8M9 cascade 三档（n_trials=2→5）+ ICC 自动调；M2 模型档价差（o3 $0.15–0.60/iter vs Flash $0.01–0.05）；FrugalGPT 级联省 98%；TALE-EP 省 67% token、精度损失 <3%（降级非单调免费，存在合理预算区间）。
**默认值**：组合降级档 + 保底档；归属=M3 拒绝+M1 重发。
**耦合**：×N4（软上限触发降级而非熔断）；×N9（rejected_budget 三态语义）；×M8M9（评估降档改变噪声底——B-B10 保底约束）。

## N7 科目体系（原 B7，按根因 1 改写取值骨架）★

**一句话定义**：预算科目的划分原则与科目集——**科目必须是决策因果链的投影，而非代码模块图的投影**。

| 取值 | 描述 |
|---|---|
| 模块图投影 | 按模块名划账（生成/评估/档案）——**反模式**，隐性科目不可见 |
| **决策因果链投影** | 科目集 {explore, exploit, reeval, control, handoff, repair, overhead}；区分"产生新候选"与"维护既有候选可信度"两类成因 |
| 配比：固定 / M1 信号动态 / **固定下限+弹性上部** | control 科目 5–10% 硬下限、reeval 噪声底保底，其余弹性 |

**证据锚点**：GEPA 85–90% rollout 花在验证表维护这个隐性科目（总 6,438/678/6,858/2,157 vs 纯训练 737/79/558/269，arXiv:2507.19457）——隐性科目无独立配额即无报警；M1-H3 三账户物化点 `cost_account ∈ {explore, exploit, reeval}`；C10/G12 对照不可从构建移除 ⇒ control 科目必须有保留份额；B-B4 固定开销科目化。
**默认值**：决策因果链投影 + 固定下限（control 5–10%）+ 弹性上部；隐性科目（reeval 验证表/repair/overhead）有独立配额与占比报警线。
**耦合**：×N8（保留份额只在白名单转账下不可掏空）；×M1（cost_account 字段为类型层锚点）；×M8（reeval 保底由噪声测量定值，B-B10）；×N13（隐性科目占比=健康指标）。

## N8 科目间转账与修复类消耗归属（原 B8 扩）

**一句话定义**：跨科目资金流动的触发白名单，及 debug/重试/回滚/复活消耗的归因规则。

| 取值 | 描述 |
|---|---|
| 禁转 | 简单可审，但 G17 不可裁决时无处转 |
| **白名单事件触发** | 仅 adjudicable=None（重评转账）/ 相位切换 / Verdict 三类事件；全部入台账 |
| 自由转账 | **反模式**（科目体系形同虚设） |
| 修复归属：记原候选 / 记算子 / 记系统 | 三种归属三种错误激励（GB B-8） |
| 修复归属：**按决策归因入账 + 沉没成本隔离** | 归因到引发决策的 intent；无归因记"系统损耗"并常驻报告（B-B16/B-B17） |

**证据锚点**：G17 重评转账先例（M1 §3.5，CI 覆盖噪声底→production→reeval）；AIDE₈₅ 进化出"bug rate>15% 才挂 debug"反证全量/无 debug 皆失效配置；回滚链无配额可使自修改 agent 烧预算于改坏-回滚循环。
**默认值**：白名单事件触发 + 修复按决策归因；回滚链长度设配额上限；复活候选沉没成本不计入"已投资价值"也不计入成本-产出比分母。
**耦合**：×N7（control 挪用须走例外程序，B-B12：谁批的/理由/补跑计划）；×M4 buggy_leaf 复活通道 / ×M2-O12 debug 兜底（修复消耗的源头模块）。

## N9 意图处置语义（原 B9）★

**一句话定义**：intent_queue 的验收排序与拒绝分流语义。

| 取值 | 描述 |
|---|---|
| 验收：先进先出 | 简单，无视优先级与易腐性 |
| 验收：**priority 重排 + ttl 过期清理** | ttl_blocks=1 易腐品须主动清理 |
| 拒绝三态分流 | rejected_budget（钱不够→M1 重发低档）/ rejected_quota（配额触顶）/ deferred（可等待） |

**证据锚点**：IntentReceipt 四态枚举为 M1 §2 类型层既定；ttl 易腐+快照绑定（snapshot_ref 过期即作废）；AIDE² 外环 ~90% 拒绝率为拒绝回流一等化的旁证（GA 前沿空位 2）；BAVT 块级配额校准先例。
**默认值**：priority 重排+ttl 清理 + 三态拒绝分流；被节流终止的 run 带截断归因标记入台账（B-B5）。
**耦合**：×N3（块级回流）；×N6（rejected_budget→M1 重发低档）；×M1（拒绝回流是一等谱系事件，喂下一代分配）。

## N10 台账 schema 与可见性（原 B10）

**一句话定义**：成本台账的最小字段集、存储与切片维度。

| 取值 | 描述 |
|---|---|
| 最小字段集 | {account, block_id, unit, reserved, settled, op_kind, model_tier, eval_tier, intent_id, policy_version, admission_outcome} |
| **append-only 入 X1 + policy_version 可切片** | 成本可按签发策略版本切片（EvoX J 信号同构） |

**耦合**：×N14（版本戳字段）；×X1（存储与谱系）；×M1（成本信号供重排）。

## N11 效率指标体系（原 B11）★

**一句话定义**：衡量"钱花得值不值"的指标族与反馈对象。

| 取值 | 描述 |
|---|---|
| cost_per_call / $/token | **反模式**（便宜 19× 的模型若需 3× 重试则生产更贵） |
| **admitted_per_usd + cost-of-pass v=C/R + CPST** | 期望成功成本为采购指标；CPST 含重试/工具/缓存摊销 |

**证据锚点**：M2-O19 目标函数 admitted_per_usd；cost-of-pass（Erol et al. 2025，METR 扩展为混合 frontier）；Efficient Agents：GAIA 上保留 OWL 96.7% 性能、成本 $0.398→$0.228（cost-of-pass 改善 28.4%，arXiv:2508.02694）；digitalapplied CPST 2026-04。
**默认值**：admitted_per_usd 为主、cost-of-pass C/R 为采购对照；效率级喂 M1 重排，异常级触发降级/熔断。
**耦合**：×N2（三级键前提）；×M2-O19（目标函数对齐）；×M4（报告）；×N13（异常级与健康指标的边界：效率管"值不值"，健康管"M3 自身有没有坏"）。

## N12 预算余量反馈（原 B12）

**一句话定义**：预算余量作为观察量反馈给谁。

| 取值 | 描述 |
|---|---|
| M3 内部状态 | 决策层无预算感知（BATS 证明失效） |
| **喂 M1（BATS 式预算感知）** | 余量进入分配决策上下文 |
| 喂算子（AIRA remaining_time 式） | 算子内部自适应（少 prompt 几轮） |

**证据锚点**：BATS（arXiv:2511.17006）：无预算感知时更大预算不提升性能（触顶早）；AIRA-dojo 算子签名携带 remaining_time。
**默认值**：同时喂 M1（块级余量摘要）与算子（per-call remaining_budget），两处口径一致。
**耦合**：×M1（分配输入）；×M2（算子签名扩展）；×N1（余量须多币种分别报）。

## N13 M3 健康指标体系（新轴，根因 3）★

**一句话定义**：衡量"M3 自身是否健康"的一等指标族——M3 是失效放大器而非失效点，其失效表现为所有他模块系统性降级，故健康指标必须是全框架一等公民。

| 取值 | 描述 |
|---|---|
| 无健康指标（内部报表自足） | **反模式**：账本平衡、报表正常，但"名义预算 100 与实际可分配 70"的差额无人认领（GB B-2） |
| **四指标常驻报告** | ①有效预算率 = 进入搜索的预算/名义预算（B-B4）；②对账差额率 = \|intent 层−call 层差\|/总预算（B-B15）；③隐性科目占比（reeval 验证表/repair/overhead，B-B1）；④对照配额兑现率 = control 实际执行/锁定配额（B-B12/B-B13） |
| 健康指标 + 降级联动 | 超阈自动触发例外程序/审计/结论降权 |

**证据锚点**：GEPA 85–90% 验证开销以"论文附录数字"而非"运行期报警"存在=健康指标缺失的直接证据；对照科目被连续挪用后"无人记得最后一次有效对照是何时"（GB B-6）；intent-call 对账差额在 FunSearch/OpenEvolve/ShinkaEvolve 公开实现中均无归属结构【GB 推断，按已知代码库判断】。
**默认值**：四指标常驻报告 + 阈值联动（隐性科目占比超阈触发归因报告；对照兑现率连续 N 期不足触发待证声明标注"对照已过期"）。
**耦合**：×N7（隐性科目定义）；×N8（对照挪用例外记录）；×N5（settle/reserve 偏差率并入）；×全模块（健康读数广播，与 M4-P19 探针同构）。

## N14 计费口径版本化与标准币锚定（新轴，根因 2）

**一句话定义**：成本记录的可比性保障——台账值是有时效、有版本的测量值，不是物理常数。

| 取值 | 描述 |
|---|---|
| 裸数字记账 | 无版本戳（现有框架现状：FunSearch/AlphaEvolve/OpenEvolve/ShinkaEvolve 公开实现均无口径字段【GB 推断】） |
| **口径版本戳** | 每条记录附（供应商, 模型版本, tokenizer/计数器版本, 单价表版本, 日期）（B-B8） |
| 版本戳 + **标准币锚定** | 跨期对照以不可漂量定义"等预算"（有效调用数×上下文长度，或固定基准模型等价 token）；美元/token 保留到标准币的版本化换算函数（B-B9） |

**证据锚点**：aider 排行榜：同模型 DeepSeek-V3 换供应商 diff 合规率 98.7%→84.0%——成本-质量双维同漂，归因混淆；LLM API 2024–2026 多次数量级调价；与 M8 Receipt 失效同构（GB 根因 2）。
**默认值**：版本戳 + 标准币锚定；无版本戳的历史账目在跨 run 比较中降权或禁用。
**耦合**：×N1（汇率表版本化）；×M8（与 Receipt 版本纪律同构对齐）；×N10（schema 字段落地）；A/B 对照与退化基线重跑的公平性前提。
