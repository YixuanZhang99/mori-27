# 任务一：七个经典分歧裁决

## 分歧 1：币种族——单币种账户 vs 多币种账户族+显式汇率表（N1）

### 两方最强论据

**单币种方**：全部现存系统的实际形态（FunSearch=墙钟；AIDE=节点数；MEMOIR=评估次数 B=16/<$1）——简单、零折算开销、报表无歧义；单系统常并存两种单位也活得好好的（FunSearch=墙钟+样本上限）。

**多币种方**：单币种的"简洁"是把汇率风险静默转嫁给一切跨期结论——LLM API 2024–2026 多次数量级调价，"去年 $100"与"今年 $100"对应完全不同的搜索深度（GB B-4）；aider 同模型换供应商 diff 合规率 98.7%→84.0% 证双维同漂；N1 深挖反直觉结论："正确的问题不是用哪种钱记，而是哪个量不漂"——物理量（token/调用数/墙钟）不漂，美元只是汇率层的折算视图。

### 裁决规则

- **裁决变量**：是否存在跨供应商/跨模型档/跨期对照需求（=是否严肃 run）× 价目来源是否外部化（M2 op tax / M8M9 eval-tax）。
- **裁决规则**：默认 `多币种账户族 + 显式汇率表`（BudgetAccount{unit, ceiling, spent, reserved}×5 单位，跨币种只在显式汇率层折算、账本内不混记）；单币种仅允许于原型期+供应商模型档永不变+无跨 run 对照的场景，且须显式声明豁免理由。汇率表版本化是刚性联动（×N14，未版本化的汇率表=裸数字记账反模式）。
- **前置条件**：M2-O19 op tax 与 M8M9 eval-tax 价目表供给在位；AllocationIntent 增 budget unit 字段（接口缺口，见末节契约修订建议 R1）——无 unit 字段的 intent 在多币种账本下不可预扣。
- **默认值**：多币种账户族 + 显式汇率表。

### 落成方式

- **配置项**：`budget_units ∈ {token, usd, eval_count, node, wallclock}` 子集声明 + `exchange_rate_table`（版本化）；墙钟账户带独立 ttl 语义（不可囤不可转移，N1 深挖）。
- **协议**：reserve 按声明币种分别预扣（任一币种余额不足即拒绝，×N5）；汇率表版本变更事件入 X1。

## 分歧 2：上限性质——纯硬熔断 vs 硬上限+软上限降级档（N4）

### 两方最强论据

**纯硬熔断方**：工程上唯一零争议的节流实现，"到数即停"写进配置即合规；$47k 死循环事故（2025-11 四个 LangChain agent 跑 264h，Waxell 2026-04）证明无硬拦截是灾难——执行层必须在下一次 API 调用发出前拦截。

**硬+软双档方**：纯硬熔断拦住了钱却制造更隐蔽的数据污染——被截断 run 系统性是"探索更激进/任务更难"的 run（非随机缺失，GB B-3a），混记则污染一切完成数据统计；且触顶后下游模块按"预算正常耗尽"语义继续执行不可逆操作（档案驱逐/谱系记代/复活重耗配额），一次超额级联成多次不可逆（GB B-3b）。软阈（80%）广播把"触顶"从一个时刻变成一个**相位**，给各模块有序收敛的机会。

### 裁决规则

- **裁决变量**：是否有下游不可逆操作链（档案驱逐/快照复活/相位切换）× 截断数据的下游统计消费强度。
- **裁决规则**：默认 `硬上限 + 软上限降级档`——软阈 80% 广播"收敛模式"+ 不可逆操作配额单独审批 + 硬触顶 terminate-before-call 后入只读结算态；纯硬熔断仅作软档失效后的最后保险；"仅监控告警"为反模式永久禁止（alert 是验尸报告不是护栏）。80% 的具体取值无实证支撑（GB 提议值），列为待标定参数（见诚实边界 4）。
- **前置条件**：超限模式广播通道（→M1/M4/M2）在位——该协议全生态零实现，是空位设计；截断归因标记字段入台账 schema（×N10）。
- **默认值**：硬上限+软上限降级档。

### 落成方式

- **配置项**：`ceiling_mode ∈ {monitor_only(禁), hard_only, hard_plus_soft}` + `soft_threshold=0.8`（占位待标定）。
- **硬编码**：硬触顶后任何模块执行不可逆操作=运行期拦截（级联冻结，B-B6）；截断 run 无归因标记入账=构建期拒绝。

## 分歧 3：reserve 预扣估计的松紧——保守高预扣 vs TALE 合理区间（N5）

### 两方最强论据

**保守高预扣方**：成本方差巨大（跨 run 30×/agent 间 50×），低估预扣导致中途余额不足级联拒绝；先扣押金后结算（agentgateway 金融级先例）天然偏向"多扣多退"。

**合理区间方**：TALE 一手证据（arXiv:2412.18547）——过紧估计/约束**反而推高实际消耗**（budget 10 → 实际 157 tokens），存在"合理预算区间"，越界双输；过松则预扣锁死额度、降低并发（N5 深挖）。松紧两个方向都有真实代价，不是单调"越紧越安全"。

### 裁决规则

- **裁决变量**：intent 成本可预测性（重试率×嵌套深度×token 弹性）× 并发需求。
- **裁决规则**：默认 `reserve→settle` 且预扣估计须落在 TALE 合理预算区间内——**过紧与过松同为失效配置**；具体取值为"按 (op_kind×model_tier×供应商) 切片的历史 settle 分布的 P50–P75 起步"【推断，零文献，见诚实边界 4】；无上卷能力的嵌套调用按成本上界预扣（B-B3 押金档）。settle/reserve 偏差率按切片常驻报告（×N13），它是指示重试风暴/嵌套失控的早期探针而非记账误差。
- **前置条件**：N2 三级键历史台账积累（无历史则无分布可分位）；M1 budget_estimate 的 CI 形态声明（可空，非空带 CI——与 expected_gain 同纪律）。
- **默认值**：reserve→settle + 合理区间预扣 + 偏差率切片报告。

### 落成方式

- **配置项**：`reserve_quantile`（默认 0.5–0.75 占位）+ `nested_call_policy ∈ {rollup,押金上界}`。
- **协议**：reserve 与 settle 各记一条台账、差额独立入账（B-B15 原料）；作废 reserve 追加 reserve_released 条目而非删除（N10 append-only 兼容）。

## 分歧 4：科目投影方式——模块图投影 vs 决策因果链投影（N7）

### 两方最强论据

**模块图投影方**：按模块名划账（生成/评估/档案）与代码结构同构，实现零成本、报表直观——是第 0 天的零思考默认。

**决策因果链投影方**：GEPA 一手锚点——85–90% rollout 花在"维护验证表"隐性科目、账上记作"评估"（6,438/678/6,858/2,157 vs 737/79/558/269，验证/训练比 8.7–8.9×，arXiv:2507.19457【原文明确无成本控制】）；模块图投影的失效不违反任何内部一致性，只在与成本成因对齐的替代科目表对照时才暴露——而替代科目表不存在 ⇒ **科目设计无法靠运行中发现问题修正，必须第 0 天按决策因果链立账**（N7 深挖隐藏结构 1）。

### 裁决规则

- **裁决变量**：无——这是全 14 轴中裁决强度最高的一条：模块图投影在任何场景下都不是合法默认值，只是"未做科目设计"的别名。
- **裁决规则**：默认 `决策因果链投影`，科目集 {explore, exploit, reeval, control, handoff, repair, overhead}；隐性科目（reeval 验证表/repair/overhead）一等化=独立配额+占比报警线；配比档默认 `固定下限+弹性上部`（control 5–10% 硬下限、reeval 噪声底保底由 M8 测量定值，其余弹性由 M1 信号驱动）。handoff/spawn_island 类 intent 的归科规则按主要消耗成因归科【推断，规则待补】。
- **前置条件**：M1 cost_account 字段扩展（目前仅物化 explore/exploit/reeval 三值，control/handoff/repair/overhead 须扩枚举，见契约修订建议 R2）；M8 噪声底测量在位（reeval 保底定值来源）。
- **默认值**：决策因果链投影 + 固定下限 + 弹性上部。

### 落成方式

- **配置项**：`cost_account` 封闭枚举（七科目）+ `account_floor{control: 0.05–0.10, reeval: f(M8 noise_floor)}`。
- **硬编码**：按模块名命名的科目不在合法取值集；隐性科目无独立配额=构建期拒绝。

## 分歧 5：对照科目保障强度——保留份额+例外程序 vs 余额分配（N7×N8×B-6）

### 两方最强论据

**余额分配/弱保障方**："这期预算紧先保主线"在每一步都是局部理性；对照科目的产出（证明系统其他部分是否有效）不直接产生 best 分数，按产出分配的压力下天然排最后——既然如此不如承认现实，主线有剩再做对照。

**宪法化方**：余额模式下对照的存在性依赖当期运气，制度上等于没有（B-B13）；连续挪用 N 期后系统全部结论失去对照基础且"无人记得最后一次有效对照是何时"（GB B-6）；ShinkaEvolve 三消融的稀有性本身度量了生态中对照预算的匮乏；保险悖论（没出事时保费永远显得浪费）说明该保障无法依赖任何当期决策者的自觉，只能内生于配额设计。

### 裁决规则

- **裁决变量**：无（同分歧 4，弱保障在任何场景不合法）。
- **裁决规则**：默认四层保障链，缺一即被局部理性击穿——(a) 启动时与主科目**同时锁定**、按固定比例 5–10% 分配（B-B13，非余额模式）；(b) 挪用须显式例外记录{谁批的/理由/补跑计划}（B-B12）；(c) 连续 N 期未补跑触发结论降权（待证声明自动标注"对照已过期"）；(d) 对照配额兑现率入 N13 健康指标常驻报告。5–10% 数值无消融支撑【推断，见诚实边界 2】；该科目即 M1-UNIFIED §0.1 自我证成公约"对照预算为 M3 保留科目"的物化点。
- **前置条件**：N8=白名单转账（control 保留份额只在白名单+例外程序下物理不可掏空，轴系硬耦合 N7×N8）。
- **默认值**：比例锁定 + 例外程序 + 过期降权 + 兑现率监控四层链。

### 落成方式

- **硬编码**：control 科目的启动时锁定不可被普通转账路径触及；例外挪用的审批条目为一等台账类型。
- **协议**：对照兑现率连续 N 期不足 → 全框架广播"对照已过期"标注（→M8/M9 裁决置信、→M4 报告）。

## 分歧 6：效率指标选择——admitted_per_usd vs cost-of-pass C/R vs 单价指标（N11）

### 两方最强论据

**admitted_per_usd 方**：对齐 M2-O19 目标函数"有效搜索深度"；以 M9 准入为产出端口构成内部闭环，可按算子/相位归因（×N2 三级键）。

**cost-of-pass v=C/R 方**：以任务成功为产出端口，是外部采购对标的唯一诚实口径——便宜 19× 的模型若需 3× 重试则生产更贵（CPST，digitalapplied 2026-04）；Efficient Agents GAIA 上成本 $0.398→$0.228、cost-of-pass 改善 28.4%（arXiv:2508.02694）；Erol et al. 2025 与 METR 混合 frontier 提供学术锚。$/token 单价指标为反模式（方向性奖励高重试率组件）。

### 裁决规则

- **裁决变量**：指标的用途（内部调度信号 vs 外部采购对标）——两指标分治而非竞争。
- **裁决规则**：默认 `admitted_per_usd 为主（效率级，喂 M1 重排）+ cost-of-pass CPST 口径为采购对照（→M4 报告、降级档比较）`；单价指标永久禁止作决策依据。R 的分母口径固定为 CPST 端到端摊销（含重试/工具/缓存），依赖 N2 三级键与 N8 修复归属全部到位——口径未到位时 cost-of-pass 读数不得用于跨系统比较。M3 向 M1 报效率信号必须报 CPST 口径，否则 M1 学会偏爱"便宜而脆"的配置（N11 深挖反直觉结论）。
- **前置条件**：台账 admission_outcome 字段在位（R 可在台账内直接计算的前提）；N13 健康指标联读义务（单读效率指标=奖励预算侧作弊，GB 根因 3）。
- **默认值**：admitted_per_usd 主 + C/R 采购对照 + 两级反馈（效率级喂 M1、异常级触发降级/熔断）。

### 落成方式

- **配置项**：`efficiency_metrics = {primary: admitted_per_usd, procurement: cost_of_pass_cpst}`。
- **硬编码**：cost_per_call、$/token 不在决策指标合法取值集；cost-of-pass 跨系统引用无 CPST 口径声明=报告退回。

## 分歧 7：预算反馈双喂的分发粒度——统一广播 vs 按消费者粒度分发（N12）

### 两方最强论据

**统一广播方**：一个余量数字喂所有消费者（M1/算子/档案），实现最简、口径天然一致。

**按消费者分发方**：BATS（arXiv:2511.17006）证无预算感知时更大预算不提升性能（触顶早）⇒ 决策层必须感知；TALE 证对 LLM 输出层告知紧约束反而增加 token 消耗 ⇒ 同一数字广播给所有层是双输。正确解是"对谁说什么粒度"：对决策层（M1）说块级余量→分配自适应；对算子说 per-call remaining_budget→行为聚焦（AIRA-dojo 先例）；对 LLM 输出层至多软引导、执行归 reserve。

### 裁决规则

- **裁决变量**：消费者的决策层级（分配决策/算子内部整形/prompt 建议）。
- **裁决规则**：默认 `双喂`——M1 收块级余量摘要（随 IntentReceipt 或独立心跳），算子收 per-call remaining_budget（算子签名扩展）；两处**口径同源**为隐藏硬要求（不同源则出现"M1 以为有余量、算子已自收缩"的错位）；prompt 级预算提示至多软引导档，不得作执行依据（×N5）。余量多币种分别报（×N1）。
- **前置条件**：M2 算子签名扩展 remaining_budget 字段；M1 分配上下文接收块级余量摘要的接口。
- **默认值**：双喂 + 同源口径。

### 落成方式

- **配置项**：`feedback_targets = {m1: block_level, operators: per_call}` + 单一账本视图源声明。
- **协议**：余量分布（各科目剩余比例）本身入 N13 健康读数；双喂口径校验为定期自检项【推断：校验协议待建】。

# 任务二：失效模式 → 正式公理集（J 系列）

# 任务三：三共同根因 × 四条不变量 + I-披露/I-可逆候选 + 自我证成公约——跨模块对账

## Group B（M3 侧）三共同根因

1. **科目体系须为决策因果链的投影，而非代码模块图的投影**：B-1（科目错配）、B-2（嵌套隐形）、B-7（对账失败）、B-8（归属缺失）共享同一根因——记账的天然粒度是"哪个模块发起了哪次调用"，预算管理的正确粒度是"哪个决策引起了这笔消耗"；两层间的映射（结算/穿透/归因）是跨模块公共品，无人拥有、无人建设，M3 的核心架构职责正是拥有这个映射层（→ N7/N8、J1/J2/J9/J10）。
2. **预算测量值与评估分数同构漂移，需同级版本化与制度保护**：B-4 与 M8 Receipt 失效同构、B-5 与 E6 同构、B-6 与 S-8 同构——M3 的"美元/token"与 M8 的"分数"同为有时效、有版本的测量值；两组失效共享同一修复语法（版本戳/标准币/保底配额/比例锁定）；框架公约若只在评估层设防而不在预算层设防，防线会被从预算侧绕过——低预算抬高噪声底是"不动任何代码就使评估失效"的合法路径（→ N14、J6/J7/J8）。
3. **失效方向的激励不对称在预算层达极致，M3 健康指标必须一等化**：压缩评估/挪用对照/硬截断/不建对账层在当期报表上全部表现为效率提升，代价延迟、跨模块、归属他者；且 M3 独有机制——**M3 掌握其他所有模块的资源开关，其失效不表现为自身异常而表现为所有他模块的系统性降级——M3 是失效放大器而非失效点**（→ N13、N11×N13 分轴）。

|---|---|---|
| 根因 1（科目=决策因果链投影） | **不被任何既有不变量覆盖，但它不是"约束形状"的新原则，而是 I-谱系在预算层的语义规定**：I-谱系要求"记录带谱系、可失效、不删除硬证据"——M3 根因 1 回答的是"成本记录的谱系键是什么"：不是模块名（代码结构谱系），而是 intent 链（决策因果谱系）。AllocationIntent.intent_id/policy_version 进台账 schema（N10）即 I-谱系的预算层物化；这与 M1 根因 1 被 I-β 覆盖的处置同型——**记录层的正确性归 I-谱系，判别层的正确性归 I-β，预算科目体系是前者**。M3 的增量：把"谱系"从候选/策略版本扩展到**成本归因链**（intent→算子→失败→debug），每一笔花费都能回答"谁的决策" | **覆盖（I-谱系预算层物化形态贡献：成本归因谱系）；不上收新原则** |
| 根因 2（同构漂移+制度保护） | **与自我证成公约是"互为基础"关系，须双向论证**：(a) 公约→根因 2：M1-UNIFIED §0.1 公约已把"对照预算 5–10% 由 M3 记账为保留科目"写入管辖范围——J8 是该条款的完整物化（比例锁定+例外程序+过期降权+兑现率监控四层链），M3 是公约的执行机构（"框架公约执行者"恰是 GB B-6 对 M3 的定位）；(b) 根因 2→公约：公约的举证门槛"同预算对照+增量超 M8 噪声底"**以预算等价性为前提**——跨期重跑退化基线时"等预算"若用裸美元定义则等价性已漂移（J6 标准币），且噪声底本身是评估预算的函数（J7：压评估=抬噪声底=让被证组件更易"通过"对照，公约的显著性判据可被预算侧静默绕过）。**结论：公约不设防预算层则公约本身失效；J6/J7/J8 应作为公约的预算侧配套条款纳入其管辖范围**（建议修订，见下） | **根因 2 一半被 I-β 覆盖（测量值版本化与制度保护=质量指标一等化的预算层投影：N14 版本戳与 M8 Receipt 纪律同构对齐），另一半揭示自我证成公约的盲区——不构成新不变量，但构成公约修订建议** |
| 根因 3（激励不对称达极致+M3 健康一等化） | **与 I-β 的关系是"第五个投影+投影强度论证"**：M1 对账已建立"健康不可内观测"四模块同型链（M9 闸门判别质量/M2 算子产率/M4 档案健康/M1 策略健康）。M3 根因 3 补上**第五环，且是强度最高的一环**：前四环的失效至少显形于自身账上（裁决记录/算子日志/档案结构/意图谱系），M3 的失效连自己的账都是平的（GEPA 账本从来是平的，85–90% 错配存在于科目结构而非数字）——"裁判不能给自己计分"在预算层的实例（N13 深挖反直觉结论：M3 的健康不能由"账平"自证，必须由独立于记账逻辑的结构性比率外证）。这**反向论证了 I-β 的必要性条件**：质量指标必须独立于被测机制的内部一致性（四指标全部是结构性比率而非账务勾稽）。同时根因 3 的"激励不对称"部分与 M1/M4 处置一致——是根因而非不变量候选。N11×N13 分轴（效率管"值不值"、健康管"自己坏没坏"）是 I-β"按用途分离物化"形态（M1 已记）的预算层实例：单读效率指标=奖励预算侧作弊 | **覆盖（I-β 第五投影确认，且给出 I-β 的独立性必要条件论证）；不上收新原则** |

## 自我证成公约的预算侧修订建议（建议稿，待框架定稿裁决）【推断】

在 M1-UNIFIED §0.1 公约五条（a–e）基础上增列预算侧条款：

- **(f) 对照预算的制度保障四层链为公约级要求**（物化=J8）：比例锁定（启动时与主科目同时锁定，建议 5–10%）+ 例外程序（谁批的/理由/补跑计划）+ 过期降权（连续 N 期未补跑→待证声明标注"对照已过期"）+ 兑现率监控（入 M3 健康指标广播全框架）。
- **(g) 对照公平性的预算前提显式化**（物化=J6/J7）：跨期重跑退化基线的"等预算"以标准币定义；对照运行期的评估保底（噪声底低于最小可裁决改进量）不可被主线节流挪用——公约的"增量超 M8 噪声底"判据在预算侧被绕过的路径（压评估抬噪声底）予以封闭。
- **管辖范围追加**：标准币定义与锚传承协议（基准模型退役后的换锚规则——空白，见诚实边界 5）、有效预算率的跨 run 可比性声明格式。

## M3 是否贡献新候选不变量：否

M3 三根因全部被既有框架覆盖：根因 1 → I-谱系（物化形态贡献：成本归因谱系）；根因 2 → I-β 一半覆盖 + 自我证成公约预算侧盲区揭示（公约修订建议 (f)(g)）；根因 3 → I-β（第五投影确认 + 质量指标独立性必要条件论证）。M3 的贡献是**三个物化形态**（成本归因谱系、标准币锚定的跨期可比性制度、N11×N13 效率/健康分轴仪表盘）与**一次投影验证**（I-β 预算层第五环），不满足"跨模块投影+各自一手失效证据"之外的新原则判据——与 M1 的结论同型。

## 跨模块契约修订建议（处理深挖自报接口缺口）

> 来源：m3_deepdive.md N1/N7 证据空缺节自报的两个接口缺口 + J9 对账闭环的字段需求。全部记入 M1-UNIFIED 修订队列。

- **R1（AllocationIntent 增 budget unit 字段， MUST）**：现契约 `budget_estimate: float`（注释"单位=token 或美元，M3 口径"）为多币种账本下的二义字段——reserve 分币种预扣（N5×N1）无法执行。建议：`budget_estimate` 改为 `Dict[str, float]`（{unit: amount}，unit ∈ N1 五单位枚举）或增列 `budget_unit` 必填字段；单币种 run 由 M3 配置层填充默认值以保持向后兼容。【M1-UNIFIED §2 修订点】
- **R2（cost_account 枚举扩展+物化，MUST）**：现契约 `cost_account ∈ {explore, exploit, reeval}`（M1-H3 三账户物化点）仅覆盖 N7 七科目之三；control/handoff/repair/overhead 四科目在类型层不存在 ⇒ 隐性科目一等化（J1）与对照科目锁定（J8）无落点。建议：IntentKind 与 cost_account 同步扩为七科目封闭枚举；M1 侧须为 control 类意图（退化基线重跑/消融臂）定义签发路径（当前 G12 对照意图如何进 intent_queue 未定义——**这是公约 (f) 的执行前提**）。【M1-UNIFIED §2/§G12 修订点】
- **R3（IntentReceipt 增 executed_cost 结构化形态，SHOULD）**：现 `executed_cost: float` 单值无法承载 J9 对账闭环所需的"承诺 vs 实际 vs 产出差"三件套与分币种结算。建议：`executed_cost → Dict[str, float]`（分币种）+ 增 `settlement_report_ref`（指向台账结算条目）。【M1-UNIFIED §2 修订点】

# 任务四：诚实边界声明——M3 统一设计"知道但不解决/无据可依"清单

> 合并 m3_deepdive.md 各轴"证据空缺"节与 GB 不确定性说明，同类合并后 7 条。

1. **N13 四指标阈值零标定**（本模块最大制度空缺）：有效预算率/对账差额率/隐性科目占比/对照兑现率的"多少算超"无任何系统实现过、无失败分布可参照——首版只能以 GEPA 8.7× 这类极端值定保守上限【推断】；阈值联动（例外程序/审计/结论降权的触发线）全部待运行数据标定；健康指标自身的监控成本未估算（指标不能成为新的隐性科目——自指风险未解）。
2. **对照科目 5–10% 无消融**：保留比例只有任务设定与 GEPA 反面锚点，无"3% vs 5% vs 10%"的任何对照证据；对照保留科目在全生态零实现（GA 前沿空位 1）——四层保障链整体是空位设计，AIDE² 的预算保护决策是唯一正面旁证【厂商博客级】。
3. **N6 拒绝-重发回路与 ttl_blocks=1 的时延冲突未解**（最高优先级接口风险）：重发往返时延未量化；ttl=1 下重发意图可能出生即过期；R4 只登记冲突不裁决——若该回路实际不可用，"M3 只报价不决策"的边界刚性原则（全部接口设计的生成元）的执行层可行性受损。
4. **reserve/软阈/降级参数全线"先记账后定参"**：reserve 分位数 P50–P75（TALE 合理预算区间只在单任务测得、进化循环场景未验证、reserve 估计模型零文献）；80% 软阈（GB 提议值无实证）；保底档定值依赖 M8 噪声测量而该测量在多数系统缺位；回滚链配额上限无任何参照——全部是公理推导的占位符，触发线待运行数据标定。
5. **N14 标准币的定义与锚传承是空白**：基准模型选谁、基准模型自身退役后如何换锚（换锚本身是一次口径漂移）无先例；"现有框架均无版本戳字段"基于已知公开实现判断、未逐一代码审计【GB 自标推断成分中等】；主动对账（定期重测单位成本）本身的预算开销未估算。
6. **多币种账户族与双喂口径零运行先例**：五币种并存的运行系统实例为零（各系统均 1–2 种），N1 是空位设计；N12 双喂同源一致性是设计断言，BATS/AIRA 均为单 agent 场景、进化循环中"余量反馈给分配器"的收益无一手证据。
7. **效率指标的效度未验证**：admitted_per_usd 与最终任务性能的相关性从未被验证（它是 M2-O19 的设计断言）；cost-of-pass 在进化循环（多代、准入中间端口）中的定义无文献——Erol/Efficient Agents 均为单次任务场景；R 的分母口径（intent/块/run）同系统可差数量级，CPST 摊销口径依赖 N2/N8 全部到位方可跨系统比较。
