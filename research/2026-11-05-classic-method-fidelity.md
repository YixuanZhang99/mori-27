# GEPA and FunSearch: pinned fidelity targets

Status: source comparison, not a reproduction result. Inspected 2026-11-05. This note prepares Task 4 of `docs/superpowers/plans/2026-11-04-evidence-delivery.md`; it does not alter the MLE-first execution order or claim an external benchmark score.

## Reference identities

- GEPA official implementation: [`gepa-ai/gepa` at `3d34469165f0d604df3b48f1d5c776e9080f3da0`](https://github.com/gepa-ai/gepa/tree/3d34469165f0d604df3b48f1d5c776e9080f3da0). Its [pinned API](https://github.com/gepa-ai/gepa/blob/3d34469165f0d604df3b48f1d5c776e9080f3da0/src/gepa/api.py) defaults to instance-level Pareto selection, shuffled minibatches, reflection and round-robin component selection; merge is optional and disabled by default in that revision. The reference is actively developed, so this pin is not a claim about the exact code used for every paper result.
- FunSearch original public implementation: [`google-deepmind/funsearch` at `cc53f274237d7ab05c19df939edbc1f9616a7c19`](https://github.com/google-deepmind/funsearch/tree/cc53f274237d7ab05c19df939edbc1f9616a7c19). Its [program database](https://github.com/google-deepmind/funsearch/blob/cc53f274237d7ab05c19df939edbc1f9616a7c19/implementation/programs_database.py) groups programs by per-test score signature within islands, samples score-weighted clusters and shorter programs, and periodically resets weaker islands using founders from surviving islands. The [upstream README](https://github.com/google-deepmind/funsearch/tree/cc53f274237d7ab05c19df939edbc1f9616a7c19) says the implementation excludes the model, sandbox and distributed infrastructure; its `bin_packing` directory includes an evaluation suite.

## What this repository actually has

| Capability | Current code | Evidence boundary |
| --- | --- | --- |
| GEPA-like reflection | `m0/config/profiles/gepa_reflective.json` declares a greedy accepted pool and reflective improvement; `m0/examples/toy_gepa.py` uses a deterministic hint-encoded toy evaluator and mock model. | This exercises text feedback, not instance-Pareto selection, the official GEPA algorithm or a public benchmark. The toy score improvements are designed into the fixture. |
| Pareto building block | `m0/core/frontier/pareto.py` has a performance/cost archive; canonical evaluation can include per-item outcomes. | A performance/cost frontier is not the reference's per-validation-instance winner frontier. No existing connection proves GEPA parent sampling or paired minibatch acceptance. |
| FunSearch-like evolution | `m0/core/operator/ops.py` preserves an `EVOLVE-BLOCK` boundary; `m0/core/archive.py` assigns islands round-robin, chooses greedy parents, and periodically copies elites to the next island. `m0/examples/funsearch_offline.py` runs this using the same toy evaluator. | These are real mechanisms, but round-robin greedy migration differs from reference signature clusters, probabilistic sampling and weak-island reset. The example does not evaluate the paper's bin-packing tasks. |
| M7 runtime and accountability | Configured construction, explicit physical/currency accounting and replay are implemented in the current development branch; see `docs/CONFIGURED_CONSTRUCTION.md`. | Reuse may make a method run inspectable and recoverable. It does not establish paper fidelity, superiority, or the accounting of an unadapted external reference. |

## Minimum work before naming a reproduction

1. GEPA: define a versioned, durable candidate-by-validation-item score table with explicit ties/missing scores and deterministic seeded winner-frequency sampling. Freeze training minibatches, parent and proposal evaluation on the same minibatch, feedback provenance, acceptance rule, validation data and model call accounting. Test parent selection and compare decisions against the pinned reference on controlled matrices. Treat merge as an explicitly disabled option unless implemented and tested. Expose the actual configuration through `Framework`, not just the legacy profile label.
2. FunSearch: define a frozen program skeleton and safe editable-region contract; maintain per-test score signatures and clusters, seeded temperature sampling, short-program preference, and weak-island reset with reproducible event recording. Preserve old history instead of silently deleting it; explicitly label any adaptation to the reference's physical reset and wall-clock scheduling. Test reset, founder selection, sampling and replay against pinned examples. Use a sandbox for generated programs; the original reference intentionally leaves this integration open.
3. For each package pin exact task data, evaluator and reference revision; publish commands, settings, seeds, budgets, all outcomes and original artifacts. A fixture validates mechanics, not empirical parity. A real model run may fail or underperform and must remain visible. No paper-level claim or RUBRIC B4 closure follows until the matching public result interval is independently reproduced under a documented protocol.

The [GEPA paper](https://arxiv.org/abs/2507.19457) and [FunSearch paper](https://doi.org/10.1038/s41586-023-06924-6) provide the algorithmic context; reference-author results are distinct from results generated by this repository.
