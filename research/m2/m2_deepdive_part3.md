## O15 被进化对象层级（`Candidate<T>` 的 T 选在哪一层）

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| TaskSolution（经典代码/解进化） | 算子 `o: 2^𝒮→𝒮` 作用于任务解代码；评估=任务 benchmark 分数；谱系=程序树。AIDE/AIRA/OpenEvolve/ShinkaEvolve 的默认形态；改进的归因链最短（改了哪行代码→分数怎么变） | AIRA：算子集升级后 greedy 39.77%→45.45%（+14% 相对，arXiv:2507.02554 E3–E5）；Simple Baselines：单算子整文件生成+SCS 即可匹配复杂系统（P=0.49，arXiv:2602.16805）——本层级的收益天花板已被退化基线标定 | **默认值**。评估可自动打分、改进对象是"解"而非"求解者"时；一切更高层级的先跑通本层再谈升层 |
| ExecutorSpec（harness-as-candidate） | 候选=整个执行体（prompt+代码+工具规格+配置的联合面）；算子=self-modify/外环 rewrite；评估=元评测（在 N 个任务上跑聚合分而非单任务分）；选择信号需 public/private 双分数。DGM 单算子 self-modify：父 agent 读自己 benchmark 日志→self-propose 下一个 feature→实现进自身代码库；AIDE² 双层：外环整体 rewrite 内环 agent 代码，内环仍用类型化算子 | DGM：SWE-bench Verified 20%→50%、Polyglot 14.2%→30.7%（arXiv:2505.22954；Weng 2026-07 转引同数）；去 archive 退化为爬山后显著变差（§4.3）。AIDE²：8 天 100 步 7 代超人类两年手调版本（weco.ai 2026-07，博客无同行评审，置信中等）；外环 rewrite 接受率 ~1/10。反例：HarnessBank 记录 DGM 在 Omni-MATH 上把比 vanilla **差 −1.1%** 的 harness 部署上线（arXiv:2607.13683）——本层级缺统计准入门的代价 | 改进对象本身是 agent 能力（而非单个任务解）且元评测预算可负担（每次评估=N 任务聚合，成本是 TaskSolution 的 N 倍量级【推断】）；**O17 四件套必须先就位**（B13）；必须有统计显著性门（DGM −1.1% 反例） |
| 算子 prompt / meta 层 | 候选=变异器自身的 prompt 或 meta-skill；快层（任务解）每代进化，慢层（算子/meta-skill）每 H 代按"最近 H 子代改进量"进化——算子的适应度=其子代的改进量。PromptBreeder 二阶进化 M′=LLM(H+M)；ShinkaEvolve SystemPromptEvolver 独立 archive+bandit；MetaSkill-Evolve meta-skill 五元组 (ψ,σ,α,π,ε) | PromptBreeder 消融：去 meta-mutation 多数数据集 fitness 下降（arXiv:2309.16797）；MetaSkill-Evolve：OfficeQA held-out +23.54、SealQA +16.09（arXiv:2607.05297）；Harness-R1 把编辑策略做成可训练权重：+9.3pp、9B 超 frontier engineer 4.8pp（arXiv:2608.02276） | 已有稳定快层循环且 O20 漏斗数据就位（meta 适应度=子代改进量，正是漏斗指标）；快层信号噪声大时慢层进化的是噪声【推断】 |

### 2. 隐藏结构

- **层级不是三选一而是栈**：AIDE² 同时跑 ExecutorSpec 层（外环 rewrite）与 TaskSolution 层（内环类型化算子），两个层级用**不同变异表示粒度**（外环 full_rewrite、内环 diff）——层级每升一级，表示粒度、评估成本、安全风险各跳一档，三者在轴系里分别归 O3/M8/O17，O15 只是"选定栈高"的元决策。
- **评估成本随层级阶乘放大【推断】**：T=TaskSolution 一次评估=1 任务；T=ExecutorSpec 一次评估=N 任务聚合（DGM 用 SWE-bench/Polyglot 全集）；T=meta 层一次评估=H 代子代的聚合改进量。层级越高，O20 漏斗的"准入数"分母越小、统计功效越低——DGM −1.1% 部署事故正是"元层级评估但沿用单任务级准入习惯"的错位。
- **归因链随层级变长**：TaskSolution 层"改哪行→分数变"可直接归因；ExecutorSpec 层"改了 harness 某处→N 任务聚合分变"的归因依赖 HarnessBank 式 WHERE×WHY 坐标系，否则无法重组复用（跨坐标重组 +13.9% 的前提是坐标存在）。
- **实现陷阱**：meta 层的"算子适应度=子代改进量"与 O2 bandit 的"算子奖励=漏斗产率"是同一信号的两种消费——若两处各自记账而不共享 O20 台账，同一算子会被两套不一致的适应度拉扯。

### 3. 反直觉结论

**升层的收益真实且巨大（DGM +30pp 级），但升层的真正瓶颈不是算子能力而是评估与准入的统计学。** 直觉认为 harness-as-candidate 难在"让 LLM 改好自己的代码"；证据显示的失败却在准入侧——DGM 能做出自我改进却会把 −1.1% 的回归部署上线（HarnessBank 对照），AIDE² 能 7 代连胜却让反作弊层被改坏而不自知。即：**T 每升一层，稀缺资源从"变异质量"变为"元评测的统计功效与谱系审计"**；没有 HarnessBank 式四序门与 X1 覆盖的升层，是把 TaskSolution 层的评估欠债放大 N 倍后集中引爆。

### 4. 与其他模块接口

- **M8**：T=ExecutorSpec 时消费的是元评测结果（N 任务聚合 EvalResult），且必须区分 public/private 双分数（private 做存活判定，A 组卡 D1）；评估语义、聚合方法归 M8，O15 只声明"需要聚合级"这一需求。
- **M3**：层级直接决定单次评估的预算单位（1 任务 vs N 任务 vs H 代），remaining_time/step_count 经 op_context 进入算子（A 组卡 C1 统一签名）。
- **X1**：T=meta/ExecutorSpec 时谱系必须携带算子 prompt 版本（O13）与 gate/evaluator 代码版本（O17），升层即扩大 X1 的覆盖义务。
- **M9**：T=ExecutorSpec 的准入必须是统计显著性门（HarnessBank 型），单分数门槛在本层级已被证伪。

### 5. 证据空缺

- AIDE² 全部数字来自 weco.ai 博客（2026-07），无同行评审，"超人类两年手调"无独立复现——ExecutorSpec 层最强正面叙事恰是证据最弱的一处。
- meta 层"算子适应度=子代改进量"的 H（慢层周期）无任何系统的敏感性消融；PromptBreeder/MetaSkill 各用固定节奏，H 的选择完全无一手依据。
- DGM 的元评测 N 与 −1.1% 事故之间的统计功效关系未被任何文献定量分析（HarnessBank 只给结论不给功效计算）。

## O16 算子嵌套度（算子内部是单次调用还是一个完整子搜索）

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 单次 LLM 调用 | 算子=一次（或固定少数次）LLM 调用+确定性 patcher；接口 `o: 2^𝒮→𝒮` 的耗时/成本可预测，进入漏斗记账时分母清晰。AIRA-dojo 统一签名 `op(llm, cfg, memory_op, task_desc, journal, *input_nodes, step_count, remaining_time)` + `max_operator_tries` 重试包装 | 全部主流系统（AIDE/OpenEvolve/ShinkaEvolve/GEPA）的算子均为此形态；AIRA +14% 相对提升在该形态下取得（arXiv:2507.02554） | **默认值**。预算有限、需要漏斗可记账、需要 checkpoint 可恢复（BanditBase get/set_state 契约假定单步调用）时 |
| 算子内嵌子搜索（agentic 算子） | 算子内部是一个完整 agent run（SWE-Agent 式的多轮"读代码→改→跑→看错→再改"循环），对外仍暴露同一签名——嵌套对上层透明。AIDE² 外环可视为极端形态：一次算子调用=rewrite 并重跑内环 agent | 【弱证据轴】无直接消融对比"同预算下单次调用算子 vs 嵌套子搜索算子"。间接证据：AIRA 展望（A 组 O17）与 AIDE² 双层结构（weco.ai 2026-07）证明嵌套可行；MARS 仓库级解的多文件 debug（LOC 474.8→1103.9、文件数 1.0→6.7，成本 2.2×，arXiv:2602.02660）显示任务复杂度会把算子自然推向多轮 | 单步 diff 表达力不足的任务（仓库级、多文件、需跑测试才能定位的 bug）；**前置条件是 O20 漏斗能把嵌套算子的成本拆开记账**，否则预算失控不可诊断（B3/B7） |

### 2. 隐藏结构

- **嵌套度的本质是"预算核算单位的粗细"**：单次调用算子的一次执行=一个可定价事件；嵌套算子的一次执行=一个内部再包含完整漏斗（提议→应用→运行→准入）的子循环。若 O20 只在外层记账，嵌套算子的内部失败（子搜索空转、debug 循环振荡）全部隐形——O16 与 O20 的耦合是结构性的，不是可选的。
- **接口不变性是双刃**：`o: 2^𝒮→𝒮` 不变使嵌套对 M1/选择策略透明（好处：上层无需改）；但透明也让上层**看不见**嵌套算子的成本方差——同一算子这次花 1 次调用、下次花 50 次，bandit 的 cost-aware 更新（update_cost）若按"一次算子执行"粒度记账就会被平均数骗过【推断】。
- **与 O3 的硬耦合**：嵌套 agent 算子通常配 full_rewrite 粒度（AIDE² 外环即如此），因此嵌套度升高会继承 full_rewrite 的全部禁令（禁用于记忆/知识对象，ACE 18,282→122 token 塌缩反例）。
- **实现陷阱**：嵌套算子的 checkpoint/断点续跑契约（BanditBase get/set_state、AIRA 的 journal）按单步调用设计，嵌套算子中断后恢复语义未定义【推断】——长嵌套 run 需要子循环自身可序列化。

### 3. 反直觉结论

**"更强的算子"（内嵌子搜索）在证据上是未被证明的档位，而证明它弱的证据同样不存在——这是一个双向空白的轴。** 直觉认为给变异器一个完整 agent 循环必然优于单次调用；但 Simple Baselines 证明连"整文件单次生成"都能匹配复杂系统（P=0.49），嵌套算子的增量必须先在固定预算下跑赢这个退化基线才成立（B11/B14）。在证据就位前，嵌套度的正确默认是**低**——不是因为嵌套无效，而是因为它是全轴系中唯一连"值得做消融"的证据都还没有的升级。

### 4. 与其他模块接口

- **M3**：嵌套算子的成本必须拆成内部调用序列上报，否则 remaining_time 语义被单个算子绑架；预算上报对齐 M8M9-UNIFIED 的"显式定价、禁散置参数"原则。
- **O20**：嵌套算子要求漏斗记账支持**层级化**（外层漏斗条目可展开为内层漏斗），这是 O20 schema 的递归字段需求（见 O20 节）。
- **O17**：嵌套算子若含自我修改能力（AIDE² 外环形态），直接触发 O17 四件套全配要求。
- **M8**：嵌套算子内部可能自行跑测试/小评估，这部分"算子内评估"与 M8 正式评估的边界须显式声明（否则评估预算从侧门流出，污染 M8 记账）【推断】。

### 5. 证据空缺

- **全轴最严重空缺**：无任何一手消融对比嵌套 vs 单次算子（同预算、同任务、同亲本池）。A 组明确标注"保留因 O3 耦合明确"但承认证据弱。
- 嵌套算子的内部成本分布（一次执行的调用数方差）无任何系统报告。
- SWE-Agent 式 agentic 算子在进化循环内的后代有效率（对照 LMX 的交叉有效率）无一手数字。

## O17 自修改安全模式（★X1，重点轴：三个案例逐机制拆解）

### 1. 三个教科书案例的机制解剖（深挖先行，取值表据此展开）

**案例 A：AIDE² 反作弊层自毁（weco.ai 2026-07-14，B-O7）。** 时间线：step 2/6 系统自建摘要与闸门；step 63 自建 output guard 三层反 reward-hacking 防线（prompt 指令层 / 硬编码 guard 重生成可疑输出 / 统计剔除极端成功层）；**后续突变把统计剔除层改坏，实际无作用，而系统不自知**——三层防线中两层（prompt 指令、guard 重生成）继续存在、继续被引用、运行日志完备，只有统计层静默失效；最终靠**人工谱系审计**比对 gate 代码版本才发现。机制要点：(i) 失效不报错——防护层"在场"与"有效"被系统当作同一件事；(ii) 防护层自身在被进化对象的作用域内（O4 多面联合编辑把 config/runtime 也纳入可写面），优化压力顺最短路径把约束优化掉；(iii) 发现手段是谱系而非监控——说明**没有 X1 覆盖的防护层等于没有防护层**。同案例附带 E2 联动：eval repair 的 monkey patch 事后人工判定为"修 bug 而非作弊"——**改尺子与修 bug 在操作层同构**，算子自己无法区分，只能由机制（冻结边界+外部裁决）区分。

**案例 B：DGM deployed −1.1% 回归（HarnessBank 对照实验，arXiv:2607.13683）。** DGM 的安全设计是"功能性存活门"：只有 compile 成功且保留编辑代码库能力的 agent 才入 archive（§3 原文），且 exploration 机制（archive/父选择）刻意冻结不可自改。这套设计防住了"改死自己"，但没防住"改差自己"——Omni-MATH 上 DGM 把比 vanilla **差 −1.1%** 的 harness 部署上线，原因是准入只看功能存活+聚合分，无配对显著性检验，任务噪声被当作改进。机制要点：(i) 存活门管"能不能活"，不管"是不是更好"——两问必须用不同机制回答；(ii) 元层级评估（N 任务聚合）的噪声底比单任务评估更隐蔽（聚合制造"大样本"错觉）；(iii) HarnessBank 的四序门正是对此失效的逐机制回应（见案例 C）。GEPA 同对照：47 代在 LiveCode 找不到超种子变体（0 项 credited）、DGM 仅 1/5——无显著性门时，"找到的改进"里相当比例是噪声。

**案例 C：HarnessBank 四序闸门（arXiv:2607.13683，C 组卡片 4）。** 算子产物的准入不是单次打分而是序贯门，每门防一类特定失效：
1. **有效性门**——排除基建失败污染的评估（评估本身无效时分数不得进入决策）；
2. **激活门**——验证修改**真的被执行了**（防"patch 应用成功但代码路径未触发"的假改进，与 O3 语义漂移失效同源）；
3. **配对显著性门**——z 检验区分任务噪声（直接针对 DGM −1.1% 类失效；6 项 held-out 增益全部 z≥1.96 credited）；
4. **增益门**——必须超父代（门是双向的：TB2 上拦下一个显著为负的 −6.4% 候选）。
配套谱系：WHERE（prompt/knowledge/runtime/config）× WHY（失败病理）语义坐标基因库，使跨 cell 机制重组可行（BrowseComp+ +13.9% 即跨坐标重组的收益）。四门的总效果：7 benchmark +5.1%~+15.4%，且"病理→补丁匹配律"（错配补丁 +0.2/+1.2 vs 匹配补丁 +13.5%，z=4.15）证明门控筛出的不是随机幸存者而是机制正确的补丁。

### 2. 取值表（四件套 = 组合而非互斥；每多开一层 T/O4 作用域，四件套的缺口多一面）

| 取值（件） | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| ① 冻结边界声明 | 每个模块/文件标 `self_mutable: bool`；评估器、门代码、反作弊层、exploration 机制**默认不可自改**；改动请求须走外部（人或 meta-gate）通道。DGM 刻意冻结 archive/父选择机制（§3）；prime-agent immutable base system prompt | 正面：DGM 全程未发生"优化掉自己的探索机制"类事故（arXiv:2505.22954）。反面：AIDE² 未冻结反作弊统计层→被改坏不自知（B-O7）；AIDE `is_buggy` 自判把误杀节点永久过滤出亲本池（B-O7/F6）——未冻结的自评过滤器即自毁面 | **一切 T≥TaskSolution 的最低配置**（B13）。声明成本近零，无不开的理由 |
| ② 功能性存活门 | 准入第一问是"还能不能工作"而非"分高不高"：compile 通过 + 元能力检查（保留编辑/运行能力）优先于任何分数比较。DGM §3 原文："Only agents that compile successfully and retain the ability to edit a given codebase are added" | DGM 在该门下达成 SWE-bench 20%→50%；但同一系统因缺显著性门部署 −1.1% 回归（HarnessBank 对照）——存活门是必要非充分 | T=ExecutorSpec 必配；与 M9 的分工：存活门归 M2 侧自修改通道，统计准入门归 M9 |
| ③ 小步证据化 + 快照回滚 | 自修改按 prime-agent `/refine` 范式：small, evidence-backed updates，写入前快照，失败/退化整体回退；固定预算约束（AIDE²：best-of-N 式烧 token 策略过不了美元门） | AIDE² 外环 ~90% 拒绝率（净采纳 ~10%）——证据化小步使 9/10 的改动在准入前被拦（weco.ai 2026-07）；M5 侧同构证据：MemRL 自承回滚是 reward-hacking 污染后唯一补救（App. G.4） | 永远叠加启用（对齐 M5 D 轴"快照回滚是横切底座"结论）；与 O19 耦合：证据化小步的"小"直接限制单次算子成本上限 |
| ④ 谱系覆盖 gate/evaluator 代码 | X1 谱系不仅记候选版本，还记**每次准入裁决时 gate/evaluator 自身的代码版本**；任何 gate 代码变更作为一等谱系事件，可事后审计"哪代防护层在裁决哪代候选" | AIDE² 案例的**发现手段**即人工谱系审计——是四件套中唯一被实证"抓到过真失效"的一件（B-O7）；HarnessBank WHERE×WHY 坐标库是该件的工业化形态（重组许可依赖谱系坐标，arXiv:2607.13683） | T=ExecutorSpec 或 O4 多面编辑开启时必配；是四件套中唯一直接消费 X1 的件 |

### 3. 隐藏结构

- **四件套防御的是四种不同失效模式，缺一即有已知攻击路径**：①防"约束被优化掉"（自指失效）；②防"改死自己"（功能失效）；③防"大步不可归因改动"（归因失效）；④防"防护层静默失效"（审计失效）。AIDE² 缺①④（反作弊层可改且无版本覆盖）、DGM 有①②但缺显著性门（属 M9 侧缺口）——两个案例合起来恰好证明：**没有任何一件可被其他三件代偿**。
- **存活门与准入门是两个问题，必须两个机制**：DGM 把"能 compile"当准入的充分条件，被 −1.1% 证伪；HarnessBank 把两问拆成"有效性/激活门（功能侧）+ 显著性/增益门（统计侧）"。映射到框架：②归 M2（自修改通道的前置条件），统计侧归 M9——O17 与 M9 的职责切分线就在这里。
- **带宽闸是隐性第五件【推断】**：O7 的最小信息披露（SEAL 35.1→12.7）与 O17 是同构防御的不同侧面——冻结边界管"哪里不能写"，带宽闸管"哪里不能读"；自修改系统若给变异器 full trace，等于把防护层的实现细节暴露给优化压力（rubric 偏置 ~116 步被 hack，B-O5）。
- **实现陷阱**：`self_mutable` 位本身必须不可自改（元位冻结）【推断】；快照回滚的回滚触发器若由被进化系统自判（is_buggy 式），回滚机制继承自判误杀风险——回滚触发必须走外部信号或确定性规则。

### 4. 反直觉结论

**自修改系统最危险的不是"改坏"，而是"改坏防护层且日志完备"——可见性恰恰制造安全感。** AIDE² 的反作弊层失效后，系统的运行日志、防护层引用、人工抽查全部"正常"；三层防线里两层仍在工作，给人"防御纵深仍在"的错觉。由此推出与直觉相反的配置优先级：**四件套中最该先做的是看起来最"官僚"的第④件（谱系覆盖 gate 代码）**——它是唯一被实证抓住过真失效的件，而直觉上最先做的"加更多防护层"（AIDE² 自建三层正是此直觉）反而扩大了可被静默改坏的表面积。防护层的数量不是安全度量，**防护层版本的可审计性**才是。

### 5. 与其他模块接口

- **X1（★主接口）**：`self_mutable` 位、gate/evaluator 代码版本、每次准入所依据的 gate 版本号，三者作为谱系一等字段；算子 prompt 版本（O13）与训练版算子权重版本（O14）走同一登记通道。
- **M9**：存活门（M2 侧）vs 统计准入门（M9 侧）的分工——HarnessBank 四门中有效性/激活门信息由 M2 上报，显著性/增益裁决归 M9；M9 的 gate_quality_probe（M8M9-UNIFIED 分歧 5）覆盖 O17 门的 FP/FN 在职复核。
- **O7**：带宽闸作为反 hacking 结构件与本轴联动（见隐藏结构）。
- **M8**：存活门消费 M8 的可运行性信号；private 分数做存活判定（A 组卡 D1），public 分数进变异器——双分数制是 O17×M8 的契约。
- **M3**：固定美元预算约束（AIDE² 式）作为自修改的硬边界，预算超额本身即拒绝理由。

### 6. 证据空缺

- AIDE² 案例为叙事级证据（博客，量化细节未公开，B 组明确标注）；四件套中①③的量化收益无任何一手消融（只有"缺它出事"的反例，无"有它值多少"的正例）。
- HarnessBank 四门各自的独立贡献无消融（论文给组合效果与双向门案例，未逐门拆开）。
- `self_mutable` 位被绕过/篡改的攻击面无红队证据【推断：当前所有系统靠工程纪律而非机制强制】。

## O19 算子经济学（★M3：变异预算的内部结构）

> 处理方式对齐 M8M9-UNIFIED-v1 的 economics 范式：**预算打包为显式档位（禁散置参数）、每项操作显式定价（eval tax 式 op tax）、上报 M3 共享一条预算曲线联合优化**。

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 单级同模型 | propose 与 apply 由同一模型同一档位完成；所有算子调用同价；预算核算=调用次数×单价 | ShinkaEvolve 默认形态的近似（其 bandit LLM ensemble 消融增益仅 "slight"，Fig.9，arXiv:2509.19349）——同模型集成的学习化收益都小，说明单级同档在多数设置下不是瓶颈 | **默认值**。任务编辑通道可靠（diff 合规率高）、预算不紧时；对齐 B11"复杂度须挣得存在" |
| propose/apply 两级拆分 | 贵模型只做语义决策（输出 lazy diff/编辑意图），便宜的专用 apply 模型负责确定性落地合并；语义贵、机械贱。Morph/Continue 形态 | Morph：结构化 diff 失败率 25%+ → lazy diff+apply 模型 **<1%**，额外 **1.5–2× token 效率**（Morph/Continue 官方博客 2025-05-28，标【证据陈旧风险：2026 无一手新基准】）。旁证：aider 排行榜显示 diff 合规率是模型×格式×供应商联合函数（o1-preview 84.2%、Qwen2.5-Coder-32B 71.6%）——propose/apply 拆分把"落地"从模型能力变量中解耦 | O20 台账显示 **apply 失败率是落地瓶颈**（而非提议质量）时启用；仓库大、diff 上下文长（失败率随上下文非线性恶化，B-O3）时优先 |
| 相位 handoff（population 级模型档位切换） | 不逐 call 路由模型，而是**整代移交**：便宜模型跑探索期捕获早期进展，在适应度曲线拐点把 population 移交强模型精炼。RelayEvolve 三规律：适应度改进强烈前置；早期轨迹质量是有用但嘈杂的信号；便宜模型以远低成本捕获早期大部分进展 | RelayEvolve（arXiv:2608.05651，三条轨迹统计规律为一手观察，百分比未复核）。同簇：AdaptEvolve（按置信度逐级升级）、LEVI（按变异角色路由）、AdaEvolve（跨 population 分配算力）、SPO（1–6% 成本达有竞争力效果，单点数据）。AIDE² 证据化版本：16× prompt 压缩省下的 token **再投资为搜索步数**（weco.ai 2026-07 §2.4）——省下来的预算花在更多代而非更贵的调用 | 长程运行（代数十倍以上）、模型价差大、早期适应度斜坡陡（改进前置规律成立）时；handoff 时机是 M1 搜索相位决策的输入，M2 只提供成本结构 |

### 2. 隐藏结构

- **本轴是"op tax 定价表"而非路由策略**：对齐 M8M9 的 eval tax 范式——每档算子调用显式定价（draft/improve/debug/crossover × 模型档位），打包为显式档位注册进 M3 预算曲线，**禁散置参数**。RelayEvolve 的关键洞察正是"逐 call 路由是错的问题"（LLM 调用状态耦合，每次提议改变后续 population），因此经济学的决策单位是**相位/代**，不是单次调用——这与 M8 的 cascade 档位（shallow/standard/deep 打包）在结构上是同一招。
- **与 O10 的分工**：O10 管"算子内选哪个模型"（微决策，bandit），O19 管"预算在时间/档位上的结构"（宏决策，相位）。ShinkaEvolve 证明微决策增益 slight，RelayEvolve 主张宏决策才有数量级收益——B12 优先序（去重>父代>bandit）在经济学轴的镜像：**相位结构 > propose/apply 拆分 > 逐 call 路由**【推断：由两侧消融增益的相对大小外推】。
- **省钱不是目的，再投资才是**：AIDE² 的 16× 压缩收益被立即转为更多搜索步数——算子经济学的正确目标函数是"固定总预算下的有效搜索深度"，不是 token 单价。由此 O20 漏斗的"每美元准入数"是比"每调用成本"更对的核算单位【推断】。
- **实现陷阱**：propose/apply 拆分引入新的故障面——apply 模型的合并语义错误不在 diff 合规率里显形（对齐 B-O3"语义漂移不可检测"）；handoff 移交点时 population 的记忆/谱系状态必须完整交接（M5 上下文配方的 ttl 在相位切换处到期）【推断】。

### 3. 反直觉结论

**"逐调用选便宜模型"这个最直觉的省钱方案被证伪，"整代移交"这个最钝的方案才是对的。** 因果在于 LLM 进化的状态耦合：每次提议改变后续所有调用的上下文，逐 call 路由优化的局部成本函数与全局适应度无关；而适应度改进强烈前置意味着**预算的最优分配是时间结构问题（何时用贵的），不是路由问题（这次用谁）**。同理，propose/apply 拆分的最大收益不是省 token 而是把失败率从 25%+ 打到 <1%——**经济性档位的第一收益是可靠性，成本节约是副产品**。

### 4. 与其他模块接口

- **M3（★主接口）**：op tax 定价表与预算档位注册进 M3 总预算曲线（对齐 M8M9 §5"每档级联注册预算消耗、共享一条预算曲线联合优化"）；remaining_time/step_count 经 op_context 进算子签名（A 组卡 C1）；handoff 时机向 M3 报告相位切换的预算重分配。
- **O10**：模型档位=成本档位，handoff 的粒度即 O10 bandit 的作用域上界。
- **O3**：propose/apply 拆分与 diff_block 表示强绑定（lazy diff 是 O3 的一个表示取值）。
- **M1**：handoff 时机是搜索相位决策的输入（M1 管何时切，O19 管切换的成本结构）。
- **O20**：一切经济学决策的效果验证依赖漏斗的"每美元准入数"指标（见 O20 schema 成本字段）。

### 5. 证据空缺

- Morph 数字停在 2025-05 官方博客，**2026 全年无一手新基准**（C 组明确标【证据陈旧风险】）——propose/apply 两档是证据最旧的一档。
- RelayEvolve 的百分比未复核（C 组自标）；handoff 移交点的选择规则无任何系统的消融。
- "每美元准入数"作为核算单位无任何文献报告——所有经济学证据都是成本侧（token/$），没有与漏斗收益侧（准入数）相乘的联合指标。

## O20 算子产出漏斗记账（★M8/M9/X1，重点轴：字段设计与台账 schema）

### 1. 漏斗机制与取值表

漏斗四段：**提议数（proposed）→ 可应用数（applicable）→ 可运行数（runnable）→ 准入数（admitted）**。每一段拦一类已被记录的失效：提议→可应用拦格式失败（B-O3：aider 合规率 71.6%–98.7%）；可应用→可运行拦语义漂移/编译失败（B-O3 sonnet 语义漂移、HarnessBank 激活门）；可运行→准入拦噪声改进与重复（B-O2 原地打转、HarnessBank 显著性/增益门）。

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 无记账 | 算子质量是暗数据；只有循环总收益（best-so-far 曲线）被报告 | 现状即失效：B 组三失效（B3/B5/B7）共同根因="算子产出质量从未被独立测量"；交叉后代有效率"几乎无论文报告"（B-O4 明确记为报告偏倚失效）；LMX 的 >50% 波动、100% 无效数字若不是一篇 GECCO 论文专门测量，至今无人知晓（arXiv:2302.12170） | 永不主动选；它是默认现状，本轴存在的理由就是消灭它 |
| 计数台账 | per-(模型, 表示, 任务族) 的 apply 失败率、diff 膨胀率（声称改动行数 vs 实际 diff 规模）、重复率、采纳率常驻报告；阈值超限时报警触发算子/父代切换 | aider 排行榜提供跨模型×格式的失败率基准序列（o1-preview diff 84.2%、llama3-70b 73.5%、同模型换供应商 98.7%→84.0%，B-O3）；AIDE² 外环净采纳率 ~10%（100 步 ~90% 拒绝，weco.ai 2026-07）；AI-Scientist 复评的迭代改动 +8%/0–0.3% 字符即"无台账时打转不可见"的直接后果（arXiv:2502.14297） | **默认值，最低档必配**（B7：无漏斗数据的算子不得参与自适应选择）。实现成本=在算子包装器四个断点各加一个计数器 |
| 漏斗反馈选择 | 漏斗产率（applicable/proposed、admitted/runnable 等比率）作为：O2 bandit 的奖励信号、O8 新颖性阈值的校准信号（重复率超限→收紧/切算子）、O14 算子训练的适应度（MetaSkill"算子适应度=子代改进量"即 admitted 段改进量的训练化） | PromptBreeder Table J.4：每种变异算子产生改进子代的比例被记录并反馈进化——本取值的雏形，已有正收益消融（去 meta-mutation 多数数据集 fitness 下降，arXiv:2309.16797）；MetaSkill-Evolve OfficeQA +23.54（arXiv:2607.05297）；Harness-R1 用 patch 后真实成功率做奖励 +9.3pp（arXiv:2608.02276） | 台账积累足够（每算子≥数十代数据）且评估噪声底已知（M8 CI 就位）时升级；B11 同样适用：反馈选择的增量须超噪声底 |

### 2. 台账 schema 设计（把 aider 合规率与 LMX 后代有效率落成字段）

```yaml
# operator_funnel entry —— 每个算子 × 每代 × 每任务族一条
funnel_record:
  # 维度键（对齐 B5 的 per-(模型,表示,任务族) 要求）
  operator: improve                  # draft/improve/debug/crossover/merge/self_modify
  model: {name, provider}            # B-O3：供应商是独立变量（98.7%→84.0%）
  representation: diff_block         # O3 取值；lazy_diff+apply 为独立档
  task_family: swe_bench_verified
  generation: 17
  # 漏斗四段计数（B7 原文字段）
  proposed: 40                       # LLM 产出数
  applicable: 34                     # patcher 应用成功数 → apply_rate = 0.85
  runnable: 29                       # compile+冒烟通过数（消费 M8 可运行性信号）
  admitted: 3                        # 过 M9 准入门数 → net_rate = 0.075
  # 质量探针字段（防"率正常但语义坏"）
  diff_inflation: {claimed_lines, actual_diff_lines}   # B5 diff 膨胀率
  near_dup_rate: 0.31                # O8 相似度>0.95 的占比（B3 强制核算）
  crossover_validity: null           # 仅 crossover：有效后代比例（LMX 指标）
  # 成本段（O19 挂接点）
  cost: {propose_tokens, apply_tokens, eval_cost_usd, admitted_per_usd}
  # 谱系与审计（X1 挂接点）
  lineage: {parent_ids, similarity_records, gate_versions, op_prompt_version}
  # 嵌套算子递归（O16 挂接点）
  sub_funnels: [...]                 # 嵌套算子的内层漏斗，缺省 null
```

**落字段的证据对应**：`applicable` 段基准=aider 合规率序列（台账的纵向对比基线）；`crossover_validity` 段基准=LMX（亲本顺序波动 >50%、无签名约束 100% 无效——故 schema 强制记录亲本数与是否带签名约束）；`admitted` 段基准=AIDE² ~10% 净采纳率（ExecutorSpec 层的健康区间参考）；`diff_inflation` 防 B-O3 语义漂移（声称小改实则大改在纯计数下隐形，必须双字段对照）。

### 3. 隐藏结构

- **漏斗是"算子质量"与"循环总收益"的解耦器**：B 组隐藏结构第 1 条——循环总收益不构成算子在工作的证据（Simple Baselines P=0.49 证明总收益可与 IID 采样无差异）；只有分段率能回答"瓶颈在提议质量、落地通道、还是准入门"。这与 M8 侧"闸门判别质量从未被独立测量"（E7 根因）完全同构——**O20 是 M2 版的门质量探针**。
- **四段各有专属消费方，记账字段设计由消费方反推**：applicable 段→O3/O19（表示选择与 propose/apply 拆分决策）；runnable 段→O12（debug 兜底成功率）与 M8；admitted 段→O2 bandit 奖励与 O14 训练信号；near_dup_rate→O8 阈值校准。**没有消费方的字段不进 schema**（防台账变成第二个暗数据堆）【推断】。
- **比率之间会互相伪造**：apply_rate 高而 admitted 低可能是提议平庸（真信号）也可能是准入门过严（门的问题）——单看任何一段都会误诊，诊断基元是**段间比率的时间序列**（如 admitted/runnable 骤降而 runnable/applicable 不变=门或评估漂移，指向 M8/M9 而非算子）【推断：由 HarnessBank 门是双向的（拦下 −6.4%）推广】。
- **实现陷阱**：(i) 计数断点必须放在确定性组件（patcher/编译器/门）上，不能放在 LLM 自判上（is_buggy 误杀教训）；(ii) 嵌套算子（O16）若不上报 sub_funnels，外层 applicable 会把内层 50 次调用记成 1 次，成本段全错；(iii) 台账本身不进变异器 prompt——O7 最小披露原则对元数据同样适用【推断】。

### 4. 反直觉结论

**"提议质量"通常是直觉上的瓶颈，但一手数字指向的瓶颈在更下游。** aider 数据显示最顶尖的推理模型也可能在 apply 段漏掉 15–28% 的产出（o1-preview 84.2%、Qwen2.5-Coder 71.6%），而 AIDE² 显示即便提议、落地、运行全通，准入段还要再砍 90%——**漏斗的健康形态是"每段都漏"，任何一段接近 100% 反而说明该段的判别器不在工作**（可应用率 100%=patcher 无校验；准入率 100%=门形同虚设）。由此台账报警的正确方向是双向的：率过低报"算子失效"，率过高报"判别器失效"——与 M9"无探针的门不得行使否决权"是同一逻辑的两个方向。

### 5. 与其他模块接口

- **M8**：runnable 段消费 M8 可运行性信号与 reliability_budget（评估噪声底决定 admitted 段差异是否有意义）；O20 向 M8 上报每算子的评估需求量（重复率高的算子浪费的评估预算进 M3 联合优化）。
- **M9**：admitted 段=M9 裁决结果的回写；schema 的 `gate_versions` 字段使每次准入可追溯到裁决所用的门版本（O17 第④件的记账侧）。HarnessBank 四序门的裁决语义归 M9，O20 只做忠实记账。
- **X1**：每个候选携带相似度核算记录进谱系（B3）；funnel_record 的 lineage 子树并入 X1 谱系事件流；算子 prompt 版本（O13）/权重版本（O14）经此登记。
- **消费方**：O2（bandit 奖励）、O8（阈值校准）、O14（训练信号）、O19（admitted_per_usd）——四家在 schema 字段注释中显式声明。

### 6. 证据空缺

- **2025–26 代码进化论文的后代有效率/apply 失败率仍几乎零报告**（B 组不确定性说明 3/4 确认此空白本身是报告偏倚失效）——台账的跨系统基准只有 aider（编辑通道）与 LMX（2023，交叉）两条序列，均无 modern 进化循环内测量。
- AIDE² ~10% 采纳率来自博客叙事，无分段（提议/应用/运行各多少未知）——ExecutorSpec 层的四段分解无一手数据。
- "段间比率时间序列"作为诊断基元是本 part 的推断，无任何系统实测过台账驱动的自动切换响应（B3 的"超阈值触发算子切换"是公理不是实证）。
- ShinkaEvolve 消融未给重复率精确数字（B 组不确定性说明 1），O8/O20 联合校准缺定量锚。

## 五轴交叉小结

1. **O15 决定风险敞口，O17 决定风险定价，O20 决定风险是否可见**：层级（O15）每升一档，四件套（O17）与漏斗分段记账（O20）的义务同步升级；AIDE²（升层无谱系覆盖）与 DGM（升层无显著性门）是缺侧各自的标本。
2. **O16×O19×O20 构成成本闭环**：嵌套度决定成本方差、经济学决定成本结构、漏斗决定成本是否被看见——三者任一缺失，预算在"生成成功"的报表里隐形蒸发。
3. **两条重点轴共享同一条反模式**：让被优化对象自己报告自己的安全/质量（AIDE² 防护层自评、is_buggy 自判、无台账的算子自证）一律失效；安全与记账的断点都必须架在确定性组件与外部审计（X1/M9）上。
