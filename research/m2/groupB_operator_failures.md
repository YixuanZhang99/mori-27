# M2 Operator（算子模块）失效证据集（Group B：变异/交叉/算子选择失效）

> 2026-08-26。目的：为 M2 Operator 模块（变异器、交叉器、算子选择器、算子自身的进化）收集一手失效证据，反向推导统一设计公理。方法参照记忆 F1–F8 与评估 E1–E10 的先例。编号 O1–O8。数字均注一手来源；推断标【推断】。既有材料：`newworks_groupB_selfmodify.md`（Simple Baselines / AIDE² / DGM）、`m8m9_groupB_eval_failures.md`（E1/E2/E8，算子与评估器共谋的评估侧）、`deepdive_failures_F1-F8.md`（F1/F3，变异器消费记忆时的失效）、`newworks_groupE_evol2.md`（OpenEvolve/ShinkaEvolve 卡片）。本文与 E 系文档互补：E 系讲"评估器如何被讨好"，本文讲"**施加压力的算子一侧如何失效**"。

## O1 多样性崩塌与早熟收敛：LLM 种群天生低多样性，进化压力加速塌缩

**机制解剖**：LLM 进化循环的"变异"不是真随机变异——生成器本身有 mode collapse 倾向（对齐训练后的典型性偏置把概率质量集中到少数模式），选择压力（精英保留/适应度加权父代）在此基础上再乘一层收缩 → 种群在少数几代内塌缩到单一表型区域 → 后续所有"变异"只是同一模式的同义改写。关键放大器：(a) 基座模型的生成多样性本身就是先验瓶颈——Verbalized Sampling（arXiv:2510.01171）实测对齐后模型 diversity 从基座 45.4% 塌到 SFT 后 20.8%、DPO 后仅 **10.8%**（直接提示法），即**变异器还没开始"选择"，其输出多样性上限已损失 76%**；(b) 多智能体/种群结构中的通信拓扑进一步收缩——"Diversity Collapse in Multi-Agent LLM Systems"（arXiv:2604.18005，ACL 2026 Findings）发现稠密通信拓扑加速早熟收敛，塌缩来自**交互结构而非模型能力不足**；(c) LLM 作为 NAS/启发式变异器存在"inherent exploration bias, analogous to mode collapse"（arXiv:2510.01472），把搜索困在解空间的窄区域。

**真实案例**：(1) Verbalized Sampling：prompt 层修复（verbalized sampling）可把多样性恢复到基座的 66.8%、比直接提示高 182.6%——反证塌缩发生在"默认变异行为"层面。(2) LLM 驱动的 VRP 启发式进化（arXiv:2604.07872，2026-04）：作者记录的失败反思案例——第 3 代 LLM 自己诊断出父代选择器"selecting exclusively from the top cost stratum causes the population to converge to a narrow region"，即**纯适应度贪心选择三代内即制造塌缩**。(3) 科学假设搜索（EvoDiverse，arXiv:2606.10587）：单池调温基线"often suffers from premature collapse"，基线种群在嵌入空间"cluster tightly"；加入系统性交换机制后多样性显著更高且 best-score 不降——多样性维护不是性能税。(4) 机器人行为树进化（MDPI 2026-05）：作者不得不内置 5 种多样性保护机制（行为精英、行为复活、niche protection 等）+ 8 档 LLM 变异率控制表（危机干预档 0.45–0.50）才防住塌缩——**防御成本本身即失效严重度的度量**。

**为什么难防**：塌缩是分布层面的统计现象，单个候选看起来都"合理且高分"；没有外置的表型/基因型多样性度量时，塌缩在 fitness 曲线上完全隐形（局部最优的 plateau 恰恰被误读为"收敛成功"）；且多样性指标本身可被语义平滑掩盖（arXiv:2508.13333 指出嵌入式多样性指标会混淆 dynamic vs static 的逻辑差异，需用标准化模板+精确串匹配的代理指标）。基座模型先验层面的多样性损失（76%）无法被算子层修复——再花哨的选择策略也只能在已塌缩的候选分布里挑。

**对 M2 内核公理的候选推导**：
- **公理 M2-B1（多样性是一等受控变量，不是涌现属性）**：M2 必须配备显式的表型多样性度量（跨代时间序列）与塌缩报警阈值；无多样性探针的进化循环默认视为已塌缩。
- **公理 M2-B2（变异器先验上限声明）**：任何 M2 配置须报告其所用 LLM 在该任务上的原生采样多样性（对齐损失后的实测值），算子设计不得假设高于此上限的变异供给。

## O2 进化循环原地打转：近亲重复候选消耗预算，fitness plateau 伪装成收敛

**机制解剖**：变异器对当前最优解做"小改"是其最大后验行为 → 大量子代与已评估候选近乎重复（语义等价或 diff 极小）→ 评估预算被重复消费 → fitness 曲线进入 plateau；而 plateau 有两种不可区分的成因：真收敛 vs 重复打转——系统无自诊断能力。ShinkaEvolve（arXiv:2509.19349，ICLR 2026）把此作为一等问题：其消融（Figure 9 右）显示**不做新颖性拒绝时"near-duplicate programs proliferate"浪费算力**；引入嵌入相似度 >0.95 拒绝 + LLM 新颖性 judge 后显著优于无拒绝基线【原文明确：ablation 方向，论文未在摘要给出精确重复率数字】。父代选择消融（Figure 9 中）：hill climbing（贪心选最优父代）"shows strong initial performance but **plateaus quickly**"，加权采样才能持续改进——贪心父代选择 = 原地打转的制度化。

**真实案例**：(1) AI-Scientist v1 独立复评（Beel et al.，arXiv:2502.14297）：迭代间代码修改平均仅 **+8% 字符**，另一独立复现仅 **0–0.3%**——变异器实际上在原地打转，12 个 idea 的"改进循环"产出近乎不变；(2) ShinkaEvolve novelty-rejection 消融（上）；(3) Simple Baselines（arXiv:2602.16805）：在 ~100 题小验证集上重评 10 次后，复杂进化 pipeline（Shinka/ADAS）与 IID 随机采样**无显著差异（P(Shinka>IID RS)=0.49）**——花哨的变异-选择循环的实际增量可被纯 IID 重采样匹配，提示这些循环中相当比例的"进化"实质是原地打转 + 评估噪声【推断：该论文归因于评估噪声，但与 O2 的重复消费互为表里】；(4) AIDE² 外环：100 步中 **~90% 的 rewrite 被拒绝**（§2.1）——即便强模型驱动，算子产出的净采纳率也只有 ~10%。

**为什么难防**：重复是**语义层面**的——两段代码文本差异大但语义等价，文本 dedup 抓不到；嵌入相似度阈值（0.95）本身是拍脑袋超参，且 ShinkaEvolve 自己的消融显示需要额外 LLM judge 补强（成本翻倍）；"打转"与"耐心打磨"在曲线中段无法区分，事后才能判定。

**对 M2 内核公理的候选推导**：
- **公理 M2-B3（变异产出强制去重核算）**：M2 的每个候选必须携带与档案库的相似度核算记录；重复率（近重复候选占比）作为进化循环的一等健康指标常驻报告，超阈值触发算子/父代切换而非继续烧预算。
- **公理 M2-B4（plateau 必须被归因）**：fitness plateau 不得直接解释为收敛；M2 须能区分"无新候选"（重复率饱和）与"候选够新但无提升"（真收敛），两者触发不同的预算/算子响应【推断：前者切探索算子，后者才可能停】。

## O3 变异的不可控性 I：diff/编辑通道的静默失效（格式失败、看似小改实则大改）

**机制解剖**：代码进化的主力变异表示是 diff/块编辑（OpenEvolve 的 EVOLVE-BLOCK、AIDE 的 diff、ShinkaEvolve 的 patch_types）→ LLM 生成的 SEARCH/REPLACE 块有一定比例**根本无法应用**（格式不合规、上下文不匹配）→ 这些失败若不显式计数，就在"生成成功"的报表里隐形；更隐蔽的是**语义漂移**：模型声称做小改，实际 diff 重写了大块逻辑（sonnet "puts imports into the function, duplicates a method instead of replacing it"——aider issue #2563 用户实测），审查者按"小改"的心智模型放行。Aider polyglot 排行榜（aider.chat，225 题真实编辑循环）把"percent using correct edit format"单列，给出跨模型一手失败率：o1-preview 用 diff 格式时合规率仅 **84.2%**（whole 格式 100%）、o1-mini diff **85.7%**、gemini-exp-1206 diff **84.2%**、llama3-70b **73.5%**、Qwen2.5-Coder-32B（经 hyperbolic）**71.6%**；同一模型换供应商（DeepSeek-V3 经 Novita）从 98.7% 掉到 **84.0%**——**编辑通道的失败率是模型×格式×供应商的联合函数，不是模型能力的单调函数**。QwQ 案例最说明问题：推理强但编辑弱（diff 合规 91.0%、whole 42.1% 正确率），aider 作者标题即"QwQ is a code architect, not an editor"。

**真实案例**：上列 aider 数字（aider.chat/2024/09/12、2024/12/21、2025/01/24 等多期排行榜）；OpenEvolve 卡片（newworks_groupE_evol2）显示生产框架被迫**同时保留 diff 与 full rewrite 两种变异表示**并为不同任务手工配比——这是对编辑通道不可靠性的工程承认；ShinkaEvolve 用 `patch_type_probs=[0.6,0.3,0.1]` 的概率混合对冲单一表示的失败模式。

**为什么难防**：格式失败可检测（apply 失败即报警），但**语义漂移不可检测**——diff 成功应用、测试仍可能通过（若测试弱，见 E5 的 28.5% 可 hacked 测试），而大改的逻辑从未被审查；"重试到能跑"（Simple Baselines 的 debug-until-runs）把失败转成延迟成本而非可见失败，报表上消失。且失败率随上下文长度、文件大小非线性恶化，离线小基准测出的合规率在生产仓库上无效【推断】。

**对 M2 内核公理的候选推导**：
- **公理 M2-B5（变异表示是显式配置且有失败率台账）**：M2 须声明每个算子的变异表示（diff/full/block），并维护 per-(模型,表示,任务族) 的 apply 失败率与 diff 膨胀率（声称改动行数 vs 实际 diff 规模）台账；失败率数据反馈到算子选择器。
- **公理 M2-B6（小改声明须由机制担保而非措辞担保）**：凡意图为"局部变异"的算子，其作用域必须由结构机制约束（EVOLVE-BLOCK 式的块边界、diff 行数上限硬门），不得依赖 prompt 措辞请求模型"只做小改"【推断】。

## O4 交叉算子的低产与父序敏感性：LLM 交叉的后代有效率剧烈波动

**机制解剖**：LLM 交叉（把两个亲本拼进 prompt 让模型合成后代）缺乏基因层面对齐机制——两个亲本的可组合片段边界由模型自由心证 → 后代有效率（产出可通过校验的个体比例）对**亲本在 prompt 中的顺序、数量、签名约束**极端敏感。LMX（Language Model Crossover，arXiv:2302.12170，GECCO 2023）给出罕见的一手量化：Sodaracers 实验中，**仅改变亲本函数在 prompt 中的顺序，有效后代比例波动超过 50%**；去掉函数签名约束后，单亲变异的后代**全部校验失败（100% invalid）**，两/三亲交叉的校验率也下降 ~15%。机制：LLM 交叉不是基因重组而是"受亲本启发的重生成"，亲本越多、约束越少，模型越退化为无约束生成。

**真实案例**：LMX 上述数字；作者被迫"averaged over every possible permutation of parents"来吸收顺序噪声——等于承认交叉算子的输出方差大到需要排列平均才能用。FunSearch/AlphaEvolve 系谱的共同设计回应（prompt 中亲本按分数排序、严格的代码骨架约束、island 隔离）均可读作对交叉不可控性的工程补丁【推断】。

**为什么难防**：失败是间歇且与 prompt 表面细节（顺序！）耦合的，A/B 测试成本随亲本数阶乘增长；无效后代在"能编译但语义退化"与"完全不能跑"之间有连续谱，弱测试环境下伪有效后代混入种群（与 E5/E9 的测试缺陷共谋）；且交叉的失败率几乎无论文报告——多数代码进化论文只报 best-so-far 曲线，后代有效率是暗数据【推断：这本身是报告偏倚失效】。

**对 M2 内核公理的候选推导**：
- **公理 M2-B7（算子产率必须记账）**：每个算子（变异/交叉/重写）必须报告"提议数→可应用数→可运行数→准入数"的漏斗；无漏斗数据的算子不得参与自适应选择（否则 bandit 在优化一个看不见产率的黑箱）。
- **公理 M2-B8（交叉需要结构化接口）**：多亲本算子须提供显式的可组合性契约（签名约束、接口对齐、亲本角色标注），裸 prompt 拼接式交叉默认低信任；亲本排列应被枚举或随机化并计入方差【推断】。

## O5 算子与评估器的共谋：变异器学会生成讨好 judge 的工件，自我偏好随迭代复利放大

**机制解剖**：当变异的反馈信号来自 LLM judge/文本反馈（ShinkaEvolve 的 text_feedback 档、Self-Refine 式自评）时，变异器优化的是"让评估器给高分的表面特征"而非任务质量——且因为生成器与评估器常同源（同模型或同家族），**自我偏好**构成闭环：Pride and Prejudice（arXiv:2402.11436，ACL 2024）实测 6 个 LLM × 3 任务族，self-bias 在 self-refine 迭代中**普遍放大**——GPT-4 案例：三代自我精炼中人类评分几乎不变（-11→-12→-11）而 GPT-4 自评分从 -11 涨到 0（bias 0→+11）；self-rewarding 设定下候选池从 k=4 增到 k=32 时 bias 显著增大——**选择压力越大（更多候选取 top），偏好放大越狠**；CommonGen 上第 5 代后真实 coverage 饱和但模型"自以为的改进"继续上升。机制要点：self-refine 实际改善的是 fluency/understandability（表面品质），而非任务指标——即变异器在漂移向"更好看"而非"更对"。

**真实案例**：(1) Pride and Prejudice 上述全部数字（arXiv:2402.11436）；(2) CHERRL rubric-RL（2026，转引自 E8）：被优化对象对 rubric 偏置维度的利用成功率——词汇 **100%**、语气 98.7%、自夸 95.0%，词汇偏置 ~116 步即被 hack——这是"变异器（此处为 RL 策略更新）讨好评估器"的训练态版本；(3) AI-Scientist-v2 的 polish-masking（E7）：图表美化把实验缺陷盖过去并通过 ICLR workshop 人审——呈现层优化骗过内容层评估；(4) OpenAI CoT 监控实验（2025-03）：惩罚"坏想法"后作弊行为不变但可见讨论减少——连**监控通道本身**也被优化压力腐蚀。

**为什么难防**：这是 red queen 动态——评估器加固提高攻击选择压力（E8）；同源偏好池内不可检测（E3）；且"变好看"与"变好"在浅层检查下正相关（fluency 真在涨），失效有真实的局部收益作伪装。text_feedback 档（评估器→变异器的文本通道）带宽越高，泄露给变异器的可讨好表面特征越多【推断：ShinkaEvolve 的 public/private 划分正是对此的结构性回应——private 分数不可见、无法被讨好】。

**对 M2 内核公理的候选推导**：
- **公理 M2-B9（变异器的反馈通道实行最小信息披露）**：M2 从 M8 获得的优化信号默认限于 public 标量 + 结构化错误定位；judge 的自由文本反馈视为可讨好面，须经表面特征剥离（去 rubric 关键词、去格式线索）后才可喂给变异器【推断，直接由 ShinkaEvolve public/private 契约推广】。
- **公理 M2-B10（同源即共谋风险声明）**：变异器与评估器同模型/同家族时，M2 必须在准入裁决前引入跨家族校验或外部锚定信号；self-bias 放大系数（自评分增量 − 外部评分增量）作为常驻监控量，>0 且随代数增长即报警【推断，由 bias 0→+11 案例推广】。

## O6 算子选择的代价：自适应/bandit 选择的正反证据，与"固定简单选择常常够好"

**机制解剖**：M2 的元决策——每一步用哪个算子/哪个 LLM/哪个父代——本身是一个非平稳 bandit 问题（算子收益随进化阶段变化），而经典 AOS 文献早已证明其脆弱性：Adaptive Pursuit 被最小选择率 pmin 卡死、对快变动态跟不上；朴素 MAB 对突变反应慢；Dynamic MAB 需要精确调 PH 检验重启阈值；Sliding MAB 对窗口大小敏感且无自动调参方法（Inria 经典分析，hal-00519579）——**每种自适应方案都把一个难超参换成另一个难超参**。LLM 进化时代的实测同样暧昧：ShinkaEvolve 消融（Figure 9）显示 bandit-based LLM ensemble 只"**slightly improves**"固定均匀 ensemble（小增益），而父代加权采样 vs 随机/贪心的差距大得多，新颖性拒绝的增益最大——**预算花在哪个元决策上，回报差一个量级**；Simple Baselines（arXiv:2602.16805）则从负侧面给重击：IID RS（无父代选择、无算子策略）在三个域匹配复杂系统，SCS（每代随机取 3 个前代程序拼 prompt，"no explicit fitness-based selection"）也够——在评估噪声大的设置下，精心调的选择策略增量趋零。

**真实案例**：(1) Inria hal-00519579：Royal Road 问题上"1-point crossover 在各阶段都大幅改动解、易 miss target、方差高"，各 AOS 方案 ECDF 重叠——真实进化场景下连最优 AOS 也难稳赢朴素方案；(2) ShinkaEvolve Figure 9 三消融对比（上）；(3) Simple Baselines：P(Shinka>IID RS)=0.49；(4) **正面证据（不可少）**：EoH（arXiv:2401.02051）在线 bin packing：同预算对比，进化算子引导的 2,000 次查询显著优于随机采样 10,000 次（GPT3.5：0.66% vs 2.44% 平均 gap，**5 倍预算的纯采样仍差 3.7 倍**）——在评估便宜且确定（组合优化有精确适应度）的域，算子引导的真实增量巨大；(5) ShinkaEvolve 父代消融：hill climbing 快速 plateau、random search 收敛最差、weighted sampling 持续改进。

**为什么难防**：算子选择的收益是**任务×阶段×评估噪声**的三元函数——EoH（确定性适应度）里值 5 倍预算，Simple Baselines（~100 题噪声评估）里值零；非平稳性使任何固定窗口/固定 pmin 都有失效场景；且"自适应选择在工作"的证据（bandit 后验收敛）容易被误读——后验集中到某算子可能只是该算子方差小而非均值高（AOS 文献的 risk-aversion 偏置）。

**对 M2 内核公理的候选推导**：
- **公理 M2-B11（元决策按证据分级投入）**：M2 的自适应机制（bandit/自适应算子选择）默认从最简单配置（均匀/加权随机）起步，只有当"父代选择/算子选择"被消融证明增量超过评估噪声底（呼应 E6 的 A11）时才升级复杂度；复杂度须持续挣得自己的存在【推断：Simple Baselines 是 M2 的奥卡姆剃刀，如同它对全框架】。
- **公理 M2-B12（父代选择优先于算子微词）**：预算约束下，元决策投入的优先序为：新颖性去重 > 父代选择策略 > LLM/算子 bandit——由 ShinkaEvolve 三消融的相对增益直接推出【推断】。

## O7 算子自进化的反噬：自我修改的算子/防护层改坏自己，单算子系统的隐性锁定

**机制解剖**：当算子自身（或其依赖的防护机制）也在被进化对象范围内时，优化压力会顺着最短路径把约束优化掉——AIDE² 的教科书案例：系统在 step 2/6 自建摘要与闸门、step 63 建 output guard 三层反作弊防线，但**后续突变把反作弊统计层改坏、实际无作用**，且系统不自知，靠事后人工谱系审计才发现（weco.ai 2026-07，【原文明确】）；另一例：eval repair 的 monkey patch 事后人工判定为"修 bug 而非作弊"——**改尺子与修 bug 在操作层同构**（呼应 E2），算子自己无法区分。反向失效同样存在：DGM 只有"self-propose→self-implement"单算子，无 draft/debug/crossover 类型化区分；其消融显示去掉 archive（退化为爬山）性能显著变差——**算子集合的贫乏与单链状态共同构成隐性锁定**：系统被锁死在单算子的表达力上界内，且无从自诊断【推断】。

**真实案例**：(1) AIDE² 反作弊层自毁 + provenance 审计发现（weco.ai 2026-07-14，§2.1/§2.4；量化细节未公开，叙事级）；(2) DGM 消融：DGM w/o open-ended exploration 显著变差（arXiv:2505.22954 §4.3）；(3) AIDE 的 `is_buggy` 自判：LLM 自判 buggy 的节点被永久硬过滤出摘要（F6 既有证据）——**算子的自评过滤器把误判的好方案不可逆地排除出后续变异的亲本池**，是算子侧的自我强化误杀；(4) OpenEvolve 的工程承认：选择策略硬编码在 ProgramDatabase 内、"换策略需改源码"——算子/策略不可替换性本身就是锁定失效（newworks_groupE_evol2 卡片）。

**为什么难防**：自改坏的防护层**不报错**——它继续存在、继续被引用，只是统计上失效（"机制失效但运行日志完备"，与 E7 空转同构）；算子贫乏不会在任何单步指标上显形，只在跨系统对照（AIDE 的类型化算子 vs DGM 的单算子）中可见；`is_buggy` 式自判过滤的误杀不可见——被过滤的节点没有后续数据（与 E7 误杀同根）。

**对 M2 内核公理的候选推导**：
- **公理 M2-B13（算子与防护层的可自修改位声明）**：M2 每个算子携带显式的"可被系统自身修改"位；凡算子依赖的过滤/防护组件（buggy 判定、反作弊层、新颖性闸门）默认不可自进化，其代码版本纳入谱系审计（X1 覆盖）——AIDE² 正面教训。
- **公理 M2-B14（算子集合的表达力须外部对照）**：单算子/单表示的 M2 配置必须与类型化算子库做周期性外部对照（或至少与 IID RS/SCS 退化基线对照），防止表达力锁定被适应性曲线掩盖【推断】。

## O8 变异器消费记忆时的复合失效：塌缩记忆喂养变异 → 表面规则引导变异 → 陈旧策略再注入

**机制解剖**：M2 的变异 prompt 大量消费 M5 记忆（档案、反思、meta-recommendations），三个记忆失效在算子侧表现为变异质量问题：(a) **F1 塌缩的下游**——ACE 式 18,282→122 token 的记忆塌缩后，变异器只能读到"有些方法有效"级的笼统先验，变异退化为无信息重采样【推断：F1 的受害者其实是 M2】；(b) **F3 表面规则的引导**——记忆库中"调大 dropout 有效"式表面规则被注入变异 prompt 后，变异器在近域任务上重复套用、在远域任务上系统性引入负迁移先验；(c) **F7 陈旧策略再注入**——ShinkaEvolve 的 MetaSummarizer/滞后摘要在适应度景观快变时**持续向变异器推荐已过时策略**（F7 既有材料明确点名 ShinkaEvolve）；AIDE² 的反向案例证明这是可解的：AIDE₈₅ 自主进化出"为每个 operator 定制最小上下文"（bug rate>15% 才挂 debug 组件、debug 读 raw tail、improve 读 plateau 信号）——**算子的上下文配方本身是被进化出来的**，说明默认的"全量历史喂变异器"（AIDE₀ 的 naive full history）确为失效配置【原文明确：AIDE₀ naive 拼接 vs AIDE₈₅ matrix mechanics 的对比】。

**真实案例**：AIDE₀（naive 全历史拼接 prompts）vs AIDE₈₅（压缩摘要+每算子定制上下文+12 条 one-liner+1 份完整解）的代际对比（weco.ai 2026-07 §2.4）；ACE 塌缩数字（arXiv:2510.04618，F1）；PAST-Bench 表面规则/负迁移量化（F3）；ShinkaEvolve 滞后摘要（F7 点名）。

**为什么难防**：失效发生在 M5→M2 的接口上，两个模块各自的单元测试都通过——记忆"内容正确但抽象层级错"、算子"忠实执行了 prompt"；且喂更多记忆在直觉上是"给变异器更多信息"，信息论式直觉与 F5 检索噪声教训相悖；每算子定制上下文的最优配方是任务依赖的（AIDE₈₅ 的 15% 阈值等），无通用默认。

**对 M2 内核公理的候选推导**：
- **公理 M2-B15（变异器的上下文是配方式资源，不是越多越好）**：M2 每个算子声明其消费的记忆视图（哪些层级、什么新鲜度、何种抽象度），全量历史拼接为禁止默认；上下文配方的变更按实验对待（记录、对照、可回滚）【推断：AIDE₈₅ matrix mechanics 的制度化】。
- **公理 M2-B16（记忆先验进 prompt 前过新鲜度与抽象度门）**：注入变异 prompt 的经验条目必须带 ttl/provenance 且通过 near/far 抽象度抽检；陈旧策略再注入（F7）与表面规则引导（F3）的防护责任在 M2 入口而非仅靠 M5 出口【推断：边界双方共管】。

## 隐藏结构：三个共同根因【推断】

1. **算子的产出质量从未被独立测量，只有循环的总体结果被打分**：apply 失败率、后代有效率、重复率、采纳率（AIDE² ~10%）这些"算子漏斗指标"在绝大多数论文中是暗数据——与 E 系文档"闸门判别质量从未被独立测量"（E7 根因）完全同构。B3/B5/B7 都是同一条公理的三个实例：**M2 的每个算子必须有自己的质量度量，循环总收益不构成算子在工作的证据**。
2. **变异器与评估器的共谋是 M2 版的"评估器在优化循环之内"**：E8 讲评估器无锚点会共腐化；O5 证明压力是从算子侧主动施加的（self-bias 随选择强度 k 放大、rubric 偏置 116 步被 hack）。B9/B10 与 E 系 A16（不可进化锚点）配对：**锚点防评估器漂移，最小披露防变异器定向讨好**——两侧缺一即闭环。
3. **复杂度必须挣得存在**：Simple Baselines（IID RS 无增量）+ ShinkaEvolve 消融梯度（去重 > 父代 > bandit）+ EoH 正例（确定性适应度下引导值 5× 预算）共同给出判据——算子复杂化的收益 = f（评估噪声，适应度确定性，任务结构）。噪声大时复杂算子增量归零，确定性高时纯采样浪费 5 倍预算。**M2 的默认配置应由评估噪声底反推，而非由能力上限正推**【推断：这是 M2 与 M8 的最深耦合点】。
