## O8 新颖性闸与重复核算（原 A-O12）

**一句话定义**：子代进入评估前的近重复拦截机制——决定"评估预算是否烧在已经评过的东西上"。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 无闸 | 子代不做任何去重，直接进评估队列 | AI-Scientist v1 独立复评（arXiv:2502.14297）：迭代间代码修改平均仅 **+8% 字符**，另一复现仅 **0–0.3%**——无闸系统的"改进循环"实质原地打转；ShinkaEvolve 消融（Fig.9 右，arXiv:2509.19349）：无拒绝时 "near-duplicate programs proliferate" | 仅作为对照基线，证明闸的必要性；生产配置禁用 |
| embedding 相似度拒绝（阈值 ~0.95） | 子代代码/解 embed 后与档案库算 cosine，超阈值直接拒绝、不进评估；拒绝事件计入漏斗 | ShinkaEvolve Fig.9：**三消融中收益最大的单项**（>父代加权采样 >LLM bandit）；配合其 150 次评估即超 AlphaEvolve（原需数千次）的整体效率，去重是该效率的主要来源之一【推断】 | **默认档**。任何评估有成本的循环 |
| +LLM novelty judge | embedding 粗筛后，边缘 case 再过一次 LLM 判"语义是否等价" | ShinkaEvolve 消融：只带来**边际提升**，不值额外一次 LLM 调用（A 卡 A2 引用） | 语义重复极难判（同功能完全不同实现大量存在）且预算宽裕时；默认关 |

### 2. 隐藏结构

- **闸与 O2 原地打转是同一失效的两半**：O2 的 fitness plateau 有两种不可区分成因（真收敛 vs 重复打转），新颖性闸是把两者变成可区分的唯一机制——闸的拒绝率本身就是 plateau 归因信号（B4：重复率饱和→切探索算子；候选够新但无提升→才可能真收敛）。所以闸的真正产出不是"省下的评估费"，而是**一条可归因的诊断曲线**。
- **阈值 0.95 是拍脑袋超参**，必须用 O20 的重复率台账动态校准：拒绝率过低（<5%）说明阈值太松或变异器塌缩，过高（>50%）说明变异器已无新供给能力，两种情况都要触发算子/父代切换而非调阈值本身【推断，由 B3 推广】。
- **embedding 指标的陷阱**：arXiv:2508.13333 指出嵌入相似度会混淆 dynamic/static 逻辑差异（两段语义不同的代码嵌入很近）——新颖性闸用嵌入是"宁可误杀不可漏放"的保守选择，但对代码任务应优先行为级判据（同输入同输出）或 AST 级 diff【推断】。这与 O9 探针的指标选择问题同根（见 O9 隐藏结构）。

### 3. 反直觉结论

**LLM judge 不值一次调用，而"笨"的嵌入阈值反而是正确默认**——直觉上语义重复需要语义判断，但 ShinkaEvolve 消融显示嵌入粗筛已捕获绝大部分收益，judge 的增量边际。深层原因：新颖性闸的目的不是精确判重，而是**打断"对当前最优做小改"这一最大后验行为**（B-O2 机制解剖），粗闸已足够改变变异器的有效先验；精确判重的价值被 O20 的重复率台账替代（事后归因比事前精判便宜）。

### 4. 与其他模块接口

- **消费 M8**：闸的下游就是评估队列，闸省下的预算=M8 的可支配预算；
- **向 X1 登记**：每个候选携带与档案库的相似度核算记录（B3），使谱系可回答"这个候选与谁重复过"；
- **×O20**：重复率台账是 O20 漏斗"提议数→准入数"之间的一段；拒绝率超阈值触发 O2/O11 切换；
- **×O9**：新颖性闸管"单个候选 vs 档案"的局部去重，O9 管"种群分布"的全局多样性，两者指标互为诊断（闸拒绝率飙升是种群塌缩的前兆信号）。

### 5. 证据空缺

- 阈值 0.95 的跨任务敏感性无一手消融（ShinkaEvolve 仅在 circle packing 等任务验证）；
- "行为级/AST 级去重 vs 嵌入去重"的对比实验不存在——2025–26 代码进化论文普遍不报告重复率（B-O2：这本身是报告偏倚）；
- LLM judge"边际提升"无精确数字（原文仅方向性结论）。

## O9 多样性维护（新，B-O1 盲区补轴）★重点轴

**一句话定义**：种群的表型/基因型多样性是否被显式测量、报警与主动维护——A 组 18 轴完全没有这一维，是 Group B 从失效反推出来的盲区轴。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 无探针 | 只看 fitness 曲线，多样性是涌现属性、无人测量 | 塌缩在 fitness 曲线上**完全隐形**：plateau 恰被误读为"收敛成功"（B-O1）；Simple Baselines（arXiv:2602.16805）P(Shinka>IID RS)=0.49 提示相当比例的"进化"实质是塌缩后的同义改写+评估噪声【推断】 | 仅作对照。B1：无多样性探针的进化循环**默认视为已塌缩** |
| 探针监控 | 跨代时间序列的表型多样性度量 + 报警阈值；指标用标准化模板 + 精确串匹配代理（避免嵌入指标混淆 dynamic/static，arXiv:2508.13333） | 必要性由三方失败反推：(a) VRP 案例（arXiv:2604.07872）第 3 代 LLM **自己诊断出**贪心父代导致塌缩——若无探针，连诊断都依赖变异器偶然自白；(b) Verbalized Sampling（arXiv:2510.01171）证明变异供给上限本身已塌缩（见下）；(c) 多智能体稠密拓扑加速塌缩（arXiv:2604.18005，塌缩来自交互结构而非模型能力） | **最低档必配**（B1）。任何运行 >5 代的循环 |
| 主动维护 | 探针报警触发结构干预：EvoDiverse 系统性交换；niche protection/行为复活/行为精英；危机档变异率调节 | EvoDiverse（arXiv:2606.10587）：单池调温基线种群在嵌入空间 "cluster tightly"、常早熟塌缩；加系统交换后多样性显著更高**且 best-score 不降**——多样性维护不是性能税；机器人行为树进化（MDPI Robotics 15(5):98）：作者内置 **5 种**多样性保护机制 + **8 档** LLM 变异率表（危机干预档 0.45–0.50）才防住塌缩——防御成本本身即失效严重度的度量；PromptBreeder：随机串前缀 + BERT fitness sharing + 温度 1.0–2.0 自适应 ±0.2（arXiv:2309.16797） | 长跑（>20 代）、单池结构、或探针已报警时 |

### 2. 隐藏结构

- **三层塌缩放大器叠加**（B-O1 机制解剖，是本轴的核心结构）：(a) **先验层**——对齐训练使基座模型生成多样性从 45.4% 塌到 SFT 后 20.8%、DPO 后仅 10.8%（直接提示法，损失 76%）；(b) **算子层**——"对当前最优做小改"是变异器最大后验行为，无闸时近重复增殖（O8）；(c) **选择层**——贪心/精英父代选择再乘一层收缩（VRP 案例：纯 top 选择 3 代内种群收敛到窄区域，且是 LLM 自己在失败反思中诊断出来的）。**任何一层的花招都无法补偿另一层的塌缩**：再花哨的选择策略也只能在已塌缩的候选分布里挑（B-O1）。
- **先验层塌缩可用 prompt 部分修复**：Verbalized Sampling 实测 verbalized sampling（让模型显式输出分布再采样）把 DPO 后多样性维持在 ~30%、恢复到基座的 66.8%、比直接提示高 **182.6%**【新搜：research.rudrite.com 对 arXiv:2510.01171 的解读，含 Tulu-70B 逐阶段消融；原文数字与 B-O1 一致】——即 B2"变异器先验上限声明"不是死约束，声明上限的同时也声明了修复手段的预算。
- **指标选择是陷阱**：嵌入多样性指标混淆 dynamic（行为/输出）与 static（文本形态）差异（arXiv:2508.13333），语义平滑会把塌缩抹平——探针必须用标准化模板 + 精确串匹配/行为级代理指标，与 O8 新颖性闸的嵌入陷阱同根但方向相反（闸要保守误杀，探针要保守防漏）。
- **通信/种群拓扑是被忽略的变量**：多智能体塌缩来自交互结构而非模型能力（arXiv:2604.18005）——岛模型（O11 取值）本质是"用拓扑买多样性"，主动维护的交换机制（EvoDiverse）本质是"用受控通信赎回多样性"，两者是同一旋钮的两端【推断】。

### 3. 反直觉结论

**多样性维护不是性能税，反而常常免费甚至增益**——直觉上探索/利用权衡意味着多样性付费，但 EvoDiverse 实测交换机制提升多样性同时 best-score 不降；反例方向同样反直觉：**塌缩的代价不可见**——它不表现为性能下降，而表现为"fitness plateau 被误读为收敛成功"，系统会在自我感觉良好中停止进步。另一个反直觉点：塌缩的第一报警人竟然是变异器自己（VRP 案例中 LLM 第 3 代自诊断出父代选择问题）——但**依赖变异器自诊断等于把探针的责任外包给被监控对象**，这正是要把探针做成外置结构件的理由（与 E 系"评估器不能自证"同构）。

### 4. 与其他模块接口

- **×O11（最强耦合）**：贪心父代选择是塌缩的**制度化来源**——VRP 三代塌缩的直接原因不是模型而是选择公式；O9 探针的首要消费方就是父代选择器（报警→切换加权/岛采样）；
- **×O2**：塌缩报警应触发算子切换（提高 draft/crossover 比例）；
- **×O8**：闸拒绝率飙升 = 探针的先行指标；
- **消费 M1**：父代选择公式的参数（归 M1）是 O9 干预的执行端，O9 只供给报警与多样性时间序列；
- **×M5**：作用域记忆按算子切换（A 卡 C1，sibling 记忆促多样性）是 M5 侧的多样性干预手段，O9 探针为其提供触发信号。

### 5. 证据空缺

- 三代塌缩（VRP）是**单一案例的失败反思叙事**，无系统性的"塌缩代数 vs 选择强度"曲线；
- "探针报警阈值取多少"无任何一手标定证据——所有系统都报了机制没人报阈值；
- EvoDiverse 的"多样性升 best-score 不降"在科学假设搜索单域验证，代码域未复现；
- 行为树 8 档变异率表（MDPI）是工程经验值，无消融证明每档的必要性。

## O10 算子内 LLM/参数选择（原 A-O10）

**一句话定义**：算子调用内部用哪个模型、什么温度等超参的决策机制——注意与 O2（选哪个算子）和 O19（预算的相位结构）三方分权。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 固定模型 + 固定超参 | 所有算子调用同一模型同一温度 | 零开销基线；ShinkaEvolve 消融证明它对 bandit 只输 "slight"（见下）——固定档输得不多 | **默认档**。评估噪声中等、预算有限时 |
| BanditBase 式 cost-aware UCB | 有状态 bandit 对象：`select_llm / update / update_cost / get_state / set_state`，状态入 checkpoint 契约支持断点续跑 | ShinkaEvolve Fig.9：bandit LLM ensemble 仅 "**slightly improves**" 固定均匀 ensemble——三消融中增益最小（新颖性拒绝 > 父代加权 > bandit，B12 投入优先序末位）；Inria AOS 经典分析（hal-00519579）：每种自适应方案把一个难超参换成另一个难超参（pmin/PH 阈值/窗口大小各有失效场景） | O20 台账显示模型间真实产率差异 > 评估噪声底时升级 |
| 超参可自进化（PBT 式） | 温度等超参随种群进化：PromptBreeder 温度 1.0–2.0 随进化自适应变异 ±0.2；算子有效性统计反馈进化（Table J.4） | PromptBreeder 消融：去 meta-mutation 多数数据集 fitness 下降（arXiv:2309.16797）——但获益归于 meta 层整体，温度自进化的独立贡献未分离【证据空缺】 | 长程运行、与 O13 可进化 prompt 联动时 |

### 2. 隐藏结构

- **三处"选模型"决策的切分是本轴最易混淆处**：O10 管单次调用内（逐 call 档位）；O19 管预算在时间上的相位结构（RelayEvolve 证明"下次调用用哪个模型"是错的问题，对的问题是"population 何时移交"——调用状态耦合使逐 call 路由的前提不成立）；O2 管算子。三者混为一谈是常见的实现错误。
- **bandit 的奖励来源决定其意义**：无 O20 漏斗数据时 bandit 在优化一个看不见产率的黑箱（B7）——模型后验集中到某档可能只是该档方差小而非均值高（AOS risk-aversion 偏置，B-O6）。
- **状态持久化是隐形刚需**：bandit 的 get/set_state 必须入 checkpoint 契约（A 卡 B2），否则断点续跑后选择历史清零、bandit 退化为均匀采样——这个实现陷阱无任何论文报告，但所有无持久化的 bandit 实现都中招【推断】。

### 3. 反直觉结论

**在模型选择上花预算，回报比去重和父代选择低一个量级**（B12，由 ShinkaEvolve 三消融相对增益直接推出）——直觉上"给贵任务配贵模型"是最自然的优化方向，实证上它是三消融中最弱的。原因：单次调用的模型档位差异大部分被评估噪声淹没（Simple Baselines：噪声大时一切选择策略增量归零），而新颖性与父代结构改变的是**候选分布本身**。推论：O10 的正确默认是"把省下的复杂度预算投给 O8/O11"。

### 4. 与其他模块接口

- **×O19**：模型档=成本档，O19 的相位 handoff 决策以 O10 的档集为动作空间；
- **×O13**：prompt 可进化时 bandit 作用域须含 prompt 版本（模型×prompt 是联合臂）；
- **消费 M3**：cost-aware UCB 的 cost 项来自 M3 预算记账；
- **×O20**：bandit 奖励=漏斗产率，B7 规定无漏斗数据的算子/模型档不得参与自适应选择。

### 5. 证据空缺

- ShinkaEvolve bandit 增益仅 "slight"，无精确数字（Fig.9 图内数值未读，B 组已标注）；
- 温度自进化（PromptBreeder ±0.2）的独立消融不存在；
- 2026 前沿簇（AdaptEvolve 置信度升级、LEVI 角色路由）相对收益数字未复核（C 卡 6 标注）。

## O11 亲本选择（原 A-O11，与 M1 交界）

**一句话定义**：算子输入亲本的采样公式。**职责切分（按轴系原则 4 显式化）：选择算法/公式归 M1 Policy；本轴只定义 M2 侧的"亲本池构造与信号供给"——M2 向 M1 承诺提供什么样的候选池（带什么字段、什么质量门、什么多样性结构），以及亲本选择的结构需求（Pareto 前沿、岛结构、互补性配对），公式参数（温度、权重系数）进 M2 配置但选择过程本身在 M1 执行。**

### 1. 取值表（取值 = M2 供给 M1 的亲本池结构方案）

| 取值 | 机制展开（M2 侧义务） | 量化证据 | 何时选 |
|---|---|---|---|
| 贪心 best | 亲本池=当前 top-k，无多样性过滤 | hill climbing 在 ShinkaEvolve 消融中 "shows strong initial performance but **plateaus quickly**"；VRP 案例：纯 top 选择 **3 代内塌缩**（arXiv:2604.07872）——贪心是原地打转的制度化（B-O2） | 仅短程 exploitation 相位或对照基线 |
| 加权采样（供给 rarity/子代数字段） | M2 向谱系查询并供给 `F(p) ∝ reward × (1+α·children_count 或 children_variance) × rarity` 所需的全部字段：子代计数、子代方差（OpenRSI 用作内在动机）、稀少度 | ShinkaEvolve 父代消融三档排序：**weighted > hill climbing > random**，且只有 weighted 持续改进（Fig.9 中）；OpenRSI 同公式族（A 卡 B2） | **默认档**。M2 必须保证 rarity 与 children_count 在谱系中可查——这是本轴对 X1 的硬需求 |
| Pareto-per-instance | M2 维护"每个 problem instance 上最优"的前沿而非全局最优池 | GEPA：Pareto 候选选择是其超 GRPO +10%、35× 样本效率机制的一部分（arXiv:2507.19457）；防止单一全局最优吸干选择概率【推断】 | 多 instance/多目标评估、instance 间难度差异大时 |
| 岛比例采样 + 迁移 | M2 维护多个隔离亲本池 + 周期性迁移事件 | FunSearch/AlphaEvolve 式隔离；EvoDiverse 证明受控交换维持多样性不伤 best-score（O9）；多智能体塌缩证据（arXiv:2604.18005）反证无隔离的稠密拓扑加速塌缩 | 长跑、评估便宜、任务多模态时 |

### 2. 隐藏结构

- **M2 侧的真正产物是"字段契约"不是公式**：加权公式需要的 rarity、children_count、children_variance，Pareto 需要的 per-instance 最优表，岛需要的 pool 标签——全部是谱系/档案的 schema 需求。若 X1 谱系没记子代计数，M1 的任何加权公式都无法实例化。**亲本选择失效的第一现场往往是字段缺失而非公式错误**【推断】。
- **crossover 的亲本选择是独立决策**：双高分父代往往同构、交叉退化为重写（A 卡 A4【推断】）；GEPA+Merge 按"互补 lesson"选 Pareto 前沿两候选，再 +8.16%（IFBench）——crossover 父选按**互补性（差异大/覆盖互补）**而非双高分。
- **亲本池质量受 O12 污染**：`is_buggy` 自判硬过滤把误判的好方案不可逆排除出亲本池（B-O7）——亲本池构造必须消费"带复活通道"的失败标记而非布尔硬过滤，两轴的接口是同一字段。
- **O9 的执行端**：O9 探针报警后，最便宜的干预就是 M1 侧切父代公式（贪心→加权/岛）——O9 供给信号，本轴供给可切换的结构选项。

### 3. 反直觉结论

**random 垫底说明"远离最差"比"靠近最好"更重要**：ShinkaEvolve 三档排序 weighted > hill climbing > random 中，贪心和随机各踩一个极端——贪心 3 代塌缩（供给太窄），random 收敛最差（无质量信号）。加权采样的本质是把"子代数/稀少度"当作**已开采程度的折现因子**，即亲本选择的最优结构不是适应度函数而是**适应度×新鲜度的联合分布**。另一个反直觉点：评估噪声大时亲本选择的增量整体趋零（Simple Baselines）——先修 M8 噪声底再调父代公式（B11）。

### 4. 与其他模块接口

- **公式与执行归 M1**（轴系原则 4）；M2 输出：亲本池 schema（rarity/children_count/per-instance 最优表/岛标签）+ 结构需求声明（Pareto/岛/互补配对）+ 公式参数默认值；
- **×X1**：所有供给字段由 X1 谱系记账产生——本轴是 X1 字段需求的主要提出方；
- **×O9**：父代选择是多样性第一调节阀（轴系原文）；
- **×O12**：buggy 标记语义（可复活 vs 硬过滤）决定亲本池下限；
- **×O5**：作用域记忆与亲本共同决定子代看到的多样性（A 组强耦合备忘）。

### 5. 证据空缺

- 加权公式中 α、rarity 定义各家不同（ShinkaEvolve vs OpenRSI），无横向对照；
- "crossover 父选按互补性优于双高分"是【推断】（A 卡 A4），GEPA Merge 的 +8.16% 是间接证据；
- 岛模型的迁移频率/比例无一手消融（FunSearch/AlphaEvolve 论文均未单独消融）。

## O12 失败子代处理（原 A-O14）

**一句话定义**：算子产出不可运行/校验失败后的处置策略——丢弃、修复、还是冻结只修。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 丢弃 | 失败子代直接丢弃，烧掉的生成成本沉没 | 最简单；但 AIRA 式系统中 buggy 子节点是重要信号源，丢弃=浪费生成成本+丢失失败归因素材（A 卡 A4） | sandbox 任务、评估极便宜、失败率 <10% 时 |
| debug 兜底循环（上限 N_d / 时限） | 失败子代自动进 debug 算子，保持原思路、消费错误日志/traceback，上限次数或时限后放弃 | AIRA：buggy 子节点自动进 debug，上限 **10 节点或 12h**（A 卡 A4）；E 组旁证：所有成功系统都给 crossover 子代接 debug 兜底——**无任何系统报告 crossover 子代 compile/pass 率高于 improve**【推断，A 卡 A4】 | **默认档**。有 traceback 等结构化错误信号时 |
| buggy 节点冻结只许修 | buggy 节点打标记冻结，只许作为 debug 输入、不许作为 improve/crossover 亲本 | 防 undo-redo 振荡（AIRA debug 看祖先链的设计动机，A 卡 C1）；但 AIDE 教训：`is_buggy` **LLM 自判** buggy 的节点被永久硬过滤出亲本池——自评过滤器把误判的好方案不可逆排除，自我强化误杀（B-O7） | 振荡实测发生时；判定必须可复活 |

### 2. 隐藏结构

- **debug 兜底的真实功能是信号回收而非成本节约**：失败子代 + traceback 是变异器最便宜的归因素材（消费 M8 错误定位信号），丢弃策略丢掉的不只是生成成本而是 O6 反思管线的输入。
- **is_buggy 判定是"谁当法官"问题**：AIDE 用 LLM 自判→不可逆误杀；AIRA 用"执行失败"这一**环境事实**判定→零误判。结构原则：失败判定只能来自环境（compile/run 结果），LLM 判断只能做**优先级排序**（先修谁），不能做准入硬过滤（B-O7 教训的制度化【推断】）。
- **上限的超参形态**：AIRA 用双上限（节点数 ∨ 时限），这是把 M3 预算约束内嵌到算子层——debug 循环是 M2 内部唯一可能失控烧预算的环路，上限不是保守而是必需。
- **失败率是 O20 漏斗的第二段**："可运行数/提议数"之差的修复成功率（debug 兜底的命中率）是漏斗一等指标——无此记账则无法区分"算子烂"与"任务难"。

### 3. 反直觉结论

**失败子代的价值可能高于成功子代的平均值**——crossover 子代既然无人报告其 pass 率高于 improve，crossover 的净收益大部分由 debug 兜底兑现【推断，由 A 卡 A4 归纳】；即交叉算子的真实形态不是"融合"而是"融合+修复"复合管线，debug 不是异常处理而是交叉的正常末段。同时，**修复上限内的失败不算失败**：AIDE² 外环 ~90% 拒绝率下系统整体仍在改进（weco.ai 2026-07）——失败子代处理的正确 KPI 不是修复率而是单位预算的净采纳率。

### 4. 与其他模块接口

- **消费 M8**：结构化错误定位（traceback/compile error）是 debug 算子的输入，受 O7 带宽契约约束；
- **×O20**：debug 修复成功率是漏斗"可应用→可运行"段的记账；
- **×O11**：buggy 标记语义决定亲本池下限（保留复活通道）；
- **×M1**：debug 节点的调度优先级（buggy 叶回访概率 debug_prob）是搜索策略决策，归 M1。

### 5. 证据空缺

- debug 兜底修复成功率无系统报告（AIRA 给了上限没给命中率）；
- "上限 10 节点/12h"是单一系统经验值，无敏感性分析；
- "crossover 子代 pass 率低于 improve"是**阴性证据**（无人报告），非正面测量。

## O13 算子 prompt 管理与可进化性（原 A-O13）★进入 X1

**一句话定义**：算子的 prompt 是代码内嵌、配置即数据、还是自身可进化对象。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 代码内嵌 | prompt 硬编码在算子源码里，改动=改代码 | OpenEvolve：选择策略硬编码在 ProgramDatabase 内、"换策略需改源码"（newworks_groupE_evol2，B-O7 引用）——不可审计、不可 A/B、不可回滚，**不可替换性本身就是锁定失效** | 仅原型期；任何要跑对照实验的系统禁用 |
| Jinja/YAML 配置即数据 | prompt 模板外置为配置文件，版本化、可 A/B、可回滚；变更按实验对待（记录、对照、可回滚，B15 原则同样适用） | AIDE₀→AIDE₈₅ 代际对比：prompt 配方（每算子定制上下文）的变更带来 +14% 级系统差异且可逐代归因（weco.ai 2026-07 §2.4）——只有配置化才能做这种归因 | **默认档**。一切严肃实验 |
| 可进化（独立 archive + bandit） | 算子 prompt 自身是被进化对象：ShinkaEvolve `SystemPromptEvolver`（变异用 system prompt 有独立 archive + 独立 bandit）；PromptBreeder 二阶自指进化 M′=LLM(H+M)（meta-mutation prompt 自身被进化） | PromptBreeder 消融：去 meta-mutation 后多数数据集 fitness 下降（arXiv:2309.16797）；ShinkaEvolve 150 次评估超 AlphaEvolve（arXiv:2509.19349，meta 层是三创新之一） | 长跑 + 评估便宜 + O20 漏斗已就位（prompt 版本的产率可分辨）时升级 |

### 2. 隐藏结构

- **三取值的真实分界是"变更的归因能力"**：内嵌档无法回答"这次改进是 prompt 改了还是模型变了"；配置档可回答但需人工做对照；可进化档把归因自动化（prompt 版本 × 产率台账）。所以本轴与 O20 是硬耦合：**无可进化 prompt 的产率分辨能力时，开可进化档=引入不可归因的漂移源**。
- **可进化 prompt 的防护位**：B13 规定凡算子依赖的过滤/防护组件（buggy 判定、反作弊层、新颖性闸 prompt）默认**不可自进化**——O13 的可进化位必须逐 prompt 声明，AIDE² 反作弊统计层被突变改坏而不自知的案例（B-O7）正是"防护 prompt 也被进化"的直接后果【推断】。
- **二阶进化的结构**：PromptBreeder 的 M′=LLM(H+M) 说明"prompt 的进化"自身需要一个 mutation prompt——可进化档不是一档而是递归深度选择（进化到第几层停止），多数系统停在一阶（prompt 进化、meta-prompt 固定）。

### 3. 反直觉结论

**"配置即数据"的收益大于"可进化"的边际收益，且前者是后者的前提**——直觉上可进化 prompt 是更高级形态，但 ShinkaEvolve 的 meta 层收益在三消融中并非最大项（新颖性拒绝才是）；而 OpenEvolve 式内嵌锁定的代价（无法 A/B、无法回滚）是灾难性的。即：先把 prompt 从代码里拿出来（配置化），收益立现且为零风险；再谈进化，且进化必须以配置化的版本基础设施为前提。

### 4. 与其他模块接口

- **向 X1 登记（硬义务）**：每次变异记录所用算子 prompt 的版本号，谱系边标注 (operator, prompt_version)——否则跨代归因不可能；
- **×O14**：prompt 可进化是算子可学习性的轻量档（prompt 空间进化 vs 权重空间训练）；
- **×O10**：prompt 可进化时 bandit 臂 = (模型 × prompt 版本)；
- **×M5**：可进化档的 archive 复用 M5 的条目/检索基础设施【推断】。

### 5. 证据空缺

- PromptBreeder 消融只报方向（"多数数据集下降"），无逐数据集数字；
- "prompt 版本 × 产率"的联合分辨需要多少样本量，无任何统计分析；
- 工业界"变异 prompt 变更审批流"无一手披露（C 组空白标注）。

## O14 算子可学习性（新，C1）★重点轴 ★部分进入 X1

**一句话定义**：算子的产出分布是固定 prompt 程序，还是可训练的权重/可被同一管线递归进化的 meta 对象——这是 2026 年打破"算子=固定 prompt"隐含假设的新轴。

### 1. 取值表

| 取值 | 机制展开 | 量化证据 | 何时选 |
|---|---|---|---|
| 固定 prompt 算子 | 算子=人工/进化出的 prompt 程序，权重不动 | 全部经典系统默认（AIDE/AIRA/OpenEvolve/ShinkaEvolve/DGM）；Simple Baselines 证明其在噪声评估下与复杂系统等价（P=0.49） | **默认档**。无训练基础设施、评估噪声大、或 O20 漏斗数据不足以支撑训练信号时 |
| SFT/RL 训练的编辑策略 | 把"失败轨迹→可执行 patch"做成专用模型的可训练能力。Harness-R1 全管线【新搜：arXiv:2608.02276 正文】：冻结目标 agent → 挖掘失败轨迹打包成 failure packet → 9B engineer 生成可执行 runtime patch（4 个生命周期 hook：episode init / pre-decision / pre-action / post-feedback）→ patch 校验安装后**冻结目标在同一批任务上重跑** → 奖励=全 batch 性能差 Δ（无效/no-op/不完整=0）→ 冷启动 SFT（GPT-5.5 teacher 产 ~877 条可执行编辑样例）+ 在线 GRPO（每 packet 采 K=8 候选，组内归一优势，~1500 个 failure packet，8×H800） | Harness-R1（arXiv:2608.02276）：冻结 Qwen3.5-9B 目标在 WebShop/ALFWorld/DBBench 均值 **44.3%→53.6%（+9.3pp）**；比监督版 engineer 高 7.1pp；**9B 训练版超最强 frontier engineer GLM-5.2（48.8%）4.8pp**；目标 SFT 变强后重训专属 engineer 仍 +5.0pp（59.2→64.2）；**20 个未见目标 agent 平均 +7.06pp，21 目标矩阵 63 组合中 56 改善、4 持平、3 回归（均 ≤2.0pp）**；稀疏证据（仅 10 条失败）下 held-out 1270 任务 **+8.9±1.5pp，而两个 frontier engineer 平均为负**（方差 ±2.5/±3.6，在边际增益与显著回退间摇摆）；案例研究：frontier patch"合理诊断编译出降低成功率的行为"（App. H）——**只会写 plausible 的 patch，不会写 effective 的 patch** | 有：可重跑的确定性评估环境 + 失败轨迹挖掘 + RL 基础设施；目标模型冻结或昂贵不可训时收益最大 |
| meta 算子双时间尺度进化 | 改进过程本身提升为一等进化对象：每分支携带 meta-skill m=(ψ 诊断, σ 跨分支检索, α 子代预算, π 编辑提案, ε 应用+校验)；任务 skill 每代进化，**meta-skill 每 H 代按"最近 H 个子代的改进量"进化——算子的适应度=其子代的改进量** | MetaSkill-Evolve（arXiv:2607.05297）：五个 pipeline agent 共享单一冻结 backbone，相对 raw backbone 的 held-out 提升 **OfficeQA +23.54、SealQA +16.09、ALFWorld +1.92**，超 no-skill/static-skill/单层进化全部基线 | 不训练权重但要算子自适应的中间档；多分支并行进化结构已就位时 |

### 2. 隐藏结构

- **核心机制创新是奖励的定义，不是模型**：Harness-R1 的 reward = patch 应用后冻结目标的**同批重跑真实任务成功率差**——这把"算子质量"从代理信号（plausibility、judge 评分）变成结果接地信号，正面回答了 frontier engineer 失败的原因："他们优化 plausibility，从不重跑目标，所以无法知道编辑是否真的提升成功率"（论文 §5 Discussion【新搜】）。**算子可学习性的本质是 O20 漏斗"产率"被提升为可微分的（经 RL 的）训练目标**。
- **9B 胜前沿工程师的深层含义**：信号来源 > 模型规模——"the signal comes from outcomes rather than model scale"（论文原文【新搜】）。这推翻了 M2 的一个默认假设（变异器越强越好，O10 的上游假设）：在结果接地训练面前，模型档位是次要变量。与 B12 优先序（去重>父代>bandit）合读：**M2 的预算优先序顶端应该再加一条"结果接地的算子训练信号"**【推断】。
- **稀疏证据泛化是最被低估的数字**：10 条失败 → held-out +8.9±1.5pp 且三个种子全正，而 frontier 平均为负——说明可学习性的收益不在"见过更多"而在**"病理→干预"映射被学成了能力**（与 HarnessBank 的"病理→补丁匹配律"+13.5%（z=4.15）跨工作互证，C 卡 4）。
- **双时间尺度的时间结构**：MetaSkill-Evolve 的"快（子代每代）/慢（meta 每 H 代）"结构解决的是算子适应度的信用分配——单个子代改进不能归因于算子（噪声太大），H 代聚合才可。这给出了"算子适应度"的可操作定义：**算子的适应度=其最近 H 个子代的改进量均值**，正是 O20 漏斗指标的直接消费（轴系原文）。
- **可学习档的失效模式是新的**：固定 prompt 算子失效是"不够好"，可训练算子失效是"过拟合训练批"——Harness-R1 自承 reward 是 same-batch transductive 目标、无跨 batch 持久 patch 记忆（§3.1），其 held-out 验证（App. F）正是对这个失效的防护【新搜】。

### 3. 反直觉结论

**最强的算子不是最大的模型，而是被结果信号训练过的小模型**——9B 超 GLM-5.2 计 4.8pp、在稀疏证据下 frontier 为负而 9B 稳定为正，直接否定"用更强 frontier 模型当变异器"这一 2024–25 默认配置。进一步：**算子的能力是与其服务的目标 agent 解耦的资产**——同一训练配方迁移到 20 个未见目标全正增益（无一例需要 per-target 重调），说明"编辑能力"可以脱离"被编辑对象"单独学习，算子第一次成为可携带资产（类比 M5 轴 E 的跨模型记忆迁移 3.5×）。

### 4. 与其他模块接口

- **消费 O20（硬依赖）**：算子适应度=子代改进量，即漏斗"提议→准入"的产率指标——无 O20 记账则无可训练信号，轴系默认值（固定 prompt）的前提正是"先有漏斗数据"；
- **向 X1 登记**：训练版算子的权重版本（checkpoint id + 训练数据批指纹）进 X1 谱系，与 O13 的 prompt 版本号并列；
- **消费 M5**：failure packet 的挖掘/压缩是记忆检索问题（Harness-R1 的 deterministic extractor 保留失败轨迹的任务约束+动作观察摘录【新搜】）；
- **×M3**：训练预算是独立科目（~877 SFT 样例 + ~1500 RL packet + 8×H800 单节点是 Harness-R1 参考成本【新搜】）；GRPO 每步 K=8 候选 × 同批重跑，评估成本是普通变异的 8 倍量级——M3 必须为此单列预算；
- **×M8**：奖励信号直接来自评估重跑，M8 的噪声底决定训练信号质量下限。

### 5. 证据空缺

- Harness-R1 仅三个交互 benchmark（WebShop/ALFWorld/DBBench），**代码进化域（M2 主战场）未验证**——"编辑策略可训练"在 patch harness 上成立，在"变异程序候选"上的对应物不存在；
- same-batch transductive 奖励的多轮迭代（目标变强→重训→再变强）只验证了一轮（+5.0pp），长期共演化动态未明（论文自列为 future work【新搜】）；
- MetaSkill-Evolve 的 H（聚合窗口）无敏感性分析；+23.54 的 baseline 强度（raw backbone）较弱；
- 训练版算子被 reward hacking 污染的情形无证据（奖励=真实重跑，天然抗 hacking，但 same-batch 过拟合是其等价风险）。

## 七轴交叉的三个结构性结论

1. **O8/O9/O11 是同一塌缩问题的三层防线**：O8 管入口（重复拦截）、O11 管选择压力（父代结构）、O9 管测量与报警（探针）——三层共享同一组证据（45.4%→10.8%、3 代塌缩、hill climbing plateau），任何单层都不充分（先验层塌缩 76% 已封顶变异供给，B2）。
2. **O20 漏斗是 O10/O13/O14 三条"学习化轴"的共同前提**：bandit 选模型（O10）、prompt 可进化（O13）、权重可训练（O14）的学习信号全部来自漏斗产率——"算子质量从未被独立测量"（Group B 根因 1）是三条轴共用的证据空缺根源。
3. **O14 的出现重排了 M2 预算优先序**：原优先序（B12：去重 > 父代 > bandit）假定算子是固定 prompt；Harness-R1 证明"结果接地的算子训练"的收益（+9.3pp、稀疏证据 +8.9±1.5pp）超过任何 prompt 层调优——**一旦评估可重跑且有 RL 基础设施，O14 训练档应排在 O10 bandit 之前**【推断】。
