## K1 Ground 车道触发时机与策略

### 1. 取值表

| 取值 | 机制展开（怎么工作） | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 构想前离线建库 | 先建领域级结构化知识（ToI EvoGraph 引文演化树 / KAPSO learn 建 MediaWiki+Neo4j+Weaviate 双索引 KB），构想时读库而非读原文。最贵、结构化程度最高，把"检索"变成"读图" | ToI：6 主题均分 6.27 vs 最强基线 5.36（人类参考 6.29），去 gap 建模 −0.72、去跨轨迹信号 −0.65（arXiv:2608.10740，GC-K §6a）；KAPSO：2000+ 仓库语料、条目带 SOURCE_REPO/commit provenance（arXiv:2601.21526，GC-K §3） | 领域冷启动且任务簇可复用（一次建库多次摊销）；或需要 gap 地图级结构化证据（K11 最高档）时必选 |
| 构想中可选工具 | 检索做成 intent 化工具挂给 coordinator，agent 自主决定何时查（Arbor grounded lane / orx-lit）；工具在隔离上下文中运行，只回压缩 digest | Arbor `ResearchSearch` 4 intent + 隔离上下文设计【原文】；Arbor 该车道默认 off（GC-K §1）——"可选"的价值以"可不用"为前提 | **默认**。预算有限、评估噪声中等的标准场景；M6 收益不确定时，按需触发把成本方差控制在调用侧 |
| 构想中强制注入 | 每轮变异 prompt 固定挂知识段（R&D-Agent memory context 的外部版即 KAPSO KR：`K_base(g, r̂)` 每轮返回有界类型化页面集） | R&D-Agent 消融：w/o Memory Context 仅 −9%（35.1→32.0 Any Medal），而 w/o Reasoning Pipeline −24%、w/o Exploration Path −28%（arXiv:2505.14738 §4.3，GC-K §4）——常驻注入的边际贡献有限且受消费管线制约 | 仅当消费管线（M2 侧上下文配方）已被消融验证时；否则常驻成本换不来稳定增益 |

### 2. 隐藏结构

- **时机选择的本质是"知识成本的可方差化"**：离线建库把成本前置且不可关，强制注入把成本均匀摊到每轮（token 账单随步数线性涨），可选工具+失败触发把成本集中在"信息缺口真实存在"的时刻。R&D-Agent 的 −9% vs −24% 对比说明：**知识的边际贡献 ≈ 消费管线质量的函数，而非注入频率的函数**——时机加密不能代偿管线薄弱（DA §二.1）。
- **"构想后 veto 闸门"作为 ground 时机已被证伪并移出本轴**：AI-Scientist 把检索放在构想后当新颖性闸门，判定粒度（≤10 条关键词元数据 + LLM 一票）决定其 12/12 漏报（2502.14297）；该位置的所有 veto 语义已归入 K7 并标记禁止取值。本轴只保留"启发/修复"语义的时机。
- **触发信号的来源决定本轴与 M8 的耦合深度**：失败触发档的 `s` 必须是 M8 的结构化失败信号（错误类型/复现性），若 s 只是"分数没涨"级别的模糊信号，ERA 式检索会退化为噪声触发的预算泄漏【推断】。
- 实现陷阱：可选工具档的实际调用率完全由 prompt 措辞与工具可见性决定——orx-lit 用 "start here" skill 注入才保证宿主 agent 真的先查文献；无偏好注入的"可选"实际等于"不用"（GC-K §5【推断】）。工具注册时必须同时注册使用时机偏好。

### 3. 反直觉结论

**"更早、更多、更常驻"的知识接入不是单调改进——R&D-Agent 的常驻记忆注入只值 −9%，而被淘汰的 veto 式后置（AI-Scientist）反而是负价值**。时机轴上收益最高的两个点恰好在谱系两端：最前置的离线建库（ToI，+0.91 绝对分）与最后的失败触发（ERA），共同点是把知识接入绑定到**具体的信息缺口事件**（建库时的 gap 建模 / 失败时的诊断需求），而非绑定到循环节拍。常驻注入之所以弱，是因为它回答的是一个没被提出的问题【推断：这把 K1 的默认组合钉在"可选工具+失败触发"而非"全程组合"】。

### 4. 与其他模块接口

- **消费 M8**：失败触发档的 s 由 M8 失败信号提供；评测模式标识（benchmark 模式强制本轴 off）也由 M8/M9 传入（×K9）。
- **消费 M3**：常驻/每轮注入的 token 成本进预算核算科目；失败触发的检索深度档位随剩余预算调节（×K6）。
- **×K10**：失败触发即 M5×M6 ERA 联合入口——同一信号同时路由 M5 `recall(signal)` 与本轴 repair 检索。
- **×M2**：本轴只决定"何时可取"，取到的内容如何进变异 prompt 归 M2-O5 上下文配方；M6 不拥有消费逻辑（定稿边界）。

### 5. 证据空缺

- ToI 的 6.27 vs 5.36 混杂了"离线建库"与"gap 信号卡格式"（K4）两个变量，时机档的独立贡献未分离——消融去的是 gap 建模/跨轨迹信号，不是"离线 vs 在线"。
- KAPSO 无公开消融分离三点位（初始化锚定/每轮 KR/失败 ERA）的各自贡献。
- "可选工具"档在不同 LLM 上的实际调用率/查询质量无任何系统报告（Arbor 只有设计声明）。

## K2 车道隔离结构（硬约束轴）

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 单车道混合（**禁止取值**） | 同一检索结果既启发又作证：构想期读过的文献集合被拿来判"novel"——自我指涉的循环论证 | AI-Scientist：12/12 idea（含 micro-batching for SGD、adaptive learning rates、e-fold cross validation 等已确立概念）全判 novel（arXiv:2502.14297，GC-K §2）——单车道+浅判定是隔离不存在的直接后果 | 任何场景均禁止 |
| 逻辑分离（**禁止取值**） | 两次检索但共享缓存/抓取文本/session——第二次检索的排序与摘要已被第一次的阅读历史污染，"独立"只存在于调用次数上 | 【推断，根因证据充分】Arbor 设计文档明确 "never share fetched text" 作为隔离定义，隐含共享文本=不隔离；2606.12071 发现 comparative judging 会系统性偏袒已见过的生成物（win rate 27.2%→49.1%）【新搜】——同一 judge 见过前文即产生偏好，共享文本的审计同理 | 任何场景均禁止 |
| 两车道零共享 + 字段分离 | ground 与 audit 各自独立检索、独立上下文、独立抓取文本；落地字段分离 `node.grounding` vs `node.related_work`，谱系中分别溯源 | Arbor 是目前唯一显式一手实现【原文】（GC-K §1）；其设计陈述即本轴的公理化表述："the same page can't both inspire an idea and certify it as novel" | **唯一合法默认（定稿边界，无降级档）** |

### 2. 隐藏结构：禁降级硬约束的工程实现

"两车道零共享"不能靠实现纪律，必须落到三层机制（对标 M2-O17"结构约束必须有谱系/审计兜底"的 AIDE² 教训——反作弊层被改坏而不自知）：

1. **字段分离（数据层）**：IdeaNode schema 中 `grounding` 与 `related_work` 是两个独立字段，类型不同（grounding=list[digest_ref]，related_work=AuditVerdict 对象），写入路径不同（ground 车道只能写 grounding，audit 车道只能写 related_work）。写入权限按车道做调用方校验——工具层面 ground 车道的 `query()` 返回对象**结构上不含**可写入 related_work 的句柄。
2. **独立检索上下文（运行时层）**：audit 由专门 SearchAgent 执行全新搜索（"so it can't be fooled by whatever grounded ideation read earlier"，Arbor【原文】）。工程要点：(a) 两车道使用独立的检索 session/缓存命名空间，禁止共享 HTTP cache 与 embedding cache 的键空间；(b) audit 的 query 构造**不得包含** ground 车道的 digest 原文——只能从 idea 文本本身构造查询（否则 digest 内容经查询词泄漏进 audit 上下文，形成软破窗）；(c) audit 语料集 ⊇ ground 语料集（×K8），防止审计只查"自己用过的子集"。
3. **静态检查（部署层，K16 的落点）**：启动时校验两车道 backend 配置独立、上下文对象类型隔离、落库字段分离；运行时做抓取文本哈希台账重叠扫描（audit 产物与 ground 历史抓取比对，重叠即报警作废 verdict）。隔离的承诺必须可被检测，否则就是文档修辞。

### 3. 反直觉结论

**隔离的价值不在防"作弊"，而在防"诚实但循环的论证"**——没有 agent 会故意用同一页面自证新颖，但只要两车道共享抓取文本，审计的"未找到先验"就只是在说"构想期没读过这篇"，verdict 的信息量坍缩为零且不产生任何报错。更反直觉的是：**AI-Scientist 的 12/12 误判表面上死于"关键词浅检索"，深层死因是单车道结构本身**——它的检索只面向"确认这个 idea 相关文献很少"，查询词由 idea 自己生成，命中即非 novel、不命中即 novel，判定函数与构想函数同分布，漏报是结构必然而非参数失误【推断：这解释了为何其 10 轮×10 条的"加预算"修复无效】。

### 4. 与其他模块接口

- **进 X1 谱系**：grounding / related_work 分别携带来源 ID 与打开记录落谱系，"灵感来源"与"先验审计"可分别溯源、分别作废。
- **×K8**：本轴是结构声明，K8 是检索执行面的落实；K2 的零共享靠 K8 的独立 fresh search 兑现。
- **×K16**：隔离违规检测是本轴的验证层——无 K16 则 K2 只是配置承诺。
- **×M2**：M2 算子读 `grounding` 字段做变异上下文（O5），读 `related_work` 只用于 merge 报告与 citation context，两字段的消费路径同样分离。

### 5. 证据空缺

- Arbor 的隔离仅有设计文档声明，无运行时验证机制的公开报告（K16 根因证据【推断】）；也无"隔离被违反时会发生什么"的受控实验。
- "逻辑分离（共享缓存）到底污染多少 verdict 质量"无定量测量——禁止取值的依据是机制推断+单车道实证，中间档的失效幅度是暗数据。

## K3 来源混合与后端配置

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 纯公共文献库 | Semantic Scholar / alphaXiv / OpenAlex / bioRxiv，关键词或全文检索（AI-Scientist、orx-lit） | AI-Scientist 仅 Semantic Scholar 关键词检索（≤10 条元数据）是其漏报根因之一（2502.14297）；orx-lit 提供 alphaXiv/OpenAlex/bioRxiv 全文免登录检索（GC-K §5） | 最低成本起步；学术领域且任务与文献强相关时 |
| 文献 + 通用 web | Arbor 默认 `[alphaxiv, jina]` 全免 key 组合；alphaXiv URL 走 SDK 全文，其余走 Jina reader（PDF 也能读） | Arbor backend 协议【原文】：有序列表、结果合并去重（GC-K §1） | **默认起步档**。零 key 配置即可运行，web 源覆盖文献库收录延迟（2026 新工作） |
| + 代码仓库语料 / 策展知识库 | KAPSO：2000+ 常用数据/ML 仓库语料 + MediaWiki 策展 KB，Neo4j（图）+ Weaviate（向量）双索引，条目带 SOURCE_REPO/路径/commit provenance | KAPSO 语料规模与 provenance 字段【原文】（GC-K §3）；知识不只回答"世界已知什么论文"，还回答"环境/实现/惯用法" | 任务需要实现级知识（环境约束、API 惯用法、替代实现）；有建库预算（×K1 取值①） |
| 有序 backend 列表 + 静默降级 | 缺 key 后端静默跳过，结果合并去重；backend 列表本身可配（alphaxiv/jina/serper/exa/exa-mcp/自托管 endpoint） | Arbor backend 协议【原文】 | 部署环境 key 可用性不稳定时必配；与任意上档叠加 |

### 2. 隐藏结构

- **来源集是 K8"更广文献"承诺的物化载体**：轴系约束"audit 语料集 ⊇ ground 语料集"（ToI 教训：novelty 检查须面向 broader literature beyond Tr），因此后端列表必须按车道分别配置——ground 可以是文献+web 的经济组合，audit 必须在其上扩（至少加 OpenAlex 级别的宽覆盖源），两列表的包含关系应进 K16 静态检查【推断】。
- **静默降级是双刃剑**：缺 key 静默跳过保证可运行性，但也意味着来源覆盖悄悄缩水——同一份配置在有无 SERPER key 的两台机器上实际是两个不同来源集，audit verdict 的可比性被破坏。降级事件必须落台账（进 X1 的 verdict 元数据："本次审计实际覆盖了哪些后端"），否则 K14 的误判率台账混杂来源覆盖变量【推断】。
- **来源决定 provenance 可追性的上限**（×K12）：仓库语料天然带 commit 级 provenance（KAPSO），web 抓取只有 URL+抓取时刻，文献库有 DOI/版本——混合来源的 packet 必须按来源类型分级标注可追性强度，不能把 web 来源与文献来源等权引用。

### 3. 反直觉结论

**最贵的来源（策展 KB + 仓库语料 + 双索引）服务于"约束与修复"，而不是"新颖性"**——KAPSO 的全部重型来源投资换来的能力是 seed 锚定、环境约束、失败修复（Principle/Implementation/Environment/Heuristic 四类型），它明确"不声称 novelty"；而服务新颖性判定的 AI-Scientist 只用了最轻的 Semantic Scholar 元数据。即：**来源投资的正确方向由车道语义决定**——ground 车道的修复/约束意图值得重来源，audit 车道要的是"宽"（覆盖）而非"深"（结构化），把策展 KB 的钱花在 audit 上是错配【推断】。

### 4. 与其他模块接口

- **×K12**：来源类型决定 provenance 链路与"未打开来源丢弃"规则的可执行粒度。
- **×K8**：audit 来源集 ⊇ ground 来源集的约束在本轴配置层落实，K16 负责校验。
- **×M3**：需 key 后端（serper/exa）的调用费与 web 抓取的 token 成本进预算科目；静默降级使成本科目自带下限保护。

### 5. 证据空缺

- 各来源组合的检索质量（命中率/召回相对人工金标）无任何系统公开对比；Arbor 的 `[alphaxiv, jina]` 默认仅有"免 key"工程理由，无质量论证。
- "audit 来源集扩多少才够"无定量答案——ToI 的 beyond-Tr 是定性声明。

## K4 注入格式（反收敛的核心旋钮）★重点轴

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| flat RAG 拼接（**禁止默认**） | 检索到的摘要/原文段落直接拼进构想上下文 | 2605.27905 大规模实证：5 框架 × 5 LLM 生成 **219,655** 个 idea，四一致发现——AI idea 比同领域人类论文**更集中**、更贴近起始文献、与未来人类方向对齐更差、位于历史生态位**低影响区**（arXiv:2605.27905，GC-K §6b）；ToI 动机即批评 "treat papers as unstructured context"（GC-K §6a【原文】） | 仅作对照基线保留（K15 消融协议的 off 档） |
| 压缩 digest | 检索在隔离上下文中运行，冗长原文不进主窗口，只返回 summary + findings + 编号来源（Arbor）；从源头压缩上下文占用与克隆表面 | Arbor digest 设计【原文】；配合"未打开来源丢弃"（K12）防幻觉 | **默认起步档**。前置成本最低；保留"可选工具"语义下 agent 可不消费 |
| gap/约束/失败模式信号卡 | 注入的不是方案而是**未解问题的结构化证据**：EvoGraph 建引文图选 frontier → EvoTrace 重建分支化学术演化树（沿路径记录"推进了什么/解决哪个局限/遗留什么 gap"）→ EvoAgent 产出两类信号卡（convergent / cross-link），附 ≥2 独立轨迹证据 + 非显而易见闸门 | ToI：6 主题 6.27 vs 最强基线 5.36（人类 6.29）；消融：去 gap 建模 **−0.72**、去跨轨迹信号 **−0.65**（arXiv:2608.10740）——信号卡的两个结构成分各自贡献真实增益 | 成熟档（默认演进目标）。前置：离线建库（K1 取值①）在位；K15 监控在位（格式变更按实验对待） |
| 类型化 bounded packet | KAPSO KGKnowledge：四类型（Principle/Implementation/Environment/Heuristic）+ typed edges（IMPLEMENTED_BY/USES_HEURISTIC/REQUIRES_ENV）+ 置信度 + provenance（query_used/source_pages）+ ERA 附件 | KAPSO  packet schema【原文】（GC-K §3）；其价值在"有界"——bounded 集合天然限制注入体积与污染半径 | 实现/修复语义为主时（与 repair intent、ERA 联合入口配套）；纯启发场景其类型体系对 gap 表达力不足【推断】 |

**gap 信号卡 schema（ToI 结构的本框架物化）**：

```yaml
signal_card:
  gap_id: str                    # 稳定标识，进 X1 谱系
  kind: convergent | cross_link  # 共享 gap / 跨轨迹桥接
  statement: str                 # gap 内容：遗留什么未解、为何卡住
  evidence:                      # 硬约束：≥2 条独立轨迹
    - {trace_id, paper_id, path_excerpt}   # 演化树路径片段，非方案文本
    - {trace_id, paper_id, path_excerpt}
  trajectory_independence: bool  # 两条证据不得同谱系（单谱系延续被拒）
  non_obviousness_gate:          # 非显而易见闸门
    collapses_to: str | null     # 若可还原为教科书式组合，命名其坍塌到的先验方法
    structural_novelty: str      # 组合给不出的结构性质（填不出即拒）
  constraints: [str]             # 环境/资源约束（可来自 KAPSO 式 Environment 条目）
  failure_modes: [str]           # 已知失败模式（与 M5 pitfall 条目对齐，分标来源）
  provenance: {query_used, source_pages, opened: [url+ts]}  # K12 契约
  ttl: duration                  # gap 时效（生态位会移动）
```

### 2. 隐藏结构

- **2605.27905 收敛效应的机制解剖**：219,655 个 idea 的四一致负发现不是"LLM 不会创新"，而是**注入表示对生成分布的一阶矩拖拽**——flat 拼接把"已有方案的文本表面"放进上下文，下一 token 预测天然向高密度区域（起始文献的邻域）集中，于是 idea 系统性贴近起始文献、落在历史低影响区。四发现是同一条机制的四个投影：集中度↑（分布方差被先验压缩）、起始文献距离↓（一阶矩被拖向注入文本）、未来对齐↓（先验是过去时）、低影响区（高密度=已被充分开采的生态位）。推论：**任何"方案文本可见"的注入格式都在不同程度上继承这个拖拽**，digest 只是减弱（压缩降低表面可克隆性）而非消除；只有信号卡把注入内容换成"gap/约束"——即把先验从"答案的分布"换成"问题空间的地图"——才改变拖拽方向（GC-K §9【推断】的"注入方案→克隆；注入 gap/约束→扩大探索"是对此的压缩表述）。
- **ToI 两条硬门槛是信号卡的"防退化闸"**：≥2 独立轨迹证据防"单篇论文的 limitation 小节被当成领域 gap"（单谱系延续被拒）；非显而易见闸门（必须命名坍塌到的先验方法+陈述组合给不出的结构性质）防"两方法拼接伪装成 gap 方向"。没有这两道闸，信号卡会退化为"引用更多的 flat RAG"——消融 −0.72/−0.65 证明两个成分各自扛真实增益【推断：闸门本身是格式的一部分，不是可选质检】。
- **格式与时机是组合爆炸的联合空间**：digest 可在任意时机档使用，信号卡实质要求离线建库（演化树不可在线构建），packet 要求策展 KB——选格式档时隐含选了 K1/K3 的前置投入。格式变更因此是"实验"（K15 强制 2×2 消融重跑），不是配置热更。
- 实现陷阱：digest 的"隔离上下文中生成"是格式的一部分——压缩过程若与消费过程同窗口，原文已污染主上下文，压缩只是摘要幻觉；信号卡的 evidence 字段必须引用**路径片段**（演化关系）而非论文正文段落，否则退化为带编号的方案拼接。

### 3. 反直觉结论

**外部知识的原创性毒性不在知识本身而在表示形态，且"压缩"这个最直觉的修复只治一半**。2605.27905 的 219,655 idea 是在"各框架自有检索/注入设计"下产生的——即现实部署的默认格式集体落在收敛区；而 ToI 的对比（6.27 vs 5.36）证明同一批文献换个表示（演化树+信号卡）可以逼近人类参考（6.29）。最反直觉的推论：**flat RAG 连"digest 起步"的过渡期都应尽量缩短**——digest 缓解的是上下文成本与幻觉（K12），对收敛效应只有二阶改善；只要注入内容仍以"已有工作说了什么"为主语，分布拖拽就存在。格式轴的终局是"注入内容的语法主语必须是 gap/约束/失败模式，不能是方案"【推断：这应写成 schema 校验规则而非 prompt 建议】。

### 4. 与其他模块接口

- **×K13**：格式即 M6→M2 契约的 schema——digest/packet/信号卡是 `query(intent)` 返回类型的三个版本，schema 变更=契约版本变更，须可追溯到代际（进 X1）。
- **×K15**：格式是收敛效应的第一调节阀——任何格式档变更强制重跑 2×2 消融（开/关 ground × 开/关 audit）并报告多样性指标。
- **×K11**：信号卡是多样性供给的载体——convergent/cross-link 信号直接喂给 M2 的 QD 维护（执行在 M2，供给在本轴）。
- **×K12**：一切格式内嵌 provenance 字段（query_used/source_pages/opened 记录）；信号卡的 evidence 引用必须满足"实际打开过"。
- **×M2**：信号卡的 failure_modes 与 M5 pitfall 条目在注入前**分标来源类型**（内部经验 vs 外部文献），汇合配方归 M2-O5。

### 5. 证据空缺

- 2605.27905 未按"注入格式"分层报告——四发现是框架级聚合，格式作为解释变量是【推断】（ToI 动机陈述为旁证）；缺"同一检索内容、仅改注入格式"的受控实验。
- ToI 仅 6 主题、单一评分体系；信号卡 vs digest 的同预算对照不存在（digest 档增益无一手数字）。
- 信号卡 schema 的字段级消融（只去非显而易见闸门 / 只去 ≥2 轨迹约束）未做——现有消融粒度是"gap 建模/跨轨迹信号"两大块。

## K5 检索意图集（intent taxonomy）

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 无 intent（自由文本查询） | 通用 web 搜索形态，查询目的不可审计、不可路由 | openresearch-cli 路线：CLI 一等命令 + system prompt 偏好声明，"何时查、查什么"全部无人负责（GC-K §5【推断】） | 零耦合原型期；进不了生产（K13 无契约档的伴生形态） |
| Arbor 四 intent | `related_work`（重叠/缺口评估）、`survey`（领域格局+取舍）、`lookup`（具体事实）、`explore`（开放扫描）；intent 决定检索策略与 digest 形态 | Arbor `ResearchSearch` 4 intent【原文】（GC-K §1） | **默认基线**。四值覆盖"评估/格局/事实/扫描"四种认识论需求 |
| 四 intent + 失败修复意图 | + `repair`：失败条件化的 heuristics/诊断/替代实现检索（KAPSO ERA 的 `RetrieveKnowledge(g, r̂, s)`） | KAPSO ERA【原文】；repair 的查询以失败信号 s 为条件，语义与其余四 intent 正交（修复 vs 启发） | **默认**。M8 失败信号结构化后即开；×K1 失败触发档的 M6 侧实现 |

### 2. 隐藏结构

- **intent 集是 ground 车道的"可审计性边界"**：自由文本查询无法回答"这次检索是为了什么"——事后无法区分 agent 在做启发还是在自我验证（若 ground 车道被用来查"我这个 idea 是不是 novel"，就是在自建一条无隔离的伪 audit 车道，K2 破窗）。intent 白名单 + "audit 不走 intent 体系、走独立 `audit(idea)` 入口"是把两车道语义钉在 API 层【推断：这是 K16 静态检查的可执行判据——凡 ground 查询文本相似于 novelty 判定模式即报警】。
- **intent 即路由参数**：不同 intent 对应不同深度档（lookup 浅读即够，survey/explore 需 6k 深读，×K6）、不同来源集（repair 偏向仓库语料/Environment 条目，related_work 偏向文献库，×K3）——intent 词汇表是把 K3/K6 的配置按语义索引的键。
- 意图集应为配置即数据（YAML 可扩），但新增 intent 须声明：深度档、来源子集、是否失败条件化、与 audit 的区分判据——否则 intent 膨胀会重建自由文本的不可审计性【推断】。

### 3. 反直觉结论

**给检索工具加 intent 约束不是限制表达力，而是制造可归因性**——自由查询看似更通用，但四 intent 的划分（评估/格局/事实/扫描）恰好对应检索产物在变异上下文中的四种消费方式（O5 配方的字段），无 intent 标注的产物进不了白名单矩阵的槽位，只能被全量拼接——即无 intent 的"自由"实际兑换成 K4 的 flat 拼接退化【推断】。

### 4. 与其他模块接口

- **×K13**：intent 集是 `query(intent)` 的类型签名；新增 intent=契约 minor 版本变更。
- **×K10**：repair intent 是 ERA 联合入口的 M6 侧实现——失败信号同时触发 M5 `recall(signal)` 与本 intent。
- **×K16**：intent 标注是 ground/audit 归属判定依据；audit 语义不出现在 intent 词汇表中是刻意的排他设计。

### 5. 证据空缺

- 四 intent 的划分无消融依据（Arbor 未报告三 intent 或五 intent 的对照）；各 intent 的实际调用分布未知。
- repair intent 的检索质量（修复建议命中率）无定量报告——KAPSO 只给了机制。

## K6 阅读深度与预算分级

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 统一浅读 | 全部按摘要级截断（~2k token/页） | Arbor 审计车道依据："abstracts are enough to judge prior art"【原文】——先验判定确实只需浅读 | 仅 audit 车道单独成立；ground 车道用浅读=信号卡/digest 失去方法细节原料 |
| 统一深读 | 全部保方法/结果章节（~6k token/页） | 无系统采用——审计车道深读是纯浪费（verdict 语义只需要存在性判定） | 不推荐 |
| 分级双预算 | 构想深读 `research_visit_tokens`≈6000（方法/结果章节在截断后幸存）；审计浅读 `visit_max_content_tokens`≈2048 | Arbor 双 token 预算 2048/6000【原文】——可复用一手设计，也是"车道语义决定预算"的物化 | **默认**。与 K2 车道结构天然对齐 |
| 分级 + 迭代轮数上限 | AI-Scientist 参数化：≤10 轮 × ≤10 条结果/轮 | AI-Scientist 在 10×10 配置下仍 12/12 误判（2502.14297）——**预算不能弥补判定机制缺陷**；但轮数上限仍是必要护栏（防 agent 把检索当无限预算循环） | 默认叠加项；轮数上限进 M3 预算科目 |

### 2. 隐藏结构

- **深度档是车道语义的函数，不是任务难度的函数**：audit 判定的是"先验存在性"（摘要足够），ground 启发的是"方法迁移可能性"（需要方法/结果细节）——因此深度配置应绑定车道+intent（×K5：lookup 浅读、survey 深读），而非绑定查询复杂度。AI-Scientist 的反证：它给审计加了 10 轮迭代预算，但判定粒度（关键词匹配元数据）没变，误判率纹丝不动——**预算轴救不了判定轴**。
- **每页 token × 轮数 = 检索成本科目**（×M3）：6k×深读页数 vs 2k×浅读页数在同一预算账户下竞争，分级双预算实际是"把 token 花在信息密度高的车道上"的分配规则；失败触发检索建议用中档深度（诊断需要方法细节但不必全文）。
- 实现陷阱：截断位置有语义——"方法/结果章节在截断后幸存"要求截断器感知章节结构（Arbor 的 alphaXiv SDK 全文路线能拿到结构化章节，纯 Jina reader 抓取的网页文本只能按字符截断）——深度档的可兑现性依赖来源后端的内容结构化程度（×K3）【推断】。

### 3. 反直觉结论

**审计用更浅的阅读不是妥协而是正确性条件**——直觉上"判新颖性是大事，应该深读"，但 Arbor 的理由链是：先验存在性是存在性命题（∃），摘要是论文主张的最高密度表示，深读增加的细节不改变 ∃ 判定却线性烧预算；反过来，构想期的启发是构造性需求（需要可迁移的机制细节），浅读等于没读。深度错配的两个方向都是净亏，只是亏的科目不同（预算 vs 信息）【推断】。

### 4. 与其他模块接口

- **×M3**：每页 token×轮数进预算核算；深度档随 remaining_budget 可调（末段降档）。
- **×K1**：失败触发检索用中档深度；离线建库不受页级预算约束（一次性成本）。
- **×K2**：双预算的 2048/6000 参数按车道绑定，车道隔离配置变更时联动检查。

### 5. 证据空缺

- 2048/6000 是 Arbor 单系统的工程选择，无消融（如 4k 审计是否改善 verdict 质量未知）；"摘要足够判先验"在方法高度技术化的领域（如系统优化）可能不成立。
- 截断器章节感知能力对 digest/信号卡质量的影响无量化。

### 1. 取值表

|---|---|---|---|

| novel | 审计车道未找到先验（注意：是"未找到"不是"不存在"，受来源覆盖与判定机制双重限制） | merge 报告的 contribution 措辞依据之一；**不构成加分** |
| partial-overlap | 存在部分重叠工作，附最接近论文与重叠点 | M9 必须要求谱系/报告显式定位差异；**不构成减分** |
| prior-art-exists | 找到实质等价先验 | M9 的强参考信号：merge 须给出"实证增益独立于先验"的论证；**仍不是一票否决**——裁决权（是否准入）永远由 M9 基于 fitness 显著性+预算+verdict 综合行使，M6 不拥有否决权 |

### 2. 隐藏结构

- **双向误判的逐机制拆解（为什么硬闸门必死）**：
  - **false-novel 12/12 的机制**：(i) 查询由 idea 自身生成——检索词与 idea 共享词汇，已知技术若措辞不同（"micro-batching" vs 当年的 "mini-batch chunking"）即漏；(ii) ≤10 条元数据+≤10 轮——召回上限被参数卡死；(iii) 单车道结构（×K2）——判定分布与构想分布同源，不存在独立检验；(iv) 二元 verdict——"无明确匹配即 novel=True"把检索失败默认映射为 novel，**错误方向被默认值放大**。
  - **false-kill 9/10 的机制**：LLM-as-judge 的新颖性判定有系统性偏置。【新搜】2606.12071 给出机制级证据：LLM judge 的 novelty 打分与**狭隘性（source-boundedness）混淆**——模型生成的 RQ 更狭隘（绑定源论文方法/设定），judge 把狭隘误读为具体、把具体误读为新颖；显式测狭隘性后与人类判断一致率达 72–76%。即 judge 缺的不是检索而是**评价维度的缺失**——comparative 设置还进一步放大偏袒（平局打破时偏向生成物）。
  - 两个方向的共同结构：**判定器的错误率不可知且不可内部测量**（AI-Scientist 上线即 12/12 误判而不自知——×K14），硬闸门把这个不可知错误率直接换算成流水线的误杀/漏放率。
- **advisory 定位的本质是"错误定价"**：veto 式把 verdict 错误定价为 idea 的生命（误杀代价=整个分支）；advisory 把同一份 verdict 定价为一条参考信息（误杀代价≈0，漏报代价=merge 报告里多一段可被人/谱系复查的错误措辞）。误杀代价 > 浪费一次实验（轴系公理）→ advisory 是唯一理性选择；但 advisory 的可信性必须由 K14 台账持续挣得——**无质量数据的 verdict 不得进 merge 参考**（对标 M2-O20"无漏斗数据的算子不得参与自适应选择"）。
- **时机双触发的分工**：add 预检护树（防重复方向扩张），merge 复核护名（防把 fitness win 误述为 contribution win）；两个时点的审计对象状态不同（未验证 vs 已验证），verdict 字段应带 `audit_phase` 标注【推断】。

### 3. 反直觉结论

**审计做得"更强"（更多轮、更深读、更严 prompt）不能把它变成硬闸门——因为失效是判定范式级的，不是参数级的**。AI-Scientist 有 10×10 的迭代预算仍 12/12 漏报；2606.12071 用最好的模型（gpt-5.5/gemini-3.1-pro 时代）+ 精心设计的三维 rubric 仍与人专家一致性 22%——两份证据夹击说明当前 LLM 的 novelty 判别能力上限就在"advisory 级"。更深的反直觉：**审计的最大价值恰恰在它不阻断时释放**—— Arbor 的 "never blocks" 使 verdict 可以诚实报告不确定性（三档而非二元），而硬闸门迫使判定器在证据不足时也必须二选一，把不确定性压成错误【推断：三档 verdict 与 advisory 定位是互为前提的设计对】。

### 4. 与其他模块接口

- **×M9**：verdict 是 merge/准入的**参考输入**；裁决权（含"忽略 verdict"的权力）在 M9。M9 侧契约：merge 决策记录须注明消费了哪条 verdict（audit_id）及其档位——无 verdict 的 merge 与忽略 verdict 的 merge 都须可审计区分。
- **×K14**：verdict 双率台账是维持 advisory 定位可信的前提；K7 承诺"不阻断"，K14 承诺"不阻断的那个信号本身值得参考"。
- **×K2/K8**：审计走独立车道、独立 fresh search——本轴的时机声明不得被实现成"复用 ground 缓存的预检"。
- **进 X1**：每次审计（预检/复核）落谱系：verdict 档位、最接近论文、重叠风险、实际覆盖的后端集（×K3 降级台账）、audit_phase。

### 5. 证据空缺

- AI-Scientist 双率是其**特定判定栈**（关键词+一票 LLM）的数字；Arbor 式（独立 SearchAgent+三档+实际打开）审计的真实双率**从未被测量**——K14 台账的第一批数据是空白。
- "prior-art-exists verdict 到达后 M9 应如何量化折损"无先例——参考权重的标定是纯设计决策。
- 2606.12071 是 RQ 级（上游）判定，idea/方法级判定的偏置是否同构未证【新搜，外推风险】。

## K8 审计检索独立性 ★重点轴（与 K7 联动）

### 1. 取值表

| 取值 | 机制展开 | 量化证据（一手数字+来源） | 何时选（前置条件） |
|---|---|---|---|
| 复用 ground 结果（**禁止取值**） | 用构想期读过的文献做新颖性判断——自我指涉；"审计"只是在复述构想期的阅读史 | 即 K2 单车道失效的执行面：AI-Scientist 12/12 漏报的结构根因之一（2502.14297）；【新搜】2606.12071 comparative 偏袒效应（judge 对已见过的生成物胜率 27.2%→49.1%）提示"见过"本身即污染判定 | 任何场景均禁止 |
| 独立 fresh search | 专门 SearchAgent 全新检索——"so it can't be fooled by whatever grounded ideation read earlier"（Arbor【原文】）；独立 session、独立缓存命名空间、查询仅从 idea 文本构造 | Arbor 独立 SearchAgent 设计【原文】（GC-K §1） | **默认基线**。K2 硬约束在检索执行面的落实 |
| 独立 + 面向更广文献 | novelty 检查面向 "broader literature beyond Tr"（Tr=构想期用过的语料集）；审计语料集 ⊇ ground 语料集，且对 ground 未覆盖的来源区域加权 | ToI【原文】（GC-K §6a）；反向逻辑：只查自己用过的语料=把"我没读过"误认为"世界没有" | **默认**。前置：K3 支持按车道分别配置来源集且满足包含关系（K16 静态校验） |

### 2. 隐藏结构

- **独立性的三个可违反面与对策**（本轴是 K2 的执行面，违例即 K2 破窗）：(i) **查询面**——audit 查询若由 ground digest 派生，构想期的阅读选择经查询词泄漏（对策：查询构造器只接受 idea 原文+任务描述）；(ii) **缓存面**——共享 HTTP/embedding cache 使 audit 命中 ground 的热数据、排序被历史点击污染（对策：命名空间隔离的缓存键，K16 启动时校验）；(iii) **语料面**——audit 语料 = ground 语料时，"更广文献"承诺落空（对策：来源集包含关系作为配置不变量）。【推断：三面各自可独立静默失效，故 K16 需要静态+运行时双层检测而非单层】
- **"更广文献"与 K6 浅读的组合是审计性价比的核心**：audit 的边际信息量集中在"覆盖宽度 × 存在性判定"，深读不加宽度——2k 浅读+宽来源+独立检索是同一枚设计的三面（Arbor 三者的共现不是巧合）【推断】。
- **审计独立性的验证只能来自外部**：K16 运行时重叠审计（audit 产物 vs ground 抓取历史的哈希比对）是本轴唯一可设想的实证手段；无它则"独立"与 K2 一样只是纪律声明。
- 与 K7 的联动结构：K7 管"verdict 有多大权力"（无权力），K8 管"verdict 有多少信息量"（独立性=信息量的来源）——**一个无权力但有信息量的信号正是 advisory 定位的完整定义**；两轴合起来把审计变成"便宜的第二意见"，而非"昂贵的橡皮图章"或"不可靠的裁判"。

### 3. 反直觉结论

**审计检索"重新查一遍"看似浪费（ground 已花过检索预算），实则重复正是价值所在**——只有独立同分布（最好独立且更广）的第二次检索，其"未命中"才携带关于先验不存在的信息；复用第一次检索结果的"审计"信息量恒等于零，无论其 verdict 措辞多自信。换算成预算语言：audit 车道的检索费不是 ground 车道的冗余开销，而是**购买 verdict 信息量的唯一支付方式**——省掉它的系统在报表上看到的不是"审计成本减半"，而是"审计模块输出恒为噪声"【推断】。

### 4. 与其他模块接口

- **×K2**：本轴是车道隔离在检索执行面的落实；字段分离（grounding/related_work）是其落地层。
- **×K3**："更广文献"要求 audit 来源列表 ⊇ ground 来源列表；K3 的静默降级必须按车道分别记账（audit 降级=覆盖承诺缩水，须落 verdict 元数据）。
- **×K16**：运行时文本重叠审计验证独立性被实际执行；违规即作废 verdict 并留谱系记录（进 X1）。
- **×K14**：独立检索的 verdict 才有资格进误判率台账采样——复用档的"verdict"无判别质量可言。

### 5. 证据空缺

- "独立 fresh search vs 复用 ground 结果"的 verdict 质量对照实验不存在（禁止取值的依据是机制推断+单车道实证，非 A/B 测量）。
- "更广文献"的宽度参数（audit/ground 来源集比例）无任何系统给出推荐值。
- 2606.12071 的 comparative 偏袒是在"同一 judge 同窗口比较"设置下测得，"缓存/session 级共享"对审计判定的污染幅度未直接测量【新搜，外推】。
